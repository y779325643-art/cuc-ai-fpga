显式结构骨架下的 RTL 正确交付与收益归因
ArchXBench 八任务 A/C/B 对照实验报告

版本 1.0  |  编写日期：2026-11-17  |  生成日期：2026-11-14  |  评测与兼容性复核：2026-11-16

用途：为论文的实验设置、结果分析、消融讨论和补充材料提供可追溯文本。报告汇总既有实验，不增加模型生成或硬件验证，不改变原始成绩与数据发布身份。

摘要

将多模块 RTL 的结构构造与行为生成分离，能够把接口、参数和模块连接交由固定程序完成，并保留模型对算法和时序行为的实现责任。本实验在八个 ArchXBench 任务的受控架构配置上比较三种生成条件，共执行120次原始生成请求。三组共享功能规格、公开约定和文字架构；A生成完整工程，C额外看到显式结构骨架并生成完整工程，B看到同一骨架但返回行为体，由程序装配。统一复核两项工具适配问题后，A、C、B的正确交付率分别为65.0%、70.0%和72.5%，B相对A高7.5个百分点。四个A失败而B通过的同题同编号对照中，C均通过；源码和日志将差异定位到行为模块的索引实现、重启握手和事件触发语义。多任务对照刻画生成流程的整体收益，历史FFT同一行为、只换顶层的干预则提供确定性结构的直接机制证据。两类证据分别承担效果测量与机制隔离的论证职责。[E1–E8]

1 研究问题与术语

研究问题是：在模型、功能要求和文字架构保持一致时，提供代码化结构骨架以及将结构交由程序装配，能否提高一次生成的正确交付率？评价重点是可通过功能与综合验证的交付结果；生成长度和token用量作为辅助指标。

表1 术语及证据含义
术语	本文定义
RTL	Register-Transfer Level，寄存器传输级硬件描述；本实验候选使用Verilog-2001。
结构骨架	模块头、参数、端口、线网、实例及参数绑定；固定部分不提供算法、状态机、缓存、复位和寄存器更新实现。
行为模块	由模型实现算法、存储、控制、事件触发、寄存和握手的模块内容。
正确交付率	一次生成结果通过语言与接口检查、原源功能测试、统一综合及原网表功能测试的比例；也对应记录中的完整通过率。
源功能通过	原源级测试与比较判据通过，不自动包含综合、网表或全输入形式等价结论。
结构互换	保持既有行为模块字节不变，只替换结构文件的干预，用于隔离结构本身的作用。
兼容性修正视图	同一批候选在统一工具适配复核后的结果；原始结果保留，修正来源单列。

2 实验设计

2.1 三组信息与输出责任

2.2 任务与生成预算

2.3 验收与统计口径

主指标采用完整验证的二元结果。对任务t、组别g、重复r，只有全部规定阶段通过时I(t,g,r)＝1，否则为0；基础设施未知状态单列。本轮最终未知状态为0。每组的任务等权通过率为p_g＝(1/8)Σ_t[(1/5)Σ_r I(t,g,r)]，由于每题重复数相同，也等于成功份数除以40。所有失败和工具超时保留在分母中。

本报告给出描述性比例及百分点差，不据此声明统计显著性。八个任务是任务层面的覆盖，五次重复是同任务生成样本；同题同编号的A/C/B用于分块记录和差异核对，不表示共享随机采样种子或固定了相同的行为代码。历史试验及结构互换诊断不并入本轮120份分母。

2.4 统一工具适配复核

复核保持候选字节、测试台、测试向量、金标、容差和工具预算不变，并对相关任务的全部15份候选统一执行。浮点加法器原联合编译模式把Verilog-2001合法标识符packed当作SystemVerilog关键字；全15份改用Verilog-2001联合编译后均通过，B-2恢复完整通过。DCT原导出脚本按固定名称寻找顶层，A-5的顶层经Yosys参数化后具有派生名称；全15份统一选择实际top属性进行导出和规模读取后，A-5恢复通过，C-1的原语言错误保留。[E4,E5]

两项复核均先执行正、负控制：FP正控源/网表各23/23，错误输出负控检出19/23；DCT正控源/网表各48/48，重复输出行负控检出6/48。复核没有新增模型样本，原始成绩与修正结果分别保存。

4 四个正向案例的代码与日志归因

按同题同重复编号核对，A失败而B通过共有四对，四对中的C均完整通过。A/B另有一对反向结果，因而净差为三份。对四个正向案例，已检查的顶层或复合模块实例、参数和命名端口连接与骨架一致；B的行为体与固定结构按原字节装配，未执行逻辑修复。直接差异均落在模型生成的行为模块。[E6,E7]

4.1 Conv2D：可接受的缓存与索引实现

A-3的buf_idx/src_col只在条件分支中计算，A-4还对组合过程中的buf_idx原地加减以实现环绕。Yosys在过程转换后的检查中分别报告128条和64条位级反馈路径，阻断位置为Conv2DWindow行为体。它们尚未运行原源测试，因此可确认的是当前工具流程拒绝该实现，而非已证实卷积数值错误。

C-3的行槽索引在外层循环中无条件计算，C-4以静态行号读取并在行末搬移缓存；B-3使用纵向行缓存与横向移位，B-4在时钟过程中计算环形索引。这些是不同的行为实现选择，固定骨架未提供它们的索引或存储算法。C-3也出现过col_i锁存器推断，但该临时量输出没有有效消费者，最终被清除且检查通过。因此，归因需要落实到实际反馈路径，不能将“出现锁存器推断”本身视为失败条件。

4.2 FFT：重启握手与完成状态

A-3第一次FFT通过16/16，随后未启动IFFT。其调度器在DONE中额外使用done_cnt等待一拍：

// A-3: FftScheduler
S_DONE: begin
    if (done_cnt == 1'b0) begin
        done_cnt <= 1'b1;
    end else begin
        state <= S_IDLE;
        done_cnt <= 1'b0;
    end
end

原波形显示第二次start位于506–516 ns。515 ns上升沿到来时，A仍处理DONE，未采样start/mode，最终触发测试台的512周期等待上限。C-3/B-3均在完成状态下一拍回到空闲，并在515 ns接受第二次任务。该512周期是测试协议等待上限，与表6中的工具墙钟超时不同。三份顶层的五个实例及连接一致，失效点位于调度器行为。

// C-3
S_DONE: begin
    state <= S_IDLE;
    done_r <= 1'b0;
end
// B-3
ST_DONE: begin
    state <= ST_IDLE;
end

4.3 AES：参数常量的事件触发语义

A-4的KeyExpand用always @*对参数ROUND_INDEX进行case选择。原编译器对十轮均警告无敏感信号、过程不会触发；已有波形确认rcon_val全程保持X，并传播到有效密文。轮号与结构连接正确，合法辅助S-box模块也完整交付。

// A-4: procedural process reads a parameter only
always @* begin
    case (ROUND_INDEX)
        1: rcon_val = 8'h01;
        // Remaining cases are present in the original RTL.
        default: rcon_val = 8'h00;
    endcase
end
assign temp = sub_word ^ {rcon_val, 24'h000000};

上段为保留关键语义的节选，完整常量表见附录源代码位置。C-4和B-4将轮常量函数用于连续赋值，避免依赖参数变化触发过程。两者均通过四份原密文检查及综合网表检查。

// C-4: continuous-assignment expression
sub_w3[31:24] ^ aes_rcon(ROUND_INDEX)
// B-4
assign temp = subword(rot_temp) ^ {rcon(ROUND_INDEX), 24'h000000};

B−A为四个正向对照减一个反向对照，净增三份；C−A为四减二，净增两份；B−C为二减一，净增一份。这是同编号生成结果的净差会计，不是固定行为后的因果中介分解。

行为生成差异具有直接代码证据。四个正向对照中的控制、事件语义和索引实现均由模型产生，宿主没有将失败行为改写为通过行为。C自行输出完整RTL也通过四例，表明这些成功并不要求宿主机械装配才能实现。代码化骨架上下文是合理解释，输出任务收窄也可能影响实现选择；当前不同生成样本没有单独隔离这些作用与抽样差异。

反向与重复案例进一步明确责任边界。AES C-2在已有骨架下复现A-4的参数专用always缺陷；DCT C-1使用Verilog保留字buf作变量而被语言检查拒绝。AES B-5的装配字节准确，但算术S-box中条件调用gf_mul展开后的临时信号被Yosys检查判为无驱动；A-5/C-5通过。B-5尚未执行数值测试，该结果属于叶子写法与工具处理的失败，不能直接改称已证实的AES数值算法错误。[E6]

因此，本轮A/C/B对照用于估计生成流程的正确交付差异；其逐例改善落在行为实现层。确定性装配提供了固定结构与行为原样组合的保证，而本轮四例没有出现被装配器直接修复的错误顶层。两类论点应分别由相应证据支撑。

6 同一行为的结构互换机制证据

历史FFT A-2诊断对五个完整行为模块逐字保留，只将顶层替换为原冻结结构骨架。原顶层重复声明done而未通过Verilog检查；替换后，原FFT/IFFT源检查32/32、综合以及原网表检查32/32均通过。五份行为文件由原回执哈希核验，原候选与历史成绩保持不变，新增模型调用为0。[E8]

这一干预直接表明：在该样本中，正确行为能够因结构声明错误而无法交付，而确定性顶层能够在行为不变时恢复交付。本轮的八任务对照负责测量整体效果，这项同一行为的干预负责隔离结构机制。历史FFT A-2与本轮FFT A-3属于不同运行，前者不计入本轮120份分母。

7 可供论文采用的表述

7.1 实验设置段落

在八个公开硬件任务的受控架构配置上，对共享文字架构下的完整RTL生成（A）、显式骨架条件下的完整RTL生成（C）和确定性结构装配下的行为体生成（B）进行比较。每个任务、每种条件采样五次，共120次生成请求。三组使用相同模型与请求预算，全部生成完成后再执行验收。正确交付要求候选通过Verilog检查、原源功能测试、固定综合以及原网表功能测试。工具超时和其他失败均保留在分母中；两项评测适配问题对相关任务全部候选统一复核，原始成绩与修正视图分别保留。

7.2 结果段落

统一兼容性复核后，确定性装配条件B的正确交付率为72.5%（29/40），高于文字架构条件A的65.0%（26/40）；显式骨架条件C为70.0%（28/40）。B相对A的净增量为三份完整交付，来自四个正向对照及一个反向对照。所有生成均完整结束，排除了输出截断对本轮差异的解释。分层结果显示，B与A的差异集中在既有复杂任务复核层（19/20对16/20），新增任务层二者均为10/20。

7.3 机制分析段落

逐例源码与日志分析将四个正向对照的阻断原因定位到生成行为，包括卷积窗口索引的工具检查、FFT重启握手以及AES轮常量的事件触发语义。对应C组均完整通过，且所检查的顶层连接与骨架一致，表明这些结果不能直接归因为宿主装配修复了错误结构。A/C对照考察显式结构代码上下文；C/B对照在相同上下文下改变输出责任、格式约束与装配方式，应据此解释组间增量。另一方面，同一行为模块保持不变的FFT顶层互换诊断直接验证了确定性结构消除特定集成缺陷的作用。两类实验共同区分整体交付收益与结构机制。

上述段落采用本报告的任务范围和描述性统计口径。正式论文可将证据标记E1–E8替换为对应表格、补充材料或数据仓库引用；术语“正确交付”应保留完整验收定义。

8 结论

本轮实验建立了共享文字架构、足量输出预算下的正确交付收益：B达到72.5%，较A高7.5个百分点。消融与逐例分析将观察到的改善定位在生成行为，并把代码化骨架上下文与机械装配的责任区分开来。结合保持行为不变的结构互换证据，论文可以形成两条相互衔接的论证：多任务对照量化整体交付效果，结构干预验证确定性构造的作用机制。
