## 0. 研究决策摘要

**研究对象：契约＋确定性骨架＋有预算的反馈修复。**

拟研究的问题是：在相同公开需求、冻结模型、工具权限和总预算下，以显式契约约束结构构建与后续修复，能否提高多模块 RTL 工程在独立验证下的成功率，并以可接受的完整成本减少跨模块不一致？

论文定位优先采用**系统与受控实证研究**。不预先主张“首次结合契约、骨架和修复”，不将类型化 IR、模块分解、工具反馈、两层修复或日志记录本身作为独有创新。方法增量必须落到可执行规则、实际 RTL 边界及可测收益。

| 决策 | 本计划建议 |
|---|---|
| 方法主角 | 完整的契约约束生成与修复流程；骨架独立作用是机制问题之一 |
| 首要近邻 | CPPL、HINT、VeriRefine；其余近邻见第 2 节 |
| 领域范围 | 沿用现行规范的三类量化 AI 子系统；不得悄悄用旧流式家族替换主总体 |
| 首要系统比较 | M5@B4 与 M1@B4 |
| 首要构建比较 | M4@initial 与 M3@initial，共享初始 PC 和准入检查 |
| 主终点 | 现行规范定义的 VPP-L3；功能、阶段、成本和物理结果另列 |
| 首轮工作 | 核实两个真实任务的机制设计、复用边界与实现缺口，再决定开发／运行范围 |
| 论文正文 | 本次不写；在研究框架与证据门槛明确、获得正文授权后再开始 |
| 时间预期 | 历史提出的一周／70 小时作为资格冲刺情景；不保证据此完成投稿或接收 |

## 1. 科学问题、研究假设与可否证结果

### 1.1 问题边界

单个模块局部计算正确，不足以构成正确工程。生产者和消费者可能对同一总线的张量坐标、量化编码、有效时刻或调用身份理解不同；反馈修复还可能改变接口、连接或此前依赖的结构。

本研究从**已裁定完整且可执行的公开需求**出发，不同时解决任意模糊自然语言理解、通用神经网络编译、任意协议支持和板级部署。输出是完整 FPGA Project Package（FPP），不是只有 PC、顶层空壳或若干独立模块。

### 1.2 研究问题

| 编号 | 问题 | 主要证据 | 结论限制 |
|---|---|---|---|
| RQ1a | 完整流程是否优于直接生成与工具反馈修复？ | M5−M1 的全分母 VPP-L3 与完整成本 | 是整个系统策略差异，不是修复算法的纯效应 |
| RQ1b | 共享同一契约后，确定性构建及受限行为装配是否有增量？ | M4−M3 | 同时改变构建责任与编辑边界，不等于纯文本骨架效应 |
| RQ2 | 改善发生在哪里，哪些错误仍然存在？ | 阶段转移、自然错误、来源映射、修复轨迹 | 不把所有功能失败都归为跨模块不一致 |
| RQ4 | 生成结果能否满足预声明 FPGA 目标的物理要求？ | 预选位置的 L4 实现结果 | 不能用可综合代替时序、布线或板级证据 |

编号沿用现行规范，避免另设一套不兼容的研究问题。张量语义检查的纯效应、相同失败起点的修复机制及原生编码 Agent 对照属于可选子研究，不能由主要比较自动推出。

### 1.3 待验证假设

1. 契约将部分跨模块关系变成可检查义务，可能使错误在生成行为前暴露。
2. 程序承担结构生成，可能减少模型重复维护接口、实例和连线的负担。
3. 修复遵守契约和实际编辑边界，可能减少结构漂移及无效修改。
4. 上述收益可能被错误契约、局部算法困难、额外规划成本或过严限制抵消。

四项均为假设。检查器拒绝更多提议、结构保持率更高或首次编译率更高，都不能单独证明最终工程更可靠。

## 4. 方法定义：契约、骨架与修复怎样闭环

### 4.1 角色和数据流

```text
冻结公开需求、目标与能力范围
  → LLM 提出 design
  → 控制器绑定原需求，形成 PC
  → schema、引用、类型、能力及适用语义检查
  → 确定性解析与结构构建
  → LLM 一次批量完成所需行为单元
  → 完整 FPP 或明确失败 checkpoint
  → 公共检查与有预算修复
  → 封存唯一终止候选
  → 独立隐藏语义验证、指定 L3、预选 L4
```

开发助手、被测模型、可信评测器是不同角色。开发助手可接触的资料不得自动转给被测模型。候选自写 testbench 仅能作调试辅助，不能定义最终正确性。

### 4.2 契约的责任

PC 2.1 使用控制器拥有的 `bindings` 与模型提出的 `design`。需求事实、目标和能力绑定不可由模型修改；设计决策可以在允许范围内提出并修订。展开图、BuildPlan、ABI 等派生物由程序维护。

例如，同为 32 位的两个端口，生产者声明按通道打包，消费者声明按空间位置解释。语法与位宽检查不足以认定二者可直接连接；语义规则应要求相容声明或显式转换。该例是机制设计例，不是已观测的自然模型缺陷。

检查声明不等于证明行为：两端抄入相同错误声明，或 RTL 实际忽略正确声明，仍需独立功能验证。静态通过也不证明计算正确、无死锁、所有时序或资源约束满足。

### 4.3 骨架的责任

允许构建模块头、参数特化、实例、连接、常量、record／lane／mask 展开、文件清单及声明式工具入口。程序不静默插入 Conv、GEMM、FIFO、仲裁、repack、requantize、流水线或累加算法作为答案。

确需转换和缓冲时，要求设计显式声明，由允许的行为路径实现；公共行为 IP 若启用，必须对比较方法提供等价内容与机会，并单列其干预和成本。

行为合并需验证真实允许单元及实际 RTL，而非只靠注释。初始行为一次逻辑调用覆盖全部必需单元，漏文件、截断或非法输出均保留并计费。

### 4.4 修复的责任

| 失败对象 | 可执行动作 | 必须保持 |
|---|---|---|
| 设计提议／PC 中允许的决策错误 | 新版本 design，重新绑定、检查和构建；所需行为另耗剩余调用 | 原始需求、工具／预算与评测规则 |
| 行为实现错误 | 替换允许行为单元，重新装配并检查 | 当前受保护结构及契约边界 |
| 可信构建器、oracle 或工具故障 | 开发／基础设施诊断，保留受影响运行 | 不归为模型自然缺陷，不靠改答案救活结果 |
| 冻结需求本身存在矛盾 | 停止受影响资格流程，按版本规则处理 | 不由候选模型擅自放宽需求 |

改变布局、量化、顺序或接口解释，即使总位宽不变，也不能自动复用旧行为。首版允许全量失效受影响行为，先保证正确性，不为追求增量更新增加复杂度。

额外诊断、路由、格式纠正和重新生成均计入预算。两层修复已有近邻，本研究的假设是领域义务与执行边界的联动有用，而不是发明“两层”这一概念。

## 6. 任务、benchmark 与独立真值

### 6.1 沿用的目标家族

| 家族 | 主要工程耦合 | 最小资格材料 |
|---|---|---|
| `ai_dw_pw_block` | Depthwise→Pointwise，通道／布局／中间量化边界 | 完整公开运算顺序、整数数值规则、独立参考、ABI 和停顿／复位监测 |
| `ai_quantized_residual_block` | 主支路与 skip 的同调用／同坐标汇合 | 数值对齐、配对规则、背压及缓冲行为、独立 scoreboard |
| `ai_tiled_gemm_pipeline` | 分块装载、部分和归属、提交与完成 | 维度／遍历／分块协议、精度与累加生命周期、独立参考 |

**先完成两个真实设计卡，再投入完整实现。**建议分别覆盖一个布局／数值边界和一个事务／汇合或归并边界。卡片须列出公开输入、一个合法 PC、一个区分反例、实际构建物、允许修复面、独立 oracle、可复用资产和预计补工。两个案例只用于资格与开发，不能替代三家族总体研究。

### 6.2 与公共 benchmark 的关系

复用现成 benchmark 时，首先保留其原始需求和官方判据；结构符合度只作辅助诊断。若原任务不要求某内部层次，不能因合法融合或不同模块分解而额外判功能失败。

若新增架构或语义义务，须将其标为扩展任务并独立报告，不能混作原 benchmark 成绩。RealBench 等名称不自动意味着任务单位是完整多文件项目，需逐项检查。

自建 AI 任务应以独立公开来源、参考和缺陷检出资格建立可信性；不以“刚好能触发本检查器”为唯一选题理由。开发、排除式 pilot、正式实例／设计簇隔离；改权重、激励、seed 或参数不自动产生新独立设计。

### 6.3 真值资格

每个候选任务在观察正式方法结果前完成：公开需求自洽、正确参考通过、独立数值交叉核对、协议监测、必要正负控制和工具可执行性。控制应覆盖已声明支持的错轴／错尺度、丢失／重复／错配、部分和清零／提交和复位边界。

人工变异用于检查评测器能否检出相关缺陷，不用于证明模型自然会犯这些错误。oracle 从冻结需求建立，不能从候选 PC 生成自身答案或按候选声明删减检查。

## 7. 主要对照、共享起点与可选机制实验

### 7.1 保留现行 M0–M5

| 方法 | 初始生成 | 修复 | 主要用途 |
|---|---|---|---|
| M0 Direct | 公开需求→完整 FPP | 无 | Direct 首发 checkpoint |
| M1 Direct-Repair | 共享 M0 首发，含失败 | 预算内自由工程修复 | 完整流程强基线 |
| M2 Structured-Direct | 无类型计划→自由生成 FPP | 无 | 联合表示／规划的描述性参考 |
| M3 PC-Free | PC→自由生成 FPP | 无 | 与 M4 共享 PC 和准入检查 |
| M4 PC-Skeleton | 同一 PC→程序结构→批量行为 | 无内部免费重试和外层修复 | 构建机制终点 |
| M5 PC-Online | 共享 M4 初始尝试或失败 checkpoint | design／允许行为修复 | 完整方法 |

主比较不改：`M5@B4−M1@B4` 与 `M4@initial−M3@initial`。共同 PC 失败进入 M3/M4 全分母；M5 后继版本不得回写 M3/M4。M0/M1 与 M4/M5 的共享必须包含失败和前置成本。

所有组获得同样公开事实、数值算法、权重、ABI、公共资产与工具。Direct 允许文件级修复，避免强迫每轮重传整工程来人为制造成本劣势。

### 7.2 能解释和不能解释的差异

M5−M1 估计整个表示／构建／诊断／编辑策略组合的系统效果。M4−M3 估计共享 PC 后确定性构建与受限装配的联合增量。二者都不单独识别张量检查、修复路由或骨架可见性的纯效应。

M1−M0、M5−M4 包含追加计算的作用；不同初始失败集合上的条件修复率不可直接解释成修复能力差异。功能相同但结构更整齐，也不自动构成论文主结果。

### 7.3 可选子研究：按主张启用，不全部堆叠

| 子研究 | 共同起点与唯一主要变化 | 能支持什么 | 启用条件 |
|---|---|---|---|
| 张量语义诊断 | 共享未经该诊断筛选的 proposal，控制指定语义检查／诊断参与纠正 | 指定诊断的增量 | 关闭诊断不能破坏基础可解释性；不得同时改变任务支持域 |
| PC 义务辅助修复 | 从 M4 公开自然失败按冻结规则选同一 checkpoint；两侧获得相同 PC、RTL、原始反馈和编辑范围，只有一侧增加义务关联／重检依赖 | 义务辅助的条件机制证据 | 不据 hidden 选样，不注入缺陷补数，不当作整体修复率 |
| 骨架显示与实际保护 | 同一骨架字节，一侧可编辑，另一侧程序保护；调用粒度与其他信息一致 | 骨架展示之外的执行边界增量 | 另行冻结子协议；不冒用 M4−M3 名义 |
| 原生编码 Agent | 相同任务与工具权限，对通用 Agent 增加领域机制 | 独立系统级证据 | 可审计真实内部调用与 token；不能把外层回合当全部预算 |

资源不足时先做两项主比较。只有打算提出相应独立机制主张时才补子研究；不在看到有利结果后临时挑选主张。

### 7.4 外部近邻基线

优先核 CPPL 的适用子集与适配成本；HINT、VeriRefine 若输入和目标粒度不同，记录差异与翻译投入。要声称优于近邻，须同任务、同信息、可比预算重跑，并冻结源码版本、支持范围和人工适配。

无法公平重跑时，可保留精确方法比较和本地强基线，但不得将 M1 命名为 CPPL／HINT／HORIZON 复现，也不得拿原论文分数充当本任务对照。

## 8. 预算、指标与统计

### 8.1 B4 与成本

B4 是候选预算设置，非已冻结正式配置：M1 通常为 1 次首发＋最多 3 次纠正；M5 通常为 1 次 PC＋1 次行为＋最多 2 次纠正。PC 先失败时按实际消耗计算剩余额度，不另开修复预算。

同时冻结累计输入／输出 token、单响应上限、上下文、公共检查周期、内部工具调用、运行时间、CPU／内存和 EDA 限额。模型格式纠正、隐含重试、诊断调用和失败开销全部计入。

成本保留实际去重、独立运行归因、共享点后增量三种视图。主系统比较使用独立运行归因；共享不意味着某方法免费得到 PC。报告所有失败者成本，单列任务／oracle／构建器开发投入、最终验证及物理实现成本。

### 8.2 指标及分母

| 类别 | 预声明指标 |
|---|---|
| 主要工程终点 | 同一终止候选的共同 FPP、L0、指定 L1、public L2、独立 hidden L2 和指定 L3 通过，并具备相应边界／来源／预算资格，即 VPP-L3 |
| 关键分项 | 首发功能成功、最终功能成功、可综合／映射结果、首失败阶段、公私结果差距 |
| 机制 | 结构错误、张量／数值声明矛盾、实际事务／数值错误、局部算法错误、未分类比例 |
| 修复 | 实际纠正调用、合法非空修改、结构漂移、已通过公共性质回退、最终独立结果 |
| 成本 | 全分母调用、输入／输出 token、工具、时间、费用及缺失；成功与失败分开并列 |
| 物理 | 预选全分母 VPP-L4、L3 存活者条件结果、资源、实际时序／布线范围 |

结构不变不等于行为不回退。候选导致的错误／输出不全／超时按设计失败保留；可信基础设施无法判断为 NA；实际完整性破坏单独处理。未运行、未观察、不适用、失败不能相互替换。

只有终止候选提交隐藏验证，不据隐藏结果修复、选择或调参，不绘制不存在的隐藏迭代曲线。正式任务看到结果后不为好看而删失败样本、加容易配置或更改指标。

### 8.3 分析与样本量

遵循 [P1] §12：以独立设计簇为统计单位，先聚合簇内配置／重复，家族内簇等权，三个家族等权。两个主要比较属于同一 Holm 检验族；统计方法需在模拟数据上核验后使用。

现行建议规划值为：系统比较 δ=0.05、功效备择 Δ*=0.15；构建比较 δ=0.03、Δ*=0.10。它们仍需在新总体 pilot 前确认，不是已知效果或普遍的 SCI 门槛。若采用估计性研究或改变阈值，须在运行前明确版本化，不能结果出来后降门槛。

若沿用确认性方案，两项均检验 `H0: Delta <= δ`，同属单侧 familywise α=0.05 的 Holm 族；报告原始及调整后 p、两侧 95% 区间和负方向结果。按现行规范验证家族内设计簇重采样、边界零假设居中和 studentized cluster bootstrap；建议 19,999 次重采样。保留组合优势主张时，正式容量应在预声明备择与依赖情形下达到目标联合功效，而非只计算独立样本公式。

从冻结 manifest 左连接全体结果；设计失败为 0，无法判定保留 NA，不适用单列。按 [P1] 保留全分母界限、方向保守的未知处理与完整配对敏感性；这些是分析处理，不改写底层状态。不能用删除未知或仅报告完整成功样本恢复优势。预算不可核验时，不提出等预算确认性结论。

正式簇数、配置数和重复数由精度／功效与成本分析冻结。三家族各一个案例只能作三案例研究；多次重复、图像、权重或激励不制造独立设计。簇数太少或方差退化时报告原始结果和不确定性，不伪造精确显著性。

### 10.1 模型工作量与费用估计方法

现行排除式 paired pilot 建议规模：3 家族×4 新设计簇×1 配置×2 重复×6 方法＝144 个方法结果，即 24 个配对块；B4 完整路径最多 264 个实际去重逻辑调用、360 个独立归因逻辑调用。内部工具、网络请求、最终验证和 L4 另计。

正式容量公式沿用 [P1]：若每家族 n 簇、每簇 c 配置、r 重复，则 `blocks=3ncr`，六方法结果为 `18ncr`，核心实际／归因逻辑调用上限为 `11×blocks / 15×blocks`。这不是固定样本量，也不表示都能在一周内运行。

费用以实测输入、缓存输入、输出 token 和选定服务的当前计价计算；同时测量公开工具和队列时间。本计划不凭空填写 API 单价、单任务时长、总金额或 GPU 时数。Codex 辅助开发与被测模型的消耗分开；订阅访问不自动具备可核验 token 或实验隔离。

## 11. 停止条件与结果对应的论文主张

| 观察／资格结果 | 裁决 |
|---|---|
| 只有接口／位宽与一般错误反馈，不能指出近邻以外的具体机制 | 以有限系统实证评审价值；不继续宣称新方法核心已成立 |

| 独立 oracle 不可靠、候选可修改真值或存在隐藏反馈回流 | 停止受影响运行及优势声明，先修完整性；保留旧记录 |
| 功能成功率提高且成本可接受，预算与统计条件满足 | 支持相应系统／构建优势，范围限于所测总体 |
| 成功率相近但成本稳定下降 | 可研究效率贡献；须排除更多早失败或弱化对照造成的假节省 |

| 两项主要比较中只有一项成立 | 只主张成立的对应结论，不能补写组合优势 |
| 效果不确定、独立簇不足或预算不可核验 | 报告估计与限制；不靠重复采样伪造确定性，不临时换主终点 |

不以人工缺陷注入通过率、公开测试 PASS 文本或单个演示代替自然生成效果。错误契约导致无法修复的案例必须保留，不能只统计“契约已经正确”的子集后宣称全流程可靠。
