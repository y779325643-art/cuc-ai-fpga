# 责任检查交接成本：字段、推导与同信息对照审查

审查日期：2026-10-21。定向阅读现有原型 `checker.py`、ALU4/FIR4/TD8 三份公开 profile，以及标准 ALU adapter/miter 的实际输入与检查代码；另按补充要求核对既有 `evaluate_pilot.py` 的固定父构造段。本轮未运行 HDL、SAT、模型或作者框架，未修改这些对象、旧结果、正文或生产实现。本文是交接审查，不是新的性能评价。

**结论：当前原型自动完成了从明确合同到有限检查工件、指定边界核验和结果记录的机械工作；没有自动省去功能规范、角色选择或自由边界响应规范。对已经给出同样信息的标准 ALU miter/cutpoint，尚未证明语义输入更少或人工工作更少。** 若额外给出完整 normal AST 中的精确角色锚及复用范围，部分重复字段有可推导空间；当前 checker 没有实现该推导。成熟原语可实现同一义务不自动否定系统贡献，但本轮材料不能把字段复用、代码规模或一次适配时间认定为人工工时收益。

## 4. 可见静态冗余，不等于已节省工时

只读结构比较显示：三份 profile 的 `inactive` 均与 `normal` **整个 JSON 树相等**。定位：ALU `normal:39/inactive:160`；FIR `normal:43/inactive:145`；TD `normal:56/inactive:348`。FIR/TD 的 guard 又恒为 1（`FIR4.json:118`、`TD8.json:250`），所以这些 inactive 树在该 guard 语义下不参与响应选择；当前 schema 仍要求其完整存在。一般条件性合同不因此都可删除 inactive。

FIR normal 中恰有一个与 `boundary_expected` 相同的前缀 AST；active 用一个 probe 替换（`FIR4.json:43`、`:91`、`:121`）。TD 的 R 子树在 normal 的三个输出路径各出现一次，active 对应出现三个 probe（`TD8.json:56`、`:223`、`:253`）。这是结构级重复与明确替换机会；当前程序没有建立这些出现之间的共享节点身份，也没有自动做这个替换。

因此可以提出更紧凑的合同表示，但本轮不能声称已经省去人工规范：当前代码仍要求完整三个输出映射，`generate()` 直接分别解释它们。没有记录 profile 编写、miter 编写、绑定配置、调试或复核的人工计时；字段数、AST 重复次数、代码行数和工具运行秒数都不能替代人工工时。也没有证据证明 profile 的每个重复节点都是人逐字录入。

## 5. 为什么 F + 物理锚不能唯一推出响应

设普通函数为 F(x)，所选边界的正常值为 h(x)。普通正确性只要求替换响应满足 `G(x,h(x))=F(x)`。这约束正常轨迹上的对角，不能决定固定 x 下其他自由 z 的响应。

实际 ALU 信息就给出反例：令 h=`(a+b) mod 16`。当前 profile 的 G₁ 在 mode 0 输出 z，其余模式输出 F。另一种 G₂ 在 mode 1 输出 `(z-2b) mod 16`，其余与 G₁ 相同。取正常 z=h 时，两者都得到 mode 1 的 `(a-b) mod 16`；同一个加法 child、同一个物理端口和相同外部功能均不排除 G₂。取 a=b=0、mode=1、自由 z=1，则 G₁=0、G₂=1。标准适配器的 `verify_and_collect.py:69` 也明确写出该 wrong-mode 公式，供实际结果的数字交叉检查。

选择“仅 mode 0 委托，其他模式不受此边界影响”本身是额外角色事实。当前作者通过 `guard` 和 `inactive` 给出该事实；程序不能仅凭 F 或实例存在恢复它。FIR 必须决定哪个前缀归 `u_prev`；TD 必须决定 R 在三个输出中的哪些出现都归同一个 `u_return` 角色；这些也不能由相同算术子树的出现自动决定。

若“明确 role anchor”进一步包含了 F 的精确 AST 节点/DAG 身份、所有指定复用位置及边界/输出编码规则，那么以 probe 替换该节点的上下文可以机械决定一种 G。边界截断和量化点也须属于锚的语义；不能默认一个数学整数子树与任意窄 RTL wire 可直接互换。唯一性来自**补充的角色/表示承诺**，不来自纯函数。当前 `target.instances/module/port` 只是物理锚，并没有这个数学节点关联字段。一个有限域普通函数也不能决定自由边界域下的饱和/舍入扩展；这些应保持为可信规范，不从候选实现反推。

## 6. 交接决定

当前可以如实交付的是一套闭合输入格式、指定边界核验、有限检查工件生成和来源/工具完整性记录。现有证据未显示它相对同信息标准 miter/cutpoint 减少了必要语义规范，也没有测得人工绑定/编写工时差。相对于明确 AST 角色锚的确定性父构造，本轮未找到一个已实现的、免除额外人工角色事实的独立推导机制。

系统化接口、自动工件生成和可靠的 unknown 分类仍可作为工程贡献的组成部分。是否形成研究上的系统增量，需另有明确的任务适用性、复用或成本对照；当前字段审查不能替代这些证据。若下一步仍以“自动生成责任规范”或“节省人工规范”为核心，应先指出未由作者输入且确已被可靠推导的具体字段，以及同信息基线无法同样消去它的原因；本轮没有这样的已验证字段。
