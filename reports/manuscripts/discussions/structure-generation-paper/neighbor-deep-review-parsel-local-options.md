# Parsel：局部候选组合与生成前架构选择深审

日期：2026-10-21。只读论文与作者源码，只新增本文件；不运行框架、模型、HDL、SAT，不接触本项目hidden，不改旧稿或实现。

**结论：局部候选池、依赖分组、程序组合筛选及固定池内无需再调用模型，都已有直接先例。当前候选的真实协议差别是先组合架构／接口摘要、后生成行为，而非先生成多个函数行为再组合测试。仅把选择前移不足以成立新核心；可保留的最小系统假设是：在同信息与同生成预算下，前置局部架构备选能否改善后续首次完整工程结果，而不把声明合法率当功能收益。现有证据不足以确认该收益。**

## 2. 论文与真实实现：不能弱化的组合机制

论文[§2.3.1–2.3.2](https://arxiv.org/html/2212.10561v3#S2.SS3)先为函数生成行为候选，再在测试依赖SCC内组合；没有独立测试的子函数可并入父层联合检验。[Appendix F](https://arxiv.org/html/2212.10561v3#A6)给出乘积搜索伪代码。源码对应如下，行号均固定SHA。

| 核查点 | 作者实现锚点 | 实际含义及边界 |
| --- | --- | --- |
| 候选单位 | [fn.py L5–21、84–117](https://github.com/ezelikman/parsel/blob/bc1687cab9e8a79249f0d3e3cb4f5826dba39a95/fn.py#L5) | 一个函数节点持名字／参数／描述／子节点及多个实现；基本候选是同一描述与签名下的**函数body**，不是每个候选都重新给完整项目 |
| 子行为可交换 | [fn.py L28–59](https://github.com/ezelikman/parsel/blob/bc1687cab9e8a79249f0d3e3cb4f5826dba39a95/fn.py#L28) | 父提示列子函数描述、签名及import，不钉死某个子body；这正是独立生成后可重组的实际接口机制 |

Parsel还可在不同高层分解之间采样，并在失败后引入新子函数。因此不能说它只有一个永不变化的全局分解；准确范围是：**基本SCC候选组合在既定函数节点与签名下发生**，可选分解扩展另有阶段。当前拟让不同模块接口／分解也成为同一前置组合空间，需要另建可执行的兼容语义；这不是现有源码已展示的字段，但也不自动产生新算法。

## 3. 调用、反馈与预算：本协议不能靠表面差别取胜

[§3.1](https://arxiv.org/html/2212.10561v3#S3.SS1)已有同高层计划的直接完整代码采样消融，亦比较同一生成测试下的直接采样。其`n×k`是等效完整程序采样量，不是API调用数或严格相同总token／测试成本。[Appendix M](https://arxiv.org/html/2212.10561v3#A13)明确单函数与整体采样的不同长度上限；不能借其数字证明硬件协议更省。

实际调用由[fn.py L96–117](https://github.com/ezelikman/parsel/blob/bc1687cab9e8a79249f0d3e3cb4f5826dba39a95/fn.py#L96)逐函数请求候选，[codex.py L37–64、70–88](https://github.com/ezelikman/parsel/blob/bc1687cab9e8a79249f0d3e3cb4f5826dba39a95/codex.py#L37)按缓存补数量并分批调用API。Python默认配置[py_consts.py L159–168](https://github.com/ezelikman/parsel/blob/bc1687cab9e8a79249f0d3e3cb4f5826dba39a95/consts/py_consts.py#L159)是8起、最多64候选；不应把这些代码默认值冒称v3所有实验设置。

固定池搜索可以完全不再调用模型；测试结果只决定选哪组。令候选数固定并关闭展开／补全／回退，就已有可比较的有限池流程。因此，“我们的模型不接收逐次组合反馈”不排除Parsel式强对照。真正不同的是检查时是否已有body，以及选择后是否还发生一次受选定结构约束的行为生成。一次规划加一次行为也不是总共一次模型调用；所有规划、行为、解析失败与无解都必须计入完整分母。

所核源码把输入的assert当搜索约束，不负责本项目的公开／私有分离；论文相关段也不足以重建每次搜索与最终评价的具体测试身份。这里不推断其泄露或违规。移植对照必须只用同一获准公开规则，不能拿我们的hidden来筛架构或筛行为；生成测试与独立终评仍分开报告。

## 4. 与本次有限局部架构备选逐机制对应

| 本次协议 | 相对已读Parsel的判断 |
| --- | --- |
| LLM一次给每处有限局部选项，程序联合选 | 局部候选的组合价值已有；把记录放进一次JSON响应是调用组织选择，须测而非预设省tokens |
| 候选为模块分解／接口／协议能力，尚无body | 是明确的对象与顺序差别。若只验证端点、类型和可直接派生字段，仍只是把常规结构约束提早执行；若声称可组合语义，必须有可信能力依据 |
| 选完后固定结构、一次填行为，无修复 | 改变了搜索证据：舍弃了搜索时的真实行为见证，依赖摘要对可实现性及后续遵约的预测。这个代价／收益是可测问题，不能只称更严格或更可靠 |
| 用枚举、CSP或匹配选组合 | 同池、同约束、同目标且搜索完整时，普通Parsel式乘积枚举可得到相同解；更换选择器没有自动创造协议贡献 |
| 保顶层功能但容许少量结构变体 | 提供了研究对象，不是现成benchmark或创新证据。允许集、接口含义及实际行为检查须先固定，不能用新变体事后排除失败 |

[SynthTL固定实现深审](neighbor-deep-review-synthtl.md)已补强“模型给局部分解／规格备选、程序组合并检查”的重合，本轮不扩文献。综合而言，当前差别**可能仅是旧候选组合流程在架构层的阶段调整**；尚未建立值得单独主张的硬件机制或效果。

## 5. 仍可保留的一个最小系统假设及裁决条件

可检验假设只有一项：**在相同公开事实、库能力和总生成预算下，先给局部架构备选再机械协调，是否比完整架构采样更容易得到后续首次行为生成即可正确的工程？** 这是协议效果假设，不是新候选搜索、首次组合推理或已发现领域空白。

最小强对照应保留：①同局部池的首选／简单合法传播；②同池普通乘积枚举或匹配，以同一规则和排序选解；③同规划token预算的完整结构采样，经同一公开检查选定。各组随后只有同预算的一次行为生成；可直接从公开义务构造合法结构时，还应加入该确定性构造，不能故意保留可消元决策来制造联合选择收益。Parsel式多行为候选加公开测试可作另一个预算配置，但它改变行为采样／筛选资源，不能假装是同一首次协议。

先核公开规则确实存在非逐组独立、非自动派生的兼容约束，再区分池内可行组合覆盖、选定声明合法、实际RTL遵约、完整功能正确四层。最终指标保留全部规划失败／无解／行为失败／UNKNOWN；禁止只对有解池算成功率。搜索评价成本、实际输入／输出tokens、调用数及重试分别记录，不能以候选记录条数代替预算。

若只提升声明通过率、与同池枚举同解却无实现／成本收益，或完整结构采样／确定性构造已消除差异，应停止将该阶段调整当主核心。若得到可重放的真实跨选项约束及上述公平对照下的首次完整收益，才有系统贡献的讨论基础。当前没有该新协议实验结果，本报告不提出运行授权或SCI创新验收。
