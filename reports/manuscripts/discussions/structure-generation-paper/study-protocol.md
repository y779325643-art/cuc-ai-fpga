# 结构生成比较：原基线与局部责任划分协议准备稿

日期：2026-10-21。文档修订：准备稿 0.3。本文是 P02 的实验设计材料，不是论文正文、已执行方法、注册交换格式或实验授权。用户已确定 A 路线及“不加入修复”，并选择先细化局部责任划分；正文写作确认点保持关闭。进度只在[论文清单](../2026-10-21-structure-generation-paper-checklist.zh.md)维护。

本篇拟研究旧版 System-HIS 原型，不把它声明为 `sr2fpga-pc-2.1` 或 `paper1-v2.2` 官方实验。当前规范继续有效，本准备稿不改变其定义或已有证据。

**当前适用性：** §1–9 保留原 M3/M4 的范围、失败分母与证据口径；它们不是当前新增机制的完整主实验计划。§10 给出本轮修订的局部责任划分主对照建议，方法见[方法卡 v0.2](local-responsibility-method-card.md)。共同终点及完整失败保留原则继续适用，但新条件身份、输入声明、任务资格与记录仍待实施及版本化验证。协议未冻结，不据此启动实验。

最新决定：最后一轮有界设计未满足区分判据，已[停止局部责任划分核心候选](local-responsibility-bounded-design-review.md)。§10 转为历史技术准备，不是下一项要执行的主实验；原 M3/M4 纯实证定位也未自动恢复。

## 1. 待检验问题与允许的解释

研究问题：在公开需求、模型、生成契约、共同准入和外部评估一致时，将部分工程结构交给确定性构建器，并把模型输出限制为行为体，对初始工程的结构失误、可信功能验证及综合结果有什么影响？

| 内容 | 准备稿决定 |
| --- | --- |
| 主比较 | M4−M3，`@initial`，不做工具反馈修复或模型格式修复 |
| M3 | 一次生成契约之后，模型一次生成完整工程 |
| M4 | 消费相同契约；程序生成实际支持的结构，模型一次填写行为体 |
| 处理变量 | 确定性结构构建与模型输出责任/自由度约束的组合 |
| 预期机制（假设） | 减少模型负责的接口、实例、连接及包装失误；若组件行为仍错误，功能终点可能没有改善 |
| 可否证情况 | M3 同样可靠；M4 构建失败或表达限制抵消结构收益；结构改善但功能不变或下降 |
| 不支持的归因 | 契约表示优于无契约、骨架文本单独有效、修复有效、优于其他 agent、PPA 提升、PC 2.1 完成或可上板 |

两组均消费契约，所以不能用本对照估计“有契约对无契约”的效果。输出长度和包装责任变化属于处理组合；结果不能单独归因为 prompt 文本、token 减少或模型推理能力提升。

新颖性尚未验收：[VeriGraphi v2](https://arxiv.org/abs/2604.14550v2)已明确使用结构图约束层次、接口和连接，并根据关系装配 top；[层次 IR 工作](https://arxiv.org/abs/2608.30659v1)也区分拓扑与模块行为。[CPPL v1](https://arxiv.org/html/2605.17892v1#S3)方法段与作者代码进一步显示，固定接口/层次、预置实例、模型生成剩余逻辑和确定性 lowering 与本篇有直接机制重叠。[HINT v2](https://arxiv.org/html/2608.07625v2#S5)已有控制外部 contract、oracle 和修订预算的路线比较。不能以“结构＋模型行为”或“有受控比较”本身声称首创。

本次有界复核在所读方法、算法与消融中未找到严格等价的“同一实际生成契约字节、完整模型工程对程序结构＋模型行为、initial 无修复”对照。这只留下可能的实证问题，不能证明领域空白，也不能直接判定足够投稿 SCIE；CPPL 各实验 DSL 的实际来源仍未明确，不将“对方全部人工给结构”作为差异依据。具体范围、章节、代码修订与限制见[原文核对矩阵](related-work-matrix.md)。

**原两条件比较的后续用途：** M3/M4 仍可提供已有机制基线，主要判断依靠外部可信功能、综合、完整失败分母及成本，而非程序自己保证的结构检查通过率。论文最终方法需增加用户认可的具体机制，不能把这里的原比较直接当作最终贡献方案；候选规则、例子、代价和对照见[新增机制讨论](mechanism-options.md)。

## 3. 任务总体、调试与独立单位

输入名单以[任务就绪表](task-readiness.md)为准。当前仅有静态候选，没有 P04 运行资格，不预定这些任务一定进入主对照。

- 调试候选：事件计数、流式累加、帧内峰值。它们服务于流程调试，不自动进入主效果分母。
- 主候选：FIR、固定 ROM 点积、匹配滤波、帧式相关峰值流水、定点 TD 更新、可配置值/策略更新子系统。最终纳入规则基于规范明确、结构责任可记录、可信评估可运行；不得参考模型胜负挑选。
- 默认先讨论旧 width-8 与已有数学常数，避免在“最小准备”中附加全参数化工作；这不产生参数范围泛化证据。
- 变异资格、确定性控制、历史样例、pilot、主对照各自独立标识，不能相加当模型样本。

分析单位是独立设计/架构谱系，配对重复嵌套其中。同一项目换 seed、输入序列、提示措辞或轻微参数不自动成为新独立设计。FIR/匹配滤波/相关峰值的过滤器谱系，以及 TD/更新子系统的共享机制需审查；不能把六个候选名字直接当六个独立簇。P07 前必须确定其分组与可推广范围。当前不作功效充分或样本数量达标承诺。

## 4. 模型可见输入与结构责任

两组共同公开输入：同一份来源可追溯的需求、接口/目标/能力事实、同一生成并通过共同准入的契约字节。生成与评估分离；任务选择元数据、参考实现、期望输出、私有向量/seed、评分记录和旧结果不能作为模型输入。

M4 额外输入只允许从这些共同事实和契约确定性导出的结构，例如实际支持的模块头、参数绑定、实例和连线，以及行为孔位置。它不额外得到算法实现、任务族专用示例 TB、golden 输出或 evaluator-private 材料。投影按允许项检查，而非仅删一个已知文件名。最终工程中可保留调试 TB，但它不提供可信验收信用，也不能因 M4 的包结构而额外泄露给模型。

逐任务登记以下来源：模块/端口、实例/连线、内部层次、状态/时序/握手行为、常数/ROM 内容、manifest/约束、初始化数据。程序必须提供的是协议登记的结构，模型负责的行为必须真实保留为空待生成；不能用任务模板行为填充后再把成功归给模型。

若 M3 需生成包装文件而 M4 自动提供，它是组合机制的明确组成部分。论文不声称已经控制成“只给同一串骨架文字”的纯文本实验。

## 5. 共同准入与配对执行

拟采用一份生成契约、一次共同准入、两个独占工程生成的配对路径：

1. 从相同公开需求作一次 REQ2HIS 调用，保留原始输出、解析失败、截断或空响应。
2. 共同准入核查 schema、既有静态良构/引用、公开要求一致性、固定身份和适用的公开能力约束。具体检查与结果格式须在 P03 版本化落地；不得以“先构建出 M4”决定 M3 能否进入。
3. 共同契约设计失败时，两组都保留该计划位置与同一失败来源；不再生成新契约寻找成功。
4. 契约通过后，M3 与 M4 消费同一规范化契约的字节承诺，原始响应另存，命名白名单见下文；按预定的 AB/BA 平衡或随机顺序各执行一次工程阶段。重复之间重新作独立配对，不复用最有利契约。
5. M4 构建器自身失败只属于 M4；M3 输出或包装失败只属于 M3。记录失败与实际已发生调用，不把它们删除或把未发生调用算成零成本成功。
6. 封存每组终端候选，用同一外部评估配置判断；评价结果不反馈给本篇候选生成。

共同静态检查不应弱化 schema、既有良构或需求一致性。旧 H2 状态含 emitter 成功语义，新检查不能伪造为旧 H2 通过；若现有记录不能准确承载，先解决合同版本缺口再运行。协议仅讨论已声明支持的能力范围；不证明任意 JSON 契约可以构建。

生成阶段禁止隐含多次采样、模型 JSON 修补、第二次行为填充、工具反馈修复或 oracle-HIS 替代。已知执行失败、未知 provider 执行状态和允许的基础设施恢复需分别记录；未知执行状态不自动重发。provider seed 不支持时记录限制，不声称 seed 可完全复现模型。

现有 `generation/context_his.py` 会把 `project_name`、`project.name`、`project.project_name` 规范为 controller 固定名称。本篇需事先声明这些命名字段的归属，分别保留原始响应与规范化契约的字节/哈希，并使两组消费同一规范化版本。此类命名处理不应被误记为模型正确命名，也不能扩展为悄悄修补端口、状态、参数或算法；原始失败/截断不可由规范化抹去。

## 6. 共同终点与记录语义

主要终点拟采用“可信功能检查与指定综合均通过的完整工程”，须同时具备：共同输入与候选字节绑定、工程包/接口边界符合公开要求、指定 lint/编译检查通过、评估器拥有的已资格 harness 功能通过、指定 Yosys 综合通过。功能结论仅覆盖已运行测试，不等于形式证明。

验收使用[现有公开评估实现](../../../../agent/src/sr2fpga_agent/public_evaluator.py)与适用的注册记录；候选自带 TB 和 `TEST_PASS` 文本不提供可信功能信用。没有可信 harness 的 `not_run(needs_oracle)` 不算功能成功。generic Yosys synthesis 不能写成目标 FPGA LUT/BRAM 映射或物理时序证据。

此终点是本篇从已注册阶段记录重建的分析指标，不伪称官方 VPP、hidden/L4 成功，不创建与现有运行记录相竞争的“成功证书”。若需私有最终验证，其 scope、执行隔离、一次提交及记录方式必须在 P07 前确定并单独明确授权；本稿不自动增加 hidden 评估。

| 观察 | 分析处理 |
| --- | --- |
| 共同契约已知设计失败、解析失败或截断 | 两组同一位置为设计失败，保留上游类别；下游 `not_run` 不从完整分母删除 |
| 某组已知工程/结构/行为错误 | 该组设计失败；保持另一组实际结果 |
| 所有必需阶段可信通过且绑定一致 | 该组在本篇有限终点下通过 |
| 工具/环境中断，无法得出设计判定 | 基础设施缺失；不默认为设计失败、成功或零开销 |
| provenance、权限或 artifact 绑定不一致 | 单列完整性问题，暂停受影响执行并保留材料，不分配通过信用 |

次要指标：共同契约准入率、工程完整/结构符合情况、可归因的接口/实例/连线等错误类型、功能与综合分阶段结果、调用/token/工具时间/墙钟与失败成本。结构错误分类须按实际诊断/源码核实，不能把 M4 固定结构的名字检查结果当独立功能收益。

## 7. 分母、配对分析与不确定性

设每组有 N 个计划位置，分别报告通过 P、确定设计失败 F、未决/基础设施缺失 U，满足 P+F+U=N；缺失与完整性事件另有可追踪原因。

- 报告全部计划位置及每种失败；共同契约失败属于两组完整位置，不只展示契约通过者。
- 有缺失时报告通过比例的全分母下界 P/N 与上界 (P+U)/N，不把下界解释为把缺失判成设计失败。已判定位置中的比例 P/(P+F)只能作为明确条件下的补充描述。
- 在两组均有结论的位置报告配对一致成功、仅 M3 成功、仅 M4 成功和共同失败；同时列配对缺失数。配对差值的完整范围可用未知结果 0/1 的上下界推导，不能只取完整配对伪装成全总体效果。
- 全部位置的机制结果与“共同契约合法条件下”的结果分开，后者不代表自然需求到完整工程的总体成功率。
- 设计/任务谱系层面汇总，重复和多个变异不是新独立样本。独立簇很少时优先报告逐簇结果与有限案例差异，不预先承诺 bootstrap 区间或显著性；若 P07 选择推断方法，须说明适用条件并在主结果前固定。
- 不以显著性决定是否追加调用，不在看到主结果后改指标。探索性错误分析单独标识。

## 8. 调用、费用与工具预算

| 范围示例，尚未授权 | 计划条件输出 | 无重试、阶段均执行时的实际调用 | 独立运行归因 |
| --- | ---: | ---: | ---: |
| 3 调试任务 × 1 对 | 6 | 3×(1 共享契约＋1 M3＋1 M4)=9 | 两组各 2 次，共 12 |
| 6 候选任务 × 3 对 | 36 | 18×3=54 | 两组各 2 次，共 72 |

实际调用数与 HTTP 请求数、逻辑计费和独立归因分开。共同契约失败可减少实际后续调用，不制造替补。共享契约执行一次，但其完整成本应进入每组独立运行归因；不得全部记给先执行的一组或宣称共享部分免费。配对记录必须绑定规划执行的原始成本事件、响应及失败来源，不能只凭 context、seed 或消费契约哈希推定它们属于同一次执行。两组每个初始阶段一次模型调用；本篇无修复，不能把 B4 四次上限改写成四次免费尝试。

以下项目前未确定：具体 provider/模型及观察到的版本，解码与 seed 能力，REQ2HIS/工程阶段输入/输出 token 上限、截断策略、HTTP/逻辑调用限制、并发/重试策略、单次与总墙钟、工具/EDA 时间上限、总费用及本地存储上限。这些待定不阻塞静态审计和离线实现；在明确前不启动 P06/P08。

两组使用相同阶段预算规则，记录真实输入长度与输出长度；不人为补字使 token 相等，也不默许某组额外重试。模型上下文不足按预定规则记录，不能悄悄删掉失败样本或隐藏费用。费用估算须等模型及公开价格核实后给出，当前不虚构人民币金额。

## 10. 局部责任划分：当前主对照建议

适用状态：历史候选方案。最后一轮设计已完成且结论 STOP，以下匹配比较不执行；保留是为说明曾评审的输入与责任控制，不作为该机制仍在推进的证据。

以下标签仅为文档中的条件简称，不是已注册 method ID；不冒用 M5、不以新 profile 结果充当原固定 M4 结果。

| 条件 | 顶层责任 | 两条件固定项 |
| --- | --- | --- |
| 局部委托 | 按同一原语规则计算共同实现组；程序完成支持组，模型生成其余顶层表达式 | 同一生成 PC、公开声明、固定接口/实例/内部信号、相同叶行为路径和语法、表达式语言、一次工程调用与阶段预算规则 |
| 整体委托 | 在存在不支持组时，模型生成全部可委托的顶层赋值；固定接口/实例仍由程序提供 | 同左；模型可写集合在生成前固定，不能看结果调整，不额外给算法答案或 TB |

推荐最小主比较先采用以上两条件；原固定 M4 用于全支持形态退化与覆盖检查，是否另作模型条件在运行计划中决定。原 M3 仍为历史参照，保留或恢复为额外条件需在最终方案中明确，当前不默认扩为四组。原两条件实验未运行，不存在将旧主结果删除的问题。

两者只改变生成前的顶层责任分配策略；残余集合和输出长度随策略变化，属于处理的一部分。结论不能单独归因于连通组算法、提示词或 token 数。不能只拿原 M4 无法表达新形态的预期失败来证明局部策略优于匹配模型生成。

所有顶层义务受支持时，两策略均走程序构建，不人为把整体条件强制改成自由输出；这种退化必须记录。所有可委托顶层义务归模型时，两者同样应退化一致。不能更改 E_c 去制造这两种现象。混合形态以输入/输出/中间局部等位置覆盖，但参数/位置/seed 变体不自动计新独立设计。

共同输入需区分需求原始事实、规划生成的架构绑定与 controller 推导的拥有者计划。公共补充声明与规划来源必须对称、可追溯；手工开发例不能当作自然需求到模型架构的效果样本。若研究中实际采用手工架构，应单列该条件并限制主张，不能混入生成 PC 分母。

共同生成规划或共同语义失败保留两条件位置；单条件划分、表达式、叶行为或构建失败只属于该条件；无终端结果不得删除。可信功能和指定综合的主要终点沿用 §6；驱动、依赖或环境错误不伪造通过。若刺激自身违规，单列评价环境问题并留原件，不能由候选错误的 ready/valid 取消原本合法刺激。

N 个预定共享规划单元的最小两条件规模为 2N 个条件位置，所有阶段执行且无重试时共 3N 次模型调用；独立运行归因每条件包含自己的完整规划成本，为每条件 2N 次调用当量。若加第三模型条件，上界为 3N 个位置、4N 次实际调用；四条件则为 4N、5N。HTTP、token、费用与失败开销按实际事件另算，不从此公式推定价格。

本轮没有确定 N、模型、总费用、工具预算或私有最终评价范围；不启动 pilot。进入模型前仍须完成公平性修复、新 profile 身份/来源/失败记录、混合案例资格、叶边界与真实依赖检查、离线集成及明确的运行上限。案例准备见[资格计划](hybrid-case-qualification-plan.md)，实施拆分见[实施范围](implementation-scope.md)。
