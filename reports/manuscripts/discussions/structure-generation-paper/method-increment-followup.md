# 方法增量后续裁决：自动导出义务与完整局部域

日期：2026-10-21。任务：在已完成近邻深审和真实控制/原生 pilot 之后，最多筛两项具体改进；不修改英文 v0.2、既有 profile、候选或评价，不运行模型/HDL。

**结论：本轮没有可建议作为 SCI 方法核心开发的保留项。** 两项确有工程作用的改进分别是“由明确语义锚点自动生成响应”和“按已有局部数学生成完整局部域验证”；前者在当前三个任务上退化为普通 AST 替换/父逻辑编译，后者是标准模块级功能验证的覆盖补全。不能因使用成熟算法就否定潜在领域方法，但目前没有额外领域机制或同信息可区分收益来支撑它们成为新核心。下面给出具体处理步骤、强替代和停止条件，避免仅用“可能有价值”交付。

## 1. 先纠正需要解决的问题

当前 all-output response 在给定普通输入 x 和自由边界 z 后，完整定义了所检查父上下文的外延输出函数。它不必固定某一语法/网表，但不是更少的行为语义。把完整 response 从文字改成 JSON、guard 卡片或生成顺序，没有解决“用户是否已经再写了一遍参考父函数”的问题。

更根本地，普通数学 N(x) 和子模块数学 h(x) **不能唯一推出**额外角色。以正常加法 h=a+b 为例，父上下文 `C1(x,z)=z`、`C2(x,z)=a+b`、`C3(x,z)=z+(z-h(x))` 在 z=h(x) 时相同，在独立 z 下不同。若 N 是固定宽度函数，按相同输出编码构造也能给出这种非唯一性。任何算法仅证明 `C(x,h(x))=N(x)`，都不能据此证明 C 是用户所想要的架构。

因此额外角色的正当来源至少需要一项：用户明确指定计算分解/复用关系，或真实部署要求给出可观测的替换/故障隔离/升级语义。当前三个开发 profile 采用前者。它们没有测量物理复用、故障隔离或组件升级，不能倒推这些动机已经成立。若用户只要求普通 N，就没有理由为了得到失败而新增自由响应义务。

已知实测约束：原始 native12/12 与统一同 child 程序父12/12全部通过；global/located各6/6；六个手写全宽控制符合计划。手写负例说明逻辑区分可表达，不说明自然模型违约常见，也不提供以下改进的实际收益。[最终汇总](../../../../artifacts/codex-responsibility-transport-20261021-01/evaluation-summary.json)、[全宽控制](../../../../artifacts/responsibility-full-profile-qualification-20261021-01/results.md)。

## 2. 候选一：由明确语义锚点编译响应，避免第二份手工函数

### 2.1 输入、处理与输出

**输入严格复用：** 当前 normal 的闭合整数 AST、模块的完整局部数学/位宽、既有实例接线，以及用户已明确的角色锚点。锚点必须说明“这个有身份的规范子表达式由这个组件结果实现”，而不能只写一条名为 use 的布尔标记。删除现有手写 active/inactive 值作为推导输入；它们只能在未来资格核对中作为历史独立参照，不能暗中喂入转换。

具体新增步骤：

1. 对普通数学 AST 的表达式位置分配稳定身份，保留宽度、signed、wrap、floor、sat 等边界，不任意把它们扁平化。
2. 用用户给出的实例—表达式锚点和接线实例化局部函数，确认匹配的数学项及生效分支。只接受精确子项匹配或已经证明安全的等式；不把“同一正常函数”误当唯一正确架构。
3. 将锚定项替换为独立符号 z，沿原 AST 计算所有受影响输出；其余输出直接复用普通表达式。由现有分支路径导出 guard，不另让用户重写全部 inactive 数学。
4. 输出派生 AST、锚点来源、替换位置、数值边界和不支持原因。未找到项、多个语义不同的位置无法消歧、或需跨饱和重写时停止/报告歧义，不让 LLM 静默选一个后当用户意图。
5. 如需进一步生成，LLM只负责编写符合这份派生语义的 RTL；程序亦能直接编译派生父上下文，两者都必须获得相同义务。

这里新增的是自动消除一份重复的手写 response，不是自动发现用户的真实角色，也不降低完整外延函数所含的信息量。

### 2.2 现资产的具体 case

| 现有输入 | 按上述步骤得到什么 | 仍必须人工/公开提供什么 |
| --- | --- | --- |
| ALU4：normal 是 mode 条件树；00子项是 `a+b`；child是adder4 | 在00的锚定项换z，保留其余分支；导出原来同样的全输出响应 | 00应由 `u_add.sum` 承担这一架构选择，不是由 `a+b` 数学自己推出 |
| FIR4：normal含 `(3*x0-2*x1)+x2`；`u_prev`对应前两项 | 把锚定前两项替换为z，输出 `wrap7(z+x2)`；edge_value沿用普通式 | 链的次序/绑定及表达式身份；不因另一种加法排序普通等价就推断相同模块角色 |
| TD8：normal中 R 在return/error/update各式重复出现；R有明确 `u_return` 身份 | 一次标记R并在所有有身份的引用处替换，保留既有sat/floor链，得到原response | R引用关系及饱和次序。不能把包含同值式的每处文本都不加区分地替换 |

三者现有 normal AST 已经把关键子项直接展开为匹配位置，**不需要 LLM 发现分解、不需要 e-graph 或 solver 才能完成转换**。同一派生上下文本身也足以直接生成父 RTL。对当前资产，这一方案首先应被视为一个普通编译器前端便利功能。

### 2.3 近邻和同信息强替代

- **CPPL实际已有：** frontend 固定接口/实例/参数绑定，模型写剩余 operations；一旦父 mux/operation graph 确定，CIRCT确定性发射。[同期 compiler L174起](https://github.com/SawyDust1228/CPPL/blob/838aab3d81237baefdd4807ce0d09a8146192efc/cppl/frontend/compiler.py#L174)、[emitter固定版本](https://github.com/SawyDust1228/CPPL/blob/d7ebbb5f4036ac57a768bc362996ab05e8c39b9f/cppl/codegen/circt.py#L345)。本候选在它之前加“用公共数学项导出父图”，不是发明新的父图表示或 lowering。
- **HINT / VeriRefine已有：** 可执行/逐信号完整表示已固定真实父行为；本候选只是少写一份由相同普通数学和显式分解可导出的表示。它们的实际验收和语义范围不能弱化为只看名字，详见[CPPL/HINT深审](neighbor-deep-review-cppl-hint.md)和[VeriRefine/EQY深审](neighbor-deep-review-verirefine-eqy.md)。
- **普通替代必须获得：** 同一 normal AST、局部函数、角色锚点和接线。最强最小基线是结构子项替换＋直接父 RTL 发射；若有代数重写需要，再比较普通有类型/数值侧条件的等式重写，而不是只比字符串查找。

新增primary核查：[egg v3](https://arxiv.org/html/2004.03082v3)，§4.2给出分析事实约束的条件/动态重写，§4.3按代价提取，§6.2.1包含把表达式替换为融合算子的具体用例。它证明“应用领域等式＋分析＋提取”已有实际机制，而不仅是通用solver理论可表达。本轮没有运行egg、没有核完它的所有硬件应用，也不据此断言任何特定带sat/floor的RTL重写已自动正确。

### 2.4 可区分反例、工程上限与停止

真正的反例是**不能识别**，不应伪造成模型失败：未给role锚点时，前述C1/C2/C3都满足普通数学，推导器应拒绝声称唯一角色；给锚点后，简单子项替换应与本方法同结果。若把 `sat8(sat8(100+100)-100)=27` 错改成 `sat8(100+(100-100))=100`，这是转换器不保饱和边界的工程错误，不是证明新机制的正例。

若未来选择开发，硬上限建议为一个现AST上的纯转换模块、一份派生回执和至多八个静态资格case；不加入自然语言解析器、通用等式饱和引擎、时序新任务或更多模型调用。可复用既有binding/evaluate。该范围是计划上限，不是已实现/工时估算。

可反驳收益只应是“比手工另写全response少重复录入且保持精确语义/可定位歧义”。必须与同信息的普通AST转换比较，而非与完全手工文本比较后宣布新算法。如果简单替换/父编译完成相同步骤，或仍需在锚点里编码完整父函数，则**停止把它作为方法核心**。当前三任务已经满足这一停止条件的结构前提；没有已证的独特处理能力，**不保留为SCI核心候选**。是否把它做成便利功能需按工程需求另定，不靠稿件篇幅推动。

## 3. 候选二：按已有局部数学预生成完整模块域义务

### 3.1 输入、处理与新职责

这项改进解决的是当前确实未覆盖的“全leaf局部函数、所有声明连接”问题，**不再把模块职责等同额外角色合同**。

输入是当前公开任务已给的四类局部数学：adder4、mac_unit、discounted_return_core、td_update_core，完整接口/数值域和固定实例绑定。程序将每种局部数学编码一次，按实际端口域生成普通功能等价义务；按预声明接线生成连接证书和顶层组合义务。LLM仍可选合法RTL实现/算术写法，但不能改变局部函数。程序在生成前冻结义务，生成后从实际elaboration定位各模块/参数化实例，再用标准miter验证。若模块存在多种参数特化，身份和域必须随特化记录，不能混用一个名字。

这避免另写一份独立的 all-output free-response：需要的是原任务本已要求的普通局部函数及其组合，不引入关于不可能内部值的额外架构语义。但它只证明普通可组合功能，不识别一个正常等价的父重算是否违反另行接受的角色偏好。两者不能偷换。

具体新增步骤是：局部数学→有精确编码的参考模块；接口/绑定→逐实例连接记录；局部RTL→完整局部域证明；通过的局部摘要→组合检查；保留证明/反例/unknown及责任定位。所有步骤可用成熟工具，不宣称新的分区、cutpoint或solver。若参考模块直接由原完整AST编译，仍需独立资格来控制同源错误。

### 3.2 现有case、反例与真实边际

TD8是最明确的现资产。真实return模块的普通R范围为[-2168,2151]，而 update 的**既有公开局部接口合同**要求接受整个signed17域。完整局部证明可覆盖normal top采样和当前19个z未穷尽的组合。以 `discounted_return=65535, value=-128, alpha=16` 为例，精确差65663需要18位；若错误地先在signed17中相减，则绕回-65409，E从应有127变成-128，U从-1变成-128。这是现有完整局部数学的分析反例，不是发现某个native输出有错；本轮没有读取/测试新候选。

FIR的mac_unit合同也覆盖所有signed4 sample、signed3 coefficient和signed7 accum，而固定链只使用少量系数及受限可达accum。局部验证可补足这个域。**不能把“更大覆盖”自动写成更好生成：现12原输出全部通过既定检查，尚不知道是否有任何局部全域失败。** 手写重算负控制的leaf本来可以都正确，所以本候选不会凭局部证明识别那些父角色违约。

### 3.3 实际近邻和最强替代

CPPL的宽度传播和静态IR合法性是实质已有能力；后续patterns已解释执行真实dependency并读内部probe，但仍是所给case/sequence的执行，不由此推出每个局部函数的全域证明。[worker L285起](https://github.com/SawyDust1228/CPPL/blob/d7ebbb5f4036ac57a768bc362996ab05e8c39b9f/cppl/agents/worker.py#L285)、[patterns L71起](https://github.com/SawyDust1228/CPPL/blob/d7ebbb5f4036ac57a768bc362996ab05e8c39b9f/cppl/ir/patterns.py#L71)。HINT已有前RTL语义验收、后RTL共仿真和特定任务形式等价；VeriRefine完整ASTF也给出了足够多的局部行为目标。不能只因其论文未列本候选的每个步骤，就认定整个模块证明管线新颖。

第二项新增primary核查：[XLS官方 Solvers](https://google.github.io/xls/solvers/)，阅读“Correctness WRT reference”“IR Transform validity”“IR to netlist LEC”和“Current Limitations/Subroutines”。已有参考/实现的位向量翻译、变换前后等价和IR到网表的实际验证流程；文档也说明其子程序处理需inline及复杂乘法的成本限制。这是具体强流程，不是“solver或许能做”。本轮未运行XLS、未核实当前任意LLM HDL可直接输入它，也不把它写成已有本项目局部证明的实测结果。

同信息强替代是：按相同四个局部函数、同完整端口域生成普通Yosys/SAT或其他成熟miter，并核对同一实际接线；或将完整运算图交给现有typed compiler确定性发射。与它比较，不能把“局部全域对当前有限样本”这种覆盖不等的差异算成新算法优势。

### 3.4 工程上限、收益与停止

若未来确需补验证覆盖，最多新增一个局部reference/obligation适配器和一个实际模块/端口连接核对器，只支持现四类组合模块；不扩时序、资源、其他算子、不新造任务或触碰既有评价。所有新结果须进新artifact且独立资格，不能重写旧12/24的含义。标准工具每模块硬时限和unknown处理需预先规定；33-bit update输入域的证明成本不能凭直觉保证。

可反驳收益是“以一次局部数学编码覆盖实际多个实例和更宽局部域，并保留可定位证据”，但需与相同自动化的标准逐模块miter比设置工作量和结果一致性。若两者输入/处理/输出相同，就只是把已有流程接入仓库。当前没有新的契约推导规则、证明组合规则或已证的成本优势；它是有用的覆盖补全选项，**不保留为SCI方法核心**。不得把旧筛选已否定的泛化精度推导重新命名复活。

## 4. 总裁决与不应继续的路径

| 问题 | 本轮结果 |
| --- | --- |
| 能否从普通功能自动发明额外角色？ | 不能；非唯一性构造直接否定。需要明确架构来源，或放弃该额外角色要求。 |
| 能否少写一份完整response？ | 可以，从已有完整数学和明确分解编译；当前三个case普通AST替换即可，且能直接发射父逻辑。属于可选工程便利。 |
| 能否生成前固定可验证的跨模块义务？ | 可以，把已有局部数学/绑定变成标准功能证明目标；现任务普通编译/组合验证已有同工同能强替代。 |
| 是否已有本轮新增机制相对强替代的可区分收益？ | 没有。当前原native与程序父都全过，也没有录入成本/用户错误负担测量。 |
| 应否立即进入这两项的SCI核心开发？ | 不建议。核心新增机制仍未成立；不能以工具覆盖缺口或减少重复JSON自动完成创新目标。 |

两项可分别留作工程backlog；本轮不授权实现，也不把它们作为被采纳的新研究主张。若后续要继续找方法核心，所缺的是现资产中**独立于预先手写完整函数、确有实际动机的未决设计问题**，以及相同输入/工作量下不能由直接构造完成的处理增量。没有这样的具体问题时，不应再加一个角色标签、规则名字、补失败案例或扩大任务人口来制造区别。

阅读限制：沿用两份已完成深审中的固定CPPL源码/论文事实；仅新增egg v3上述方法段与XLS官方方法文档这两项primary sources。没有把未读作者实现判定为缺失，没有做全面查新，也没有据未找到同名方法判原创。本轮唯一写入文件为本报告。
