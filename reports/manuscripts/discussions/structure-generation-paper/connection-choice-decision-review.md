# 连接来源备选协议：创新性与可行性裁决

日期：2026-10-21。性质：内部研究评审与执行顺序，不是论文正文、正式研究定义或效果证据。进度只由[主清单](../2026-10-21-structure-generation-paper-checklist.zh.md)维护。本记录衔接[前轮实际验证](new-core-screening.md#11-连接来源限定版实际有界验证)，不恢复已停止的局部责任划分，也不采用历史M06并发变体。

## 1. 本轮结论与适用边界

**当前不通过“进入完整开发和正式模型实验”的投入门槛，不建议将此候选直接定为最低补工SCIE论文的主核心。** 可以保留为生成协议假设；这不等于证明它毫无创新，也不是宣布结构生成论文总任务停止。

依据是：连接有限域、组合搜索、结构先行及模型实现已有直接近邻；现有fork/FIR案例的合法结构可以从共同公开的角色与义务直接产生，尚未证明模型提供连接备选的必要价值；同时，当前骨架尚不能实际保护所宣称固定的FIR内部结构。需要投入工程后才能测的首次功能成功率和全流程成本，至今没有结果。

采用成熟求解器本身不是否决理由。若局部候选协议在真实任务上相对同预算完整方案及直接程序构造有稳定收益，它仍可能形成方法贡献；本轮没有观察到这种收益，也不能根据“未找到完全相同论文”确认原创性或SCIE可接受性。

实际完成：问题与信息边界核对、近邻原文复核、现有资产案例审查、强对照的小域诊断、工程入口审计、后续实验的归因与停止规则。没有修改生产Agent、合同、可信评价器、oracle、数据或研究权威；没有运行模型、HDL、训练、主实验或正文写作。

## 3. 本次唯一评审对象

第一次LLM输出单一模块/接口声明和不超过6个决策组，每组1–2个明确、有序的连接来源选项。程序只用共同公开的需求、接口及已登记能力，枚举不超过64种组合；合法方案以备选使用次数最少为优先，并以固定顺序处理并列。无解记录失败，不增补来源、重采样或删除样例。选中结构固定后，第二次LLM只实现允许的行为，独立评价不反馈本次生成。

本版本不搜索模块分解、状态放置、布局、实现目录或资源属性。模型解释不能变成可信硬约束；自报置信度不是校准概率。组合环检查只适用于已有公开组合依赖，不能禁止合法寄存器反馈。

完整握手通道包含data/valid与逆向ready。fork选来源时ready目标随源通道变化，因此“固定逻辑接收通道”不等于“每个选项的原始RTL目标集合相同”。若坚持后者，应把straight/cross整体映射归为一个二选一组；此例随之失去跨组搜索问题。两种表示必须先选清，不能拆ready制造方法收益。

## 6. 强对照诊断与它能说明什么

本轮新增的诊断只处理上节有限公开数学对象：每组列出全部有序非空子列表，即两个单元素池和两个顺序的双元素池。fork共16个池，FIR共64个池。局部首选不作跨组检查；联合枚举按相同可行性及备选计数选解；强基线直接产生两种出口匹配或两条三项线性链，再按同一候选池和目标过滤。直接构造器不读取枚举结果作为答案。

实际执行：`python artifacts/connection-choice-strong-baselines-20261021-01/verify_strong_baselines.py`，退出码0。主审已核对脚本中独立的连接/符号检查、模板构造、排序及完整分母。计数、全部池及来源hash见[执行结果](../../../../artifacts/connection-choice-strong-baselines-20261021-01/results.md)。

| 诊断量 | fork | FIR |
| --- | ---: | ---: |
| 全部有序非空候选池 | 16 | 64 |
| 联合枚举可行 / 无解 | 14 / 2 | 46 / 18 |
| 局部首选满足有限符号条件 | 8 / 16 | 16 / 64 |
| 直接构造与枚举的可行集合及最终选择一致，含无解 | 16 / 16 | 64 / 64 |
| 各组两项全列的池：存在可行结构 | 4 / 4 | 8 / 8 |

表中计数只描述这些人工有限域内的符号可行性和选择，不能当作模型成功率、真实错误分布或功能通过率；尤其不能将14/16或46/64写成RTL功能成功率。

需要保留的解释边界：

1. 即使联合枚举胜过局部首选，也只证明不顾跨组条件会出错；普通匹配/链构造同样可以实现这部分收益。
2. 若完整真实来源域恰有两项且每组都被要求输出两项，池覆盖已机械保证。当前协议允许只给一项，所以总体覆盖并非自动保证；本轮枚举子池正是为了保留缺项/无解的情形。
3. 直接程序能在这两例产生完整合法结构，说明其连接候选提议可能是多余步骤；这不推出一般自然语言模块规划、接口设计或RTL实现都无需LLM。
4. 等价解可能有不同偏好得分，但偏好得分不是功能、PPA或成本改善。局部池的表示压缩是否降低真实token和失败开销，仍须与完整方案生成比较。
5. 对小域直接构造与枚举等价，不构成协议无价值的普遍证明；它削弱的是当前案例对新增方法价值的支持。

## 8. 真实模型阶段：尚需什么，什么结果才能继续

若后续仍决定押注协议价值，应先通过案例与结构保护门槛，再在已有授权明确覆盖的范围内实施。执行前还必须确定模型版本、任务修订、重复数、各阶段token/超时/工具/费用上限，以及失败和停止规则；本轮没有这些运行配置，也不启动模型调用。

最小顺序：先两个合格案例各一个预定重复作流程哨兵；可靠后可考虑各三个重复的描述性pilot。这个规模只检验流程、候选覆盖与明显成本风险，不足以证明总体效果或SCIE贡献，不能以“有一例获胜”作为继续条件。

必须分别回答：

- **选择是否有用：** 同一缓存池、相同公开约束下，局部过滤首选与联合选择比较；普通匹配/链构造作为强对照。等价选择器可离线核查，不必人为增加付费组。
- **模型候选是否有用：** 给定同一模块/接口声明，程序直接从公开端点/角色生成合法结构，与LLM连接提议比较；把声明理解与连接候选贡献分开。
- **局部表示是否划算：** 同一公开事实、相同规划调用数与token上限下，比较一次完整连接、预算允许的多份完整连接筛选，以及局部备选协议。各组仅在规划前的公共约束下选择，随后最多一次行为生成。

主终点是最终项目首次可信功能成功及全流程实际成本。结构可行率、候选池公开可行覆盖、选择耗时与失败位置解释机制，不能取代功能终点。规划格式错、非法端点、重复、截断、空池、无解和行为失败均留在预定分母；基础设施缺失另列。候选池有公开可行结构不等于有功能正确结构。

私有评价只作用于已经封存的候选，不能用于结构选择、补候选、重新实现或决定保留哪个重复。局部规则解释器不能兼任独立功能oracle。若行为可绕过固定结构，先停止，不能用端到端通过掩盖归因失效。

只有在强对照下仍观察到可解释的首次功能/成本收益，且额外候选与保护工程没有抵消收益，才值得制定独立主实验。样本量与设计簇应由实际任务差异和拟主张决定，不存在通用的“最低几例就足以SCIE”。
