## 1. 判据与已有证据边界

本轮先读了 [CPPL/HINT 深审](neighbor-deep-review-cppl-hint.md)、[VeriRefine/EQY 深审](neighbor-deep-review-verirefine-eqy.md)、[架构符合性深审](architecture-conformance-gap-review.md)和[方法增量裁决](method-increment-followup.md)。已有停止项不因新名称而重开：程序/模型局部分区、局部连接备选后联合选择、完整父响应的 AST 替换，以及普通局部全域证明，均不作为本轮新候选。

筛选门槛是下列各项同时成立，而非给术语或论文数打分：

1. 当前真实任务里有一项尚未给定、又必须作出的结构决定；其成功标准有公开要求来源。
2. 能说明新增程序处理如何改变 LLM 的设计职责，而不是将完整参考函数交给另一个编译器。
3. 能给出同信息、同约束的具体强替代，并提出两者可能不同的输入，而非仅以“标准工具原则上可表达”作裁决。
4. 收益可被否定，且不依赖不断增加模型调用直到出现所需错误。
5. 最小原型保持在多模块结构范围，不悄悄转成协议、时序或数值算法研究。

成熟后端不构成自动否决：领域义务推导、可检验的交接规则或真实建模负担下降都可能是方法增量。反过来，增加新语法、证据文件或阶段名称，不自行建立这些增量。已有近邻审查已记录 AutoSVA 的领域前端、SV-Gap 的实际意图检查及 RTL-Obliger 的义务推导；本轮不把它们弱化成单纯 lint。

父任务提供的最新开发状态包括：已有原生首次输出与固定父构造均通过，四类原 child 的完整接口域证明没有发现反例。本轮不重跑、不扩其结论，也不继续沿用早期报告中“局部域尚未补全”作为待发明机制的动机。

## 3. 最接近可新增的一步，为什么本轮仍未保留

本轮检查了一个实际可能的剩余步骤：**在第一次 RTL 生成前，传播模块接口与通道约束，将已经唯一确定的签名/绑定冻结，只把真正未决的结构部分交给 LLM。** 以下展开是一次否决测试，不是将已停止的连接方法重新立项。

公开输入应只有：需求中的组件/实例、命名路径、端口方向、参数宽度表达式、payload/valid/ready 所属通道，以及明确的禁止合并约束。程序可归一化端点身份，统一方向/类型/尺寸，传播通道成组关系，固定被输入唯一决定的端口绑定；若有多个不同绑定，输出歧义见证而非编造唯一架构。LLM 再编写剩余模块实现及确实开放的组织，输出多文件 RTL。整个过程不需要生成后的反馈修复。

该处理有工程意义，但当前缺少可区分的新增部分：

- **接口/实例/输入绑定已有具体实现近邻。** 已读 CPPL 深审定位到同期 `_split_instances`、`_instance_ops` 和 deferred 的精确 module/id/args 核验；validator 检查实际端口、宽度、覆盖和连接。后续也有真实 dependency 的 executable patterns。不能将这些已有步骤改叫“边界共识”后视为新增机制。本轮尝试重新取得固定 GitHub 源码，服务返回 cache miss，因此此项沿用既有深审的固定源码阅读记录，不报告本轮重新核源码成功。
- **通道分组后的来源选择已被当前停止项覆盖。** fork 所需 payload/valid/ready 不能拆开，但已有筛选已明确按完整通道分组比较普通匹配；不能再用只按单 wire 同宽匹配的弱基线制造优势。
- **当前资产未给出必须交给 LLM 的新结构歧义。** 在上述 FIR/fork/TD 的固定路径上，约束传播的结果就是现有具体连接。让 LLM 重述这些决定不会形成新方法职责；隐藏它们再让模型猜，也不能凭信息不等称方法获益。

这里的强替代有两层，不能混为一个“万能编译器”论证：

| 同信息替代 | 已实现事实及可比较能力 | 必须保留的限制 |
| --- | --- | --- |
| CPPL 式接口/实例/输入绑定 frontend，加其余父操作的自由生成 | 既有固定源码审查已核构造和核验真实绑定，并非仅理论可表达；覆盖上述冻结/核验接口的核心步骤 | 不声称直接运行过当前任务或可零成本适配；不把宽度推断等同任意事务语义。新方法若声称减少适配成本仍可测，但当前未指出它具体省去哪项步骤。 |
| 当前任务已有的参数化 RTL 构造；以及已有同 child 固定父控制 | 对所列固定结构有可读的逐端口实现，固定父控制也已有父任务报告的实际通过结果 | 这些构造包含人工先验和任务特化工作，不能据此宣称通用同工作量，也不能把它们当 LLM 创新。它们只证明当前选定结构已不需要重新解决。 |

本轮没有取得“相同公开输入下，新增传播规则能保留一个当前 frontend/分组构造不能处理的合法结构，或少写一项确实重复的语义”的例子。因此不是因为编译器可以重做一切而停止，而是尚未识别新增处理本身。

## 4. 区分反例与可反驳收益检查

为避免把无效案例当原型理由，下面列出三种可能的区分及实际裁决：

| 希望区分的输入/反例 | 真正需要的信息 | 当前裁决 |
| --- | --- | --- |
| 两路同宽输入互换，接口依旧合法，计算却错 | 公开的角色/路径/样本与系数绑定 | 具体结构绑定或已做的通道匹配即可处理；不是新核心反例。若普通基线被剥去角色信息，比较不公平。 |
| 子模块存在且正常功能相同，但父层另行重算或只在错模式使用它 | 预先接受的额外模块角色响应 | 这是已有 free-boundary 合同研究；EQY/标准 miter 与严格父构造已有实质对照。不能再次将它算作本轮新增。 |
| 各模块接口合法、局部计算正确，但两路样本来自不同接收事件，或 fork 只送达一端 | 跨周期接收身份、持有与推进规则 | 是一个真实可判的问题，但需要协议/时序研究输入。本文不能自行扩范围来保住新机制。 |

如果未来仍为上述接口传播做工程实现，正确的可反驳收益只能是：同一输入和支持范围下，实际少了多少手工重复签名/绑定、减少多少歧义误处理，并保留全部合法实现。须对相同起点/终点记录适配与审阅过程；新建 JSON 字段数、源码行数、比纯自然语言提示多通过几份或“全自动”标签都不足以替代该证据。**本轮既没有需要测量的新规则，也没有该成本数据，因此不建议为了论文先写一个原型再找收益。**

## 5. 停止条件、可重开条件与改动边界

本轮已经满足的停止条件是：当前公开结构已给定；剩余接口/连接工作与已有具体实现重叠；可产生额外区分的案例需要研究新的行为对象。不是“没有自然错误就证明方案无价值”，也不是“成熟 SAT 足以否定任何领域协议”。本轮没有提供一个可满足全部门槛的新增机制，因而没有可交付的“新程序处理→新 LLM 职责→新结果”原型方案；不能用一个空步骤补齐形式。

重新启动前，最低需要一个真实公开任务，能同时说明：

1. 哪项模块边界、接口或组织决定目前尚未给定，且该决定对使用需求有实际影响；
2. 哪些不同结构仍合法，为什么不能把某个完整参考父函数直接写入输入；
3. 所需新增处理相对于一个具体、可取得的强替代，究竟减少什么人工工作或增加什么有界能力；
4. 一个不依赖模型偶然失败的预定区分案例，以及出现相同结果时立即停止的条件。

这不要求必须发明新 solver，也不要求一开始就扩大模型样本。若真实要求只剩握手、配置快照、数值精度或资源/时序折中，应先讨论是否修改首篇范围和最低工作量，而不是在当前稿件中静默吸收。若仍保持当前任务与完整合同，则更诚实的下一步是完成已有工具/审计证据与论文边界，不继续为“新增机制”增加一个同工同能的层。

本轮预计代码改动边界为 **0**。对原固定任务，不建议新增 DSL、前端、模型轮次、HDL 控制或评价语义；此判断不影响父任务已经授权的写稿和既有证据整合。最新允许的两个结构变体只完成下面的范围设计，没有启动实现或新模型实验。

## 7. 最新范围：两个保持完整顶层函数的结构变体

**授权边界：仅设计变体，不实现、不启动新模型实验。** 下面复用[既有公开组合任务](../../../../artifacts/codex-responsibility-cross-task-20261021-01/public-tasks.md)中 FIR4/TD8 的 normal 数学；不改原文件，不继承旧的固定实例名/边和单一自由切点响应。固定角色响应依赖所选分解，若原封不动继承，就会先排除本轮被允许的不同分解。这里也不宣称保持了旧完整 FPGA 任务的全部时序：它们是既有公开组合子任务的变体；若将来嵌回原状态外壳，外壳必须原样冻结并单独验证。

共同记号：`wrapN(t)` 为模 `2^N` 的 N 位编码；signed 端口按二补码解读；`sat8(t)=min(127,max(-128,t))`；`floor(t/16)` 向负无穷取整。除既有明确 wrap/sat/输出编码外均为精确整数运算。只含已知二值。无新增延迟、面积、DSP 数量、吞吐或能耗目标。

### 7.1 FIR4：加法分组开放，数值函数固定

**公开完整函数与固定字段。** 输入 `x0,x1,x2` 为 signed4，即各在 `[-8,7]`；输出 `filtered` 为 signed7、`edge_value` 为 signed5：

```text
filtered   = wrap7(3*x0 - 2*x1 + x2)
edge_value = signed5(x0 - x2)
```

顶层名、端口、编码、系数和无状态组合语义固定。`edge_value` 的精确整数范围为 `[-15,15]`，在 signed5 内。保留多模块要求：顶层及至少两个非空算术 helper；不规定实例名、必须三次使用同一 MAC 类型、MAC 次序、内部接口数量、子项分组或哪个父层执行最终加法。允许内部宽度/编码选择，但它必须仍实现上述同一个函数，不能将新增窄化当成允许改写函数。

**两个具体合法结构。** 下列局部函数都是从同一公开式子提取，不增加新的数值要求：

| 结构 | 模块与接口 | 组合 |
| --- | --- | --- |
| F-A：现链式分解 | 三个 `MAC(sample:s4, coefficient:s3, accum:s7)→result:s7`；局部为 `wrap7(accum+sample*coefficient)` | `p0=MAC(x0,3,0)`；`p1=MAC(x1,-2,p0)`；`filtered=MAC(x2,1,p1)`；edge 仍由 x0/x2 计算 |
| F-B：两组分解 | `new_term(x0:s4)→p:s7`，`p=wrap7(3*x0)`；`history_terms(x1:s4,x2:s4)→q:s7`，`q=wrap7(-2*x1+x2)`；父层加法 | `filtered=wrap7(p+q)`；edge 仍由 x0/x2 计算 |

合法性可由模运算组合直接分析：`wrap7(wrap7(a)+b)=wrap7(a+b)`，故 F-A/F-B 与公开式相同。此处没有性能优劣目标，不把分组外观称为更优结构。F-B 改变了 helper 的输入集合和局部函数，确实不只是重命名。

**结构合法但功能不等价的 F-X。** 用两个非空 helper：第一个输出 `p=wrap5(3*x0-2*x1)`，第二个输出 `filtered=wrap7(p+x2)`；各端口方向、宽度转换、驱动和图均可合法，edge 仍正确。公开输入 `x0=7,x1=-8,x2=0` 时，正确 filtered 为 `37`，F-X 为 `5`。错误来自既有函数中不存在的过早截位；无需增设资源预算或新算术义务。该输入是数学分析反例，本轮没有运行它。

**直接强基线。** 在相同函数输入下，固定采用 F-A 的现成参数化构造已能给出合法多模块输出，不必先比较所有结构。若要求支持 F-B，按公开二项子图提取其自由输入并生成两个函数即可；这是 AST 分组/普通 outlining。当前未实现这一 adapter，不能声称已测同工作量；但本变体也没有给拟议机制另一项不可归约于该过程的处理职责。手写 F-B 后让后端编译，只能作为资格控制。

### 7.2 TD8：在精确返回或饱和误差处切分

**公开完整函数与固定字段。** `reward,next_value,value` 为 signed8；`gamma,alpha` 为 unsigned8。输出 `return_value` 为 signed17，`td_error,updated_value` 为 signed8：

```text
R = reward + floor(gamma * next_value / 16)
E = sat8(R - value)
D = sat8(floor(alpha * E / 16))
U = sat8(value + D)
return_value = R
td_error = E
updated_value = U
```

顶层名/端口、unsigned 系数、负数 floor、三处 sat 的位置和输出编码固定。开放 helper 个数/名称、R 或 E 所在的模块边界、helper 的输入集合与多输出接口；保持顶层及至少两个非空算术 helper。禁止引入状态/协议目标。旧 `u_return` 的单一自由替换合同不继承到新结构，旧 profile 和旧结果继续保持原义。

**两个具体合法结构。**

| 结构 | 模块与接口 | 组合 |
| --- | --- | --- |
| T-A：R 边界 | `return_core(reward:s8,next:s8,gamma:u8)→R:s17`；`update_core(R:s17,value:s8,alpha:u8)→(E:s8,U:s8)` | 第一模块算原 R；第二模块按原 E/D/U 计算；顶层直接暴露 R/E/U |
| T-B：E 边界 | `error_core(reward:s8,next:s8,gamma:u8,value:s8)→(R:s17,E:s8)`；`apply_core(E:s8,value:s8,alpha:u8)→U:s8` | 第一模块算原 R/E；第二模块算原 D/U；顶层直接暴露 R/E/U |

T-B 把 value 移入前一个 helper，并以 E 作为后段数值接口；保留 R 作为该 helper 的另一输出。这是不同合法接口，不只是更换实例标签。两者的函数等价由原命名子式代入即可分析，不需要为合法化而移动 sat 边界，也不需要据可达范围缩小合同。

**结构合法但功能不等价的 T-X。** 保留 T-B 的模块图和端口，前段 R/E 正确；后段把 D 的 sat 移到最终加法之后，写成 `U'=sat8(value+floor(alpha*E/16))`。所有连接/端口/驱动仍可合法。公开输入 `reward=127,next_value=0,gamma=0,value=-128,alpha=255` 时：R=127，E=127，`floor(alpha*E/16)=2024`；正确 D=127、U=−1，错误 U'=127。它没有改变顶层输入或增加数学需求，单纯违反原有嵌套 sat。该输入同样只作静态分析，未执行。

**直接强基线。** 现成 T-A 构造或相同原函数 AST 的 R 切分，已经能返回一个被允许的答案。T-B 只是在同 AST 上将 R/E 子图 outline 为一个双输出 helper，再将 D/U 子图 outline；端口取各子图的自由变量及输出。一个 compiler 不需要猜用户偏好，因为两者都满足当前全部目标且没有结构质量排序。将这种子图提取、接口 closure 或 exact-sat 节点保留改名，不能构成新的领域处理。

## 8. 变体裁决：合法结构空间扩大，但目前仍只是资格题

**问题发生了实质变化：** 新变体不再由固定模块名和链唯一决定答案，F-B/T-B 也是可接受实现。因此 §2 的“结构已给定”不能直接当作新变体的停止理由。现在的停止理由是：公开全函数已给出完整运算分解，且没有约束迫使系统选择某种更难的分解；现有合法构造本身仍属于允许答案，任何选择合法结构的系统都可固定返回它。

本轮新增核对了 CIRCT 官方 [HW dialect](https://circt.llvm.org/docs/Dialects/HW/) 的 `hw.module`/`hw.instance`，以及 [Comb dialect](https://circt.llvm.org/docs/Dialects/Comb/) 的算术、比较、mux、位提取与 signed shift。前者实际定义了模块体、接口和匹配的实例端口；后者提供精确位向量组合算子的表示。这是已实现的 typed hierarchy/operation 表示，不是仅说“通用工具或许能表示”。本轮没有运行 CIRCT，也未实现这两个 profile 的 frontend；不声称它从裸自然语言自动完成分组或证明本变体。sat/floor 必须明确降为足够宽的符号运算、比较/mux和算术移位，不能将 `divs` 与 floor 不经核对地等同。

同信息最强可实现基线可具体分成两种，评价时必须分别命名：

1. **单一合法结构直接构造。** 同样拿到完整公开函数、顶层及多模块要求，固定选 F-A/T-A，复用已存在构造或其组合子任务抽取。它不覆盖全部合法组织，但当前任务并未要求覆盖全部组织。它足以挑战“LLM 是生成正确结构不可省的部分”。其先前人工模板工作要记入成本，不能藏去。
2. **AST 子图提取加 typed IR 发射。** 同样拿到完整 AST，固定的通用切分规则选择非平凡子图，输入取自由变量、输出取跨边界使用项；保留已有 wrap/sat 节点，产生模块及实例并交现有后端。对 F-B/T-B，此规则的具体提取已在 §7 写全。这条 frontend 尚未在本轮实现，不能报告实测自动化成本或把计划当复现；它说明拟议工作若只有同一子图提取，就必须和普通 outlining 比较，而非和只有自然语言的弱提示比较。

**LLM 职责核对。** 目前 LLM 可以选 F-A/F-B 或 T-A/T-B，命名接口并编写 RTL；但这是一项可替换职责。完整 AST、原运算编码和任意合法分解即可经程序得到同一目标；没有证据说明模型必须处理一种 compiler 输入中缺失、又由用户已明确给出的结构意义。若让 LLM 仅把完整式子换成 IR，它充当前端翻译器；若让它挑一个分组，其选择没有现行目标可排序。两者可作首次生成实验条件，均未自动产生新机制。

**本轮没有保留新的交接/推导核心。** 下列可做内容仍不足以越过这一门槛：从所选 cut 导出局部函数、计算端口 closure、传播位宽或范围、检查 liveness、保持 sat 节点、对不同分解做 miter。它们可以构成有用的实现与资格套件，但当前没有另一项规则或保证，能将其区别于已停止的普通 partition/编译/验证流程。

若将来出现真实使用需求，要求在多个合法分解之间兑现一种**尚未被全 AST 固定、且有独立动机的接口/替换承诺**，可以重新评估；仍需先给相同信息的直接构造/IR 基线、合法结构与反例，以及可反驳的适配负担收益。不能为打破这里的零差异，临时加入面积、时延或故障模型。本轮建议将 F-A/F-B/F-X、T-A/T-B/T-X 记录为六个预定静态资格设计，不启动任何模型、HDL或实现工作；它们不进入旧 profile 的分母，不变更旧结果，也不作为方法创新已成立的证据。

## 9. 窄候选专审：在饱和信息瓶颈处选择可验证接口

本节按新增委托具体审查一个剩余机制，不预先保留它：**生成首次 RTL 之前，按量化/饱和等多对一语义节点选择模块边界，使下游证明依赖较窄摘要，而不是宽的上游接口。** 目标若成立，是改变证明分解的成本，不是提高本来已全通过的顶层功能率。本节不修改指标、不启动实验，也不将计划中的 proof-cost 研究写成结果。

### 9.1 可执行步骤与真实 TD 例子

公开输入只取 §7.2 的完整 AST、数值类型与全部顶层输出，不再增加参考实现、隐藏向量或资源目标。拟议程序步骤可以具体写成：

1. 定位 AST 中显式的 lossy 节点，例如原有 `E=sat8(R-value)`；保留其原函数，不根据某次证明失败移动 sat。
2. 对该节点后的输出计算自由变量 closure：U 需要 E、value、alpha；顶层仍要 R 和 E。把这些真实旁路量保留在接口，不能假称 U 只需要 E。
3. 选择 E 作为 8 位跨模块结果；从同一 AST 抽取该点上下游的局部函数；确定性生成实际实例、参数和端口连接。
4. 固定这些局部义务后，LLM 一次性编写模块体；逐模块功能证明与真实连接核验在生成后执行，不能将其反例回送修复。程序亦可直接编译这些模块体，必须列作强基线。

具体得到三个 helper，而非原来的两个：

| helper | 完整接口与数学 | 输入位数，仅为形式维度 |
| --- | --- | --- |
| return | `(reward:s8,next:s8,gamma:u8)→R:s17`；原 R 公式 | 24 |
| sat_error | `(R:s17,value:s8)→E:s8`；`E=sat8(R-value)`，减法必须先精确 | 25 |
| alpha_update | `(E:s8,value:s8,alpha:u8)→U:s8`；原 D/U 公式 | 24 |

原 update 接口为 R17/value8/alpha8，共 33 输入位，输出 E/U。新结构将该义务变成 25 位和 24 位两个完整局部域；不靠假设 R 可达、不限制 E 值域，也不改变顶层 R/E/U。对完整 signed17 R，sat_error 的减法仍需精确覆盖 18 位，不能借新分解缩掉这项既有要求。

完整域局部正确性加实际接线可以组合推出顶层普通功能：return 给原 R，sat_error 给原 E，alpha_update 给原 U，顶层的三输出连接保持一致。这个组合推论本身是通常的函数组合，不是新证明规则。它也不证明父层没有冗余重算；若要禁止重算，仍需另行接受的结构/角色义务，不能把功能组合定理偷偷升级。

### 9.2 什么可能有收益，什么目前未证

**预测：** 显式 E8 边界可能让某些证明后端较快完成独立局部 miter，或使失败较易定位。这个预测可被反驳，且没有理由从输入位数直接认定成立：

- 原 update 的内部本来先得到 E8，再做 alpha×E；将节点移到端口没有创造新的 8 位数值压缩。优化后的求解器已可能利用相同结构。
- 输入数由 33 变成 25/24，没有给出 SAT 复杂度定理；位宽、乘法编码、饱和分支及锥共享都可能主导成本。两个局部域也不能按其枚举大小相加后冒充求解工作量。
- 新增一个模块、局部 reference/miter、端口连接和证明状态；若更多边界导致设置、编译或组合开销增加，可能抵消甚至超过求解收益。
- 当前四类 16 个原 child 的完整域证明已经全部 proved。尚未给出当前尺度有未完成或昂贵证明的原始成本证据；不能仅凭 33 位听起来较大就设定“难题已解决”。

FIR4 的 wrap7 不能提供同样的新瓶颈：原链的跨级结果本就为 7 位，且模加法容许在现位置组合；再按 wrap 节点切开没有较窄的后段摘要。不能为扩充样例再加一个原函数中不存在的量化点。

### 9.3 同信息强基线与新机制缺口

| 强基线 | 在本例中的具体处理 | 与窄候选的实际差别 |
| --- | --- | --- |
| 直接数学编译 | 同完整 AST，固定生成原 R/update 或新的三 helper，再按显式数值节点 lowering | 当前无需 LLM 猜函数或接口；若声称首次正确生成必需 LLM，此基线直接挑战它。不能隐藏原模板/adapter的人工作业。 |
| 普通按 sat 节点 outlining | 遍历同 AST，选第一处 E 的 sat，端口取自由变量与跨界输出，发射上表完全相同的三个 helper 与局部义务 | **在此例没有差别。** “多对一信息瓶颈”只是给该 sat 的既有语义命名；无需新增学习、范围算法或量化推导就能选中并得到同一 proof split。 |
| 已有组合验证分区 | 在原 update 的 E 节点建立对应切点，先证明 E，再以独立的 E/value/alpha 证明 U；确保不把 R 上游关系错误恢复到后段 | 能得到同样数学分解；并不声称默认工具会自动选中该点。公平对照给相同 E 节点身份，或同一 AST 的自动 sat 标记，再比较手工步骤与运行成本。 |

最后一项的依据是既有 EQY 源码深审已核实际切点、独立 PI、分区 miter、bind/amend 对域的影响；本轮没有运行该配置，也不声称任何默认配置已复现此例。第二项更加直接：候选与普通策略吃同 AST、选同节点、生成同接口、同局部域和同后端目标，**两者在机制层面已经相同**。若要保留新核心，必须说出哪项新增选择/交接规则将它们分开，而非只和按代码行数切分比较。

LLM 可执行剩余模块的 RTL 翻译，但在此资产上不是不可省部分：程序已具备每个局部的完整 AST 和所有边界。让 LLM 再选择切点，仍须与不调用模型的 sat-node 策略比较；让 LLM 编写候选实现，可以研究它对额外模块/接口的服从性，却不能把确定性 outlining 的贡献算成新的 LLM 结构推理。

### 9.4 可区分反例、停止条件与判定

§7.2 的 T-X 是合格的语义负控制：两个合法图中缺失 D 的 sat 会改变 U；精确编译、普通 sat outlining 和该窄候选都应拒绝它。**它不能区分三种方法。** 同样，若错误丢掉 alpha_update 的 value 旁路，普通自由变量 closure 已可检出；这不是新的信息瓶颈推导能力。

真正能区分候选的输入应满足：显式 sat 切分与普通已有组合验证不能在相同信息/设置代价获得其接口或证明分解，而新增程序规则可以。当前 TD 没有这种输入：E 由一个具名的原 AST sat 节点直接给出。添加“所有 loss 节点都切开”或“优先最窄节点”只是工程启发式，且需要衡量额外分区开销；本轮没有新的语义规则或成本保证来支持将其独立命名为方法核心。

**判定：不保留为新增核心，可作为可验证生成的工程策略/资格对照。** 若以后已有正式需求与原始日志证明分解成本确为瓶颈，可以先做同 AST 的原整体证明、sat-node outlining 与已有 partition 的限定成本比较；那是后续需明确授权的运行设计，不是当前已启动工作。只要 sat-node 基线产生相同接口和义务，或完整 AST 直接编译已足够，而候选未减少另一项可核实的设置/交接工作，就应停止其独立方法主张。原生功能全过不反驳潜在 proof-cost 收益，但也不为它提供任何成本证据。
