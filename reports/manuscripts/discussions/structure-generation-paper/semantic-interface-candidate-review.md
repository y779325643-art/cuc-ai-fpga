# FIR 跨输出语义接口候选：有实质重组，仍由普通线性优化覆盖

日期：2026-10-21。范围：有界静态设计审查；允许轻量 Python 精确数学核对，不调用被测模型、不运行 HDL/SAT、不改旧稿或既有 profile。除本报告外，仅新增独占的[静态资格 artifact](../../../../artifacts/responsibility-semantic-interface-static-20261021-01/README.md)。检查时为 `develop`，HEAD `e20dfd2ce46c5690767e30cb629fb5c58aff073a`；未操作 Git staging、commit 或 remote。

**判断：这是比字面 AST 分区更强、可作语义接口资格题的真实重组，但本例没有展示新增的代数或接口选择能力。** 同信息的非 LLM 小系数线性基搜索已经在本轮实际找到了相同接口；跨变量、跨输出的移位加减优化也有直接原始文献。不能只用“普通 compiler 原则上也行”否定它，本报告给出具体算法、实际搜索结果与成本边界。系统级义务交接、可靠性和工作量假设仍可研究，所缺证据与公平对照见 §7；本例的零增量不等于论文总体无创新。

## 1. 公开数学、来源与新增决定

来源是[公开组合 FIR4 normal 函数](../../../../artifacts/codex-responsibility-cross-task-20261021-01/public-tasks.md)及[先前两结构变体](independent-method-core-review.md#71-fir4加法分组开放数值函数固定)。旧 streaming FIR 的来源是 [`datapath.py` 的 `fir_filter_rtl_files`](../../../../agent/src/sr2fpga_agent/task_families/datapath.py#L2159)。本轮不继承旧固定三 MAC 链或 `u_prev` 自由边界响应；也不声称复现整个原 FPGA 时序任务。

输入 `x0,x1,x2` 是 signed4，均在 `[-8,7]`；顶层必须输出：

```text
f = wrap7(3*x0 - 2*x1 + x2)       # signed7
e = signed5(x0 - x2)              # signed5
```

除既有输出编码外使用精确整数；`wrap7` 为模 128 后按二补码解读。模块分解、内部接口及名字开放，顶层功能、编码、无状态组合语义固定。没有面积、延迟、DSP 数量、吞吐或功耗目标。

候选不再逐输出划 AST：以已经必须输出的 e 为一个接口坐标，另构造 `t=2*x0-x1`，父层 `f=wrap7(2*t-e)`。矩阵形式明确为：

```text
[e]   [1  0 -1] [x0]       [f_integer]   [-1  2] [e]
[t] = [2 -1  0] [x1]       [e        ] = [ 1  0] [t]
                 [x2]
```

相乘得到 f 的系数 `(3,-2,1)` 和 e 的系数 `(1,0,-1)`。这确实引入了原 AST 没有的 t，并复用了另一输出；不能把它说成“只是原子图换个名字”。同时，这正是多输入、多输出整数线性变换的因子化问题，不能只拿单变量 MCM 或不做代数重写的 AST outlining 作唯一强基线。

## 2. 数学与位宽资格：本轮实际执行结果

先执行纯 Python 标准库内存枚举，再按主审要求保存相同算法并重跑，捕获 stdout；两次没有扩任务或候选空间。读取的数学即上节公开函数，没有导入仓库生成器或评价器。实际[脚本](../../../../artifacts/responsibility-semantic-interface-static-20261021-01/verify_semantic_interface.py)、[输出](../../../../artifacts/responsibility-semantic-interface-static-20261021-01/results.json)和[操作/去重说明](../../../../artifacts/responsibility-semantic-interface-static-20261021-01/README.md)均独立保留。结果如下：

| 数学检查 | 实际分母/结果 |
| --- | --- |
| 正常三 signed4 输入，比较原 f 与 `wrap7(2*t-e)`，并比较原 e | 4096 个输入，f 差异 0；e 是同一精确表达式 |
| e 的精确范围 | `[-15,15]`，signed5 足够 |
| t 的精确范围 | `[-23,22]`，signed6 足够，signed5 不足 |
| 正常 f 的精确范围 | `[-46,44]`，signed7 足够 |
| 任意独立 e5/t6 的父接口 | 2048 对；`wrap7(2*t-e)` 与 `wrap7(wrap7(2*t)-e)` 差异 0 |

独立接口域是 `e∈[-16,15]`、`t∈[-32,31]`，包含正常 producer 不会发出的值；局部父函数仍可定义为 `wrap7(2*t-e)`。此域的精确整数 `2*t-e` 范围为 `[-79,78]`，若父体选择精确整数路径，应先用足够宽度再编码；选择 7 位模运算路径也可以，但要先正确扩展 t/e，并保证每步都是同一模 128 运算。这里没有 HDL 执行，不能据此认定某条 Verilog 表达式的具体 context sizing 正确。

同时枚举了三种**明确定义的错误数学实现**，用于保留位宽边界，而非声称发现模型或工具缺陷：

| 错误实现 | 4096 输入中的差异数 | 一个公开反例 |
| --- | --- | --- |
| `wrap7(2*wrap5(t)-e)` | 512 | `(-8,1,-8)`：t=−17、e=0；原 f=−34，错值 30 |
| `wrap7(wrap6(2*t)-e)` | 512 | 同一输入；过早 6 位 shift 结果编码产生 30 |
| e5 按 unsigned 零扩展后减去 | 1920 | `(-8,-8,-7)`：t=−8、e=−1；原 f=−15，错值 −47 |

这些控制区分了正确重组与错误编码。精确线性编译、sound e-graph/adder-graph 和拟议新方法均应处理它们；它们不是对强非 LLM 基线的优势反例。

## 3. 同信息非 LLM 基线：本轮已实际搜索到相同 t

输入只给两个输出的系数：`F=(3,-2,1)`、必需输出 `E=(1,0,-1)`；**没有把 t 作为搜索输入，没有把目标接口放进候选列表。** 这与拟议语义规划者拿到完整输出函数的信息边界相同。轻量基线如下：

1. 将输入变量视为三个单位向量。
2. 枚举所有 `±2^k*x_i ±2^l*x_j`，`i,j∈{0,1,2}`、`k,l∈{0,1,2}`；允许 i=j，去重得到 151 个一加减线性向量。
3. 对每个候选 T，枚举 `p,q∈{−4,−2,−1,1,2,4}`，检查精确系数等式 `F=p*T+q*E`。
4. 本轮只收集并输出成立的 4 个解；仅对委托指定的 `t=2*x0-x1` 计算完整输入域范围。未逐解计算范围、编码成本或多目标成本，也未构造 Pareto 集合。后续若实现成本选择，可增加这些处理，但不能将其记作本轮已执行能力，更不能默认“少一个 add 就物理更优”。

本轮第 3 步找到 4 个解：

| T | p | q |
| --- | --- | --- |
| `2*x0-x1` | 2 | −1 |
| `−2*x0+x1` | −2 | −1 |
| `4*x0−2*x1` | 1 | −1 |
| `−4*x0+2*x1` | −1 | −1 |

它们为符号/尺度变体，第一项就是候选接口；6 位 t 比 7 位 `2*t` 的接口更窄。搜索检查的是公开整数系数恒等式，随后用 §2 全输入核对控制有限宽编码。

这已经是本例的具体停止证据：一个不调用模型、规模很小、没有植入 t 的算法发现了相同新接口。它不是作者框架复现，也不是完成 RTL emitter；本轮只执行数学层。若拟议新方法仍从这些完整 AST/系数推导接口再让模型写 RTL，其接口发现步骤没有超出这个基线；直接发射三个加减步骤也可省去模型翻译。

另作了一个有界网络检查：先生成 E，再从 `{x0,x1,x2,E}` 的移位项用一加减生成 F，shift 范围 0–3，匹配数为 0。一个更一般的本例论证是：两操作网络中，含三种变量的 F 不可能由第一步两个 primary 移位项得到，所以第一步必须产生 E；第二步若使用 E 和 x1，x0/x2 系数必互为相反数，与 3/1 不符；使用 E 和 x0/x2 则无法产生 x1。故在“二元移位加减、精确整数、输出由节点/移位直接取得”的特定语法内至少需 3 操作，当前网络达到 3。**这不是任意位级电路、任意乘法器或 FPGA 的最优性证明。**

复算本轮关键搜索无需外部包：

```python
from itertools import product
X = [(1, 0, 0), (0, 1, 0), (0, 0, 1)]
E, F = (1, 0, -1), (3, -2, 1)
T = {
    tuple(s*(1 << k)*X[i][n] + z*(1 << l)*X[j][n]
          for n in range(3))
    for i, j, k, l, s, z in product(
        range(3), range(3), range(3), range(3), (-1, 1), (-1, 1))
}
solutions = [(t, p, q) for t in T
             for p, q in product((-4, -2, -1, 1, 2, 4), repeat=2)
             if tuple(p*t[n] + q*E[n] for n in range(3)) == F]
assert len(T) == 151 and len(solutions) == 4
assert ((2, -1, 0), 2, -1) in solutions

def wrap(n, v):
    u = v % (1 << n)
    return u - (1 << n) if u >= (1 << (n-1)) else u

inputs = list(product(range(-8, 8), repeat=3))
assert len(inputs) == 4096
assert all(wrap(7, 3*a-2*b+c) == wrap(7, 2*(2*a-b)-(a-c))
           for a, b, c in inputs)
```

## 4. 已有原始方法：应比较多变量线性计算优化

本轮读了作者原件：Hosangadi、Fallah、Kastner 的 [ASAP 2004 论文](https://cseweb.ucsd.edu/~kastner/papers/asap04-cse_mult_vars_linear_DSP.pdf)，重点 §1、Fig.1、§3–4；以及 [2007 期刊论文](https://cseweb.ucsd.edu/~kastner/papers/vlsi_sp07-alg_methods_linear_systems.pdf)，重点 §1–3、Fig.3–4 及多变量多项式/kernels/提取方法。前者以多个输出的常矩阵乘输入向量为问题，表示移位带符号的多变量项并提取共享计算；后者明确讨论代数关联/分配、矩阵拆分与多变量共享。它们直接覆盖“原 AST 未显式出现的跨输出线性中间项”，而不只处理一变量的常数乘法。

对本例，一个不依赖 LLM 的具体代数路线甚至比上节搜索更简单：用 `3*x0=4*x0−x0` 展开 f，得到 `f=4*x0−2*x1−(x0−x2)`；复用必需 e 后，对余项提取公共 2，得到 `f=2*(2*x0−x1)−e`。这与 signed-digit 展开、跨变量共享、shift 因子提取的既有范围直接相交。**本轮没有运行作者算法，不声称其具体版本必然在该实例输出同图；“本例算法能找到”的实际证据来自 §3 独立执行的小基线。**

e-graph 也应作为强备选：保留精确 wrap/整数边界，允许结合、分配、signed-digit 常数改写与跨输出共享，按完整网络成本联合提取。不能只对每个输出独立最小化树成本后把共享失败算成 e-graph 的先天缺陷；也不能把一个通用 e-graph 的可表达性当已测成功。已有[方法增量审查](method-increment-followup.md#23-近邻和同信息强替代)只核过 egg 的分析/条件重写与提取，这一具体多输出适配本轮未实现。

## 5. 成本口径：三 add/sub 不是 PPA 或接口优势

仅为静态核对，定义一个常用算术语法成本：移位与接线不计 add/sub 数，常系数乘法先展开为移位加减，二元 add/sub 各记 1。不把该成本注册成新的任务目标。

| 实现 | 明确的加减步骤 | 静态 add/sub 数 |
| --- | --- | --- |
| F-B 的直接分别实现 | p=2*x0+x0；q=x2−2*x1；f=p+q；e=x0−x2 | 4 |
| 当前跨输出重组 | e=x0−x2；t=2*x0−x1；f=2*t−e | 3 |
| 最强联合线性优化 | 可以得到当前同一 3 步图 | 本轮小基线为 3 |

不能把首行当全体 compiler 的最优输出。综合若展开或跨模块优化，原写法也可能恢复同一网络；强保层次、扇出、位宽、布线或目标器件都会改变物理成本。没有 HDL/综合结果，因此没有面积、时延、功耗、资源或证明时间结论。

按**两个 producer helper 的输入端口位数加输出端口位数**统计：

| 接口方案 | helper 输入合计 | helper 输出合计 | 合计 |
| --- | --- | --- | --- |
| F-B：p7/q7 | x0 的 4 位 + x1/x2 的 8 位 =12 | 7+7=14 | 26 |
| F-B：允许按精确范围收窄为 p6/q6 | 12 | 6+6=12 | 24 |
| e5/t6 新接口 | 两 helper 各取两路 signed4，8+8=16 | 5+6=11 | 27 |

该口径计入重复进入 helper 的 x0，没有计顶层固定端口，也不把 raw-input 的父层本地使用重复记为 helper 端口。新接口的 helper 输出较窄，但 helper 输入扇出增加；总接口量不占优。其他 cut/port 口径必须重新完整列出，不能只取输出 11 对 14 宣称通信减少。

新父层不再需要 raw x0/x2 来算 e，这可减少父层数学输入集合，但普通线性基与直接编译同样得到它。若要主张证明成本收益，还须比较每个 producer 的局部证明、父体/连接、切点适配和编译总成本；目前没有这些运行，也没有原证明难度证据。

## 6. 真正可区分什么、不能区分什么

1. **能区分纯字面分区。** 原 AST 不包含 t，且不会把 e 的表达式重新用于 f；只保原子图的 splitter 不能产生本接口。这证明应加入“跨输出代数重组”资格，不证明该机制新颖。
2. **不能区分 sound 小系数线性基/adder-graph。** 当前同信息基线已找到同一 t，并能用同一精确数学导出局部函数与父连接。不存在本例中的能力优势反例；不应为保留候选把这些已成功基线换成单变量 MCM 或只按源码大小分区。
3. **位宽负控制只能检验可信实现。** §2 的 t5、shift6、e 零扩展差异是真实数学错误，但它们挑战的是所有方案的编码正确性；不能只给基线错误类型规则再宣布新方法胜出。
4. **“另一输出已经必需”不是未知信息。** e 本来就在完整输出向量中，非 LLM 优化器应同时读取它；若基线只优化 f，比较的信息不等。模块化交接仍可能有软件贡献，但必须指出它比 §3 的“系数搜索→局部函数→签名/接线”多完成哪项可核实工作。

这项候选最有信息量的下一次裁决不是追加模型生成，而是先回答：在相同完整公开函数和允许结构下，是否存在当前小基线/标准联合线性优化没有处理、而新增交接规则确实处理的具体要求？当前没有该要求或反例。无须引入新的非线性、协议、资源预算来制造它。

## 7. 停止条件、系统级待检假设与交付结论

**当前停止的是新增代数/接口选择能力的宽主张：** 同信息小基线已经实际构造相同接口，局部数学及接线可直接编译，名义接口总量也没有降低。该重组可作为跨输出整数线性电路优化策略及新的非字面结构资格题；本例不能单独证成新的选择算法。使用成熟原语或被非 LLM 搜索解出，不自动否定系统/协议贡献。

尚可研究的系统假设及缺失证据应具体列明：

| 待检系统假设 | 同信息强对照 | 目前缺什么 |
| --- | --- | --- |
| 一次给出顶层函数和所选接口，即可靠派生局部数学、重组关系与实际端口交接，减少第二份手写函数 | 标准联合线性优化或本轮基搜索，加普通 outlining/typed emitter/标准 miter 适配；都获得同一函数、候选空间和编码规则 | 哪些语义/映射字段确实不再人工填写；实际适配、审阅与 unknown 原因记录；相同支持范围下的工作量比较 |
| 同一接口承诺能接受正常合法的内部表达、符号/尺度编码变体，并把不支持映射与真实违反区分开 | 标准 typed binding、明确编码转换与普通 wrapper/miter；不能故意漏给合法编码信息 | 生成前同意的合法实现族、独立资格控制、真实绑定证据与分类一致性；本轮只有整数式，没有 RTL 交接实现 |
| 发现的新接口能改善首次生成的可验证性或实际使用负担 | 同信息直接数学编译与相同接口下的普通生成/验证流程；包含额外模块及所有局部证明开销 | 冻结范围的真实使用/工具成本证据；不能用正常功能全过或原子 add 数代替 |

若其中一项被实现并与强对照得到可复核差异，可以支持有边界的协议/软件方法贡献；那种贡献来自具体交接保证或省工，而非 e/t 恒等式本身。当前没有这些实证，本文不判该系统贡献已经成立，也不判其不可能。SCI 贡献不以“LLM 数学上不可替代”为必要条件。

允许重新评估的条件应是具体而非术语性的：新增的领域交接规则在相同函数、结构约束与预算下，可靠接受另一种合法接口、拒绝标准流程无法正确分类的情况，或少做可记录的人工义务/映射工作；强基线必须保留多输出、符号/位宽与同等候选空间。若差异仍仅是由谁发现同一线性恒等式，或把通用移位加减因子化改名为“语义接口”，继续停止。

LLM 在当前输入上没有被证明承担独有的数学发现：它可以提出 t 或翻译 RTL，但 §3 不调用模型即可完成接口发现，typed emitter 又可替代翻译。这限定应如何分配方法贡献，不决定系统论文是否有价值。若未来改为裸自然语言取数学，还须面对已有语义前端/AST 生成近邻，不能将本轮线性优化的能力算成新的自然语言推理。

本轮完成的是数学正确性与强替代裁决：4096 正常输入和 2048 自由父接口的有限域纯数学穷举、实际小基搜索、两项作者原文核查、明确成本及反例口径。**未生成候选 RTL、未运行模型/HDL/SAT/综合、未修改旧 profile/稿件/评分，也没有测量 PPA 或 proof-cost。** 这些数学枚举不能代替未来真实 RTL 编码和工具链资格。
