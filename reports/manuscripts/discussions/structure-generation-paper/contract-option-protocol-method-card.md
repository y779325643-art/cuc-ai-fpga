# 候选方法卡：局部计算合同备选、组合认证与首次RTL实现

日期：2026-10-21。这是对用户已允许的模块分解/接口变体的具体设计，尚未作为正式论文方法采纳。前置选择器已实现并通过2入口、39项限定检查与独立源码审计；[同信息零模型编译](direct-math-compiler-baseline-review.md)也已完成1发射+4HDL资格，FIR全域和TD预定子域均通过。当前不再扩大本候选的完整LLM链或模型pilot；真实协议收益与创新仍未成立。保留本卡供复核，不增加PPA、周期、输入环境或禁止重算要求，也不修改现行研究定义。

## 1. 可检验的问题与当前机制

同样位宽的接口可以传递不同数学量。FIR中两个helper各承担多少`x1`贡献必须协调；TD中桥值表示误差E还是缩放后增量D，必须与下游计算一致。[两例定义](local-option-variant-feasibility.md)保持原normal函数及全部顶层输出，并保留合法重算。它们已经有数学资格，尚无真实模型候选池。

拟议协议让模型一次提出少量**可执行的局部数学合同**，程序组合后认证其合成函数，选一个方案固定，再让模型实现该方案。此处的选择对象已经超出旧“只选连接来源”：它选择局部计算责任及接口含义。合同正确性和生成body兑现合同分别验证，不能相互替代。

| 阶段 | 输入与处理 | 输出／保证边界 |
| --- | --- | --- |
| 公共需求 | 可信完整normal函数、输入输出编码、允许分解；调用方提供且冻结 | 与候选内容分离的可信目标；原始自然语言转成此目标的人工/模型工作必须计入，当前未自动解决 |
| 一次规划 | 模型提出有限模块合同、接口和成组局部备选，使用封闭数学语言 | 只有声明；不信任自报compatible、角色标签或自供测试 |
| 程序协调 | 检查绑定、类型、范围及DAG，展开组合；在支持规则内认证与可信目标相等；真实数学反例可否定特定组合，其他保留UNKNOWN | 全部组合记录、所选合同和接线；无解只限本池。普通乘积枚举是等能强控制 |
| 固定与一次实现 | 程序发射选中结构，模型只填写允许行为；原始需求与局部数学信息按同规则供给各组 | 实际RTL及局部遵约结果；本阶段尚未实现，不能以JSON计划代替 |
| 独立终评 | 在封存首次项目上验证实际结构、局部数学与普通功能；不回馈本次生成 | 全部尝试的最终结果及总成本；失败／UNKNOWN保留 |

本轮前置原型只接收手工可信目标及手工候选，输出选中计划。完整局部语义不是程序从裸自然语言自动推导的；这是明确的输入成本和适用范围。尚不能声称新接口会自动减少人工工作。

## 2. 最小支持范围与声称尺度

先使用固定、无状态、位精确的FIR/TD组合函数；同一决策组内ABI固定。整数运算精确，显式保留floor、sat、wrap。范围检查可以拒绝不能用声明输出表示的摘要；不把输出位宽偷偷当截位操作。程序可以以线性归一化／相同精确AST认证有限情形；规范形式不同不等于功能错误，缺反例与证书时返回UNKNOWN。

FIR的两组各两个选项产生四种组合；TD的两种producer与三种consumer含合法C_R重算，产生六种组合。D桥接是本轮新设计，不继承旧固定profile或旧生成结果。[数学资格](../../../../artifacts/responsibility-local-semantic-options-static-20261021-01/plan.md)只执行FIR四组合全域与TD两个consumer的四组合子域；C_R由静态代入分析，不能写成已运行六组合RTL验证。

## 3. 必须面对的强对照与近邻

[Parsel](neighbor-deep-review-parsel-local-options.md)已经生成局部body池并实际搜索组合；[SynthTL](neighbor-deep-review-synthtl.md)已经对局部规格/分解备选作人工确认和机械组合；[Stepwise](neighbor-deep-review-formalrtl-refinement.md)有实质语义组合规则；[RTLScout/Spire](neighbor-deep-review-rtlscout-options.md)已有局部架构选择、库组合及RTL发射。因此不能把局部候选、数学摘要、组合认证或先规划后实现单独称为首创。

| 要回答的问题 | 强控制 |
| --- | --- |
| 程序确有跨局部协调对象吗 | 相同缓存池的类型过滤、独立首选与标准完整乘积认证；只测声明／数学兼容 |
| 因子化输出本身划算吗 | 同总规划/行为预算的压缩完整方案输出；共享选项字典、索引表达及公开检查能力 |
| 模型提出这些选项值得吗 | 同一可信normal AST的固定合法构造与编译；现任务允许始终选P0/Q0及E/apply或重算 |
| 是否改善首次工程 | 各组最多一次行为；实际结构/局部遵约和普通功能终点；全部规划、失败、程序与行为成本 |

[公平性审计](local-option-protocol-fairness-review.md)给出同池闭包与独立端到端竞争的区别。同池完整闭包与本选择器得到相同方案是正确性控制，不是方法失败；该等价也不能被隐藏为所谓新搜索收益。直接构造可能省去全部规划甚至行为调用，必须如实保留。

## 4. 唯一仍待检验的系统假设

在相同公开信息和预算内，前置局部合同池的表示与组合，能否比压缩完整合同方案及直接构造，提高首次完整结果，或在事前非劣标准下减少完整成本？这包含提前筛选的代价：选择时尚无真实body，声明的数学合法性可能无法转为一次可用RTL。

正式比较前须选定并冻结主判据、允许的非劣界值、UNKNOWN/失败处理与成本边界；当前卡未确定这些数值，不构成效果实验配置。不能看过结果后在“提高成功率”和“降低成本”之间择优更换成功定义。

停止条件是：真实模型没有有用的互补选项；摘要／body不可靠；普通完整规划或直接构造同效且无成本/适配收益；只能靠额外提示、私有反馈、禁止合法重算或扩大任务目标得到差异。两例手工组合和前置原型本身均不能确认假设，也不构成SCI创新验收。
