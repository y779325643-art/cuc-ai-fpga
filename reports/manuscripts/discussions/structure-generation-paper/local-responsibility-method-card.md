## 1. 方法要解决什么问题

固定 M4 要求顶层结构全部由程序构建，模型只能填写组件行为。当规范明确、但顶层有一部分逻辑不能由当前 emitter 实现时，整体固定结构可能不足；把整个顶层交给模型又会放开本可确定生成的实例和互连。

本候选在生成前划分责任：保留能完整机械实现的结构组，把其余规范明确的局部交给模型；同时固定区域间接口和写权限。需检验的新增点是**分组及跨区边界规则**，而非行为孔、一次调用、JSON 输出或模板本身。它不承诺修复错误契约，也不保证算法功能正确。

## 2. 首版输入与范围

| 项 | 明确范围 |
| --- | --- |
| 共同输入 | 同一生成契约、公开需求、公开且版本化的接口/协议声明；所有条件接收相同事实 |
| 划分输入 | controller 固定的 emitter 能力规则、信号读写/端口方向、宽度、域与协议绑定；不得用 oracle 或运行结果决定 |
| 首版结构 | 一层顶层、单时钟域、宽度可确定的点对点 stream 连接；顶层残余限无状态组合逻辑 |
| 程序能力 | 固定接口/实例及已明确的完整 tuple 直连；首版不自动综合条件路由、仲裁、缓存或控制状态 |
| 模型责任 | 原组件行为，以及划分出的顶层残余；同一次工程调用提交，不在工具失败后追加生成 |
| 不在首版内 | 跨时钟域、顶层状态、任意时延适配、任意 AST 区域拆分、任意多层次重构、全局最优分区 |

旧 HIS 没有统一、严格的 stream bundle 与组合依赖声明。必要公开补充至少包括：data/valid/ready 端点绑定、宽度/符号、时钟/复位域、时延、组合读依赖、需共同实现的协议关系、内部边界信号及规范来源。没有这些事实就不能按名字推断。其格式和版本在方案评审后确定，本轮不创建合同或修改 schema。

| 声明层 | 由谁提供／推导 | 必须核对的事实 |
| --- | --- | --- |
| 需求和外部接口 | 用户明确需求、公开平台事实或已披露的任务定义 | 原始字节、来源定位、参数、方向、宽度、符号、采样与环境义务；不得来自参考答案 |
| 架构及端点绑定 | 共享的同一次规划输出；开发正反例可手工构造并单列来源 | 与原始响应、规范化 PC、公开事实的绑定；接口/实例/端点引用是否闭合 |
| 共同实现规则 | controller 中预先固定的原语规则 | tuple 直连的三个方向性赋值同组；selector 的数据/valid/各输入 ready 同组；规则支持范围外不得靠模型声称某分组安全 |
| 信号读取关系 | 端点连接、原语声明与后续实际叶依赖检查 | E_r 不能只取自模型的自述；公开依赖与实际实现不一致时不得取得相关保证 |
| 程序/模型拥有者 | controller 运行固定规则产生 | 是推导结果，不得作为新的任务事实或 oracle 答案反馈给规划器 |

补充声明需绑定需求、冻结公开投影、原始/规范化规划输出及规则修订；旧对象允许 additionalProperties 不代表新语义已被注册或验证。首版不要求 model 一次输出任意 E_c 图；它提供有来源的类型/端点，controller 根据已规定原语推导分组。

“规范明确但 emitter 暂不支持”可进入残余；宽度/方向不明、同一对象存在冲突写者、必要行为未定义则直接失败，不能委托模型猜。实现能力限制不得反过来变成三条件的共同准入门槛。

## 3. 必须区分两类依赖

- **共同实现关系 E_c：** 本候选政策规定共同拥有的输出，例如二选一路由的数据选择、valid 选择和两路 ready 选择；以及同一个完整 tuple 连接的赋值。这是相对于给定规则的分组约束，尚非从协议语义证明的必要条件，相关反例见 §10。
- **信号读取关系 E_r：** 一个区域读取另一已声明边界的输出，例如 selector 读取下游 ready。这允许跨区域，不要求同一拥有者；用来核对合法边界和组合环。

不能沿所有读依赖无条件求闭包，否则一条 stream 链就会全部合并。E_c 来自受限、公开、可检查的原语规则，不由模型随意声明；原语以外的共同实现关系必须先完整规定，否则该形态不在首版支持范围内。

## 4. 划分算法

1. 将顶层结构要求拆为写入义务：实例/绑定、tuple 直连、已声明的局部组合关系。实例输出的驱动来自组件，不能把程序提供端口绑定误算成程序实现了组件逻辑。
2. 根据 E_c 构造无向图，计算连通组；每个组是相对于给定 E_c 的不可拆分责任单位。按本政策不把一个组拆成“程序管 data、模型另猜 companion 控制”；不据此宣称所有正确实现都必须如此划分。
3. 对每组检查所有义务是否都满足固定 emitter 规则：满足则归程序；规范完整但至少一项不支持则整组归模型。保留触发委托的具体规则与义务，不能只输出置信分数。
4. 对划分结果核对：每个必需写入恰有一个拥有者；所有跨区读取都出现在固定边界；所有必须同组的义务同组。未声明边界不自动补线或绑常量。
5. 生成程序结构与残余清单，然后一次调用模型。合并、边界检查和共同外部评价在后；任何失败保留，不回退重新采样。

若 E_c 的组和 emitter 规则已经固定，连通组计算可以线性完成；本稿没有证明这些原语规则完备，也不声称在一般电路上求得最大可 lowering 子图。首版只主张按这些明确规则给出可重建的确定性划分。

## 5. 顶层残余怎样表达与检查

为控制补工，首版建议模型输出**有限的表达式树**承载顶层残余，controller 发射对应的连续赋值；叶组件仍按原行为体输出。表达式树是实现选择，不作为创新主张，也不引入第二次模型调用。

最小表达式包含公开信号引用、定宽常数、逐位布尔运算与条件选择。controller 对树完整校验、推导宽度、限制规模；每个 LHS 必须在预分配写集合中且恰好一次，RHS 只能读取许可集合。首版不接受顶层残余中的实例、声明、过程块、延迟、宏、include、层次引用或函数调用。这样无需把任意 Verilog 当作可安全合并的片段，也不以正则搜不到关键字作为解析成功。

提议的最小树类型为 `sig(id)`、`const(width,value)`、`not(arg)`、二元 `and/or/xor` 和 `mux(cond,then,else)`。信号只能由 controller 的 ID 表解析；常量须为定宽非负整数且不溢出；逐位运算同宽，mux 条件一位、两分支同宽。拒绝未知字段/tag、重复键、浮点/非有限数、缺写/重复写和越权读取。树的节点/深度/字节限制在开发配置中显式设定，在真实运行前再与阶段预算绑定。本轮没有注册响应 schema。

一次工程响应拟同时包含叶路径到字符串的 `behavior_files` 与 `top_assignments` 列表；这不是现有格式已支持的事实。旧 [parse_behavior_files](../../../../agent/src/sr2fpga_agent/parsers.py)会忽略额外字段并将 body 强制转字符串，新 profile 必须有严格入口，不能直接把旧函数返回视为新响应校验成功。

**保证边界：** 此树检查可约束顶层残余的可表达行为与写集合；来源 envelope 可验证程序字节。叶模块仍使用旧 RTL 行为体时，这不足以保证全工程无越界写入。当前 body guard 不能完整排除层次访问/输入驱动；开发验收必须补叶模块边界限制及利用实际 HDL 前端结果的驱动核对。若无法闭合，只能报告顶层片段保证，不能宣称候选不能绕过全工程所有权。工具链/接口可复用性须先用窄负例验证，不能把现有 regex introspection 当成已有完整解析器。

上述检查不证明所选数据表达式正确，不证明所有协议性质、全工程无组合环或无死锁。驱动核对也不等于组合依赖核对；若要覆盖跨模块实际环，须从 HDL 前端提取叶模块实际依赖并核对其与公开声明一致，不能仅凭声明图无环通过。跨模块组合依赖与功能仍需要匹配的接口检查、真实工具与独立评价。

## 6. 完整的手工设计例：二选一路由后接数据变换

这是新提议的最小案例，尚未成为登记任务，也没有可执行 oracle。本文是内部设计材料，不整体提供给候选。公开要求、参考语义和评估刺激须在后续任务修订中分开保存。

**公开行为：** p、q 为两个 8 位无符号 stream 输入，y 为输出。mode=0 选择 p，mode=1 选择 q；未选输入不得发生接受。被选数据进入固定接口组件 B，B 将 8 位数据左旋 1 位后零周期输出，valid/ready 透传。全部在同一 clk 的采样点解释；不含存储、仲裁公平性或吞吐优化要求。

**环境义务：** p/q 各自满足 valid 且不 ready 时，到下一采样点保持 valid 和 data；若本周期所选事务阻塞，下一周期 mode 保持，进入 reset 时可解除。reset_active=1 的采样周期只要求外部 y_valid、p_ready、q_ready 为零，不要求 B 内部 ready 清零；无效周期数据不作要求。

所选输入 ready 的要求是非 reset 时精确透传下游 ready，即使所选 valid=0 也如此；输出 valid 精确等于所选 valid，不能以 y_ready 掩掉。控制信号按明确二态采样；刺激非法须单列，不可因候选输出错误而取消本来合法的刺激。具体公开材料、参考独立性和手工检查项见[混合案例资格准备](hybrid-case-qualification-plan.md)。

**手工参考语义（非程序预置的答案）：** 令 a=!reset_active：

```text
sel_data  = mode ? q_data : p_data
sel_valid = a && (mode ? q_valid : p_valid)
p_ready   = a && !mode && sel_ready
q_ready   = a &&  mode && sel_ready
B.out_valid = B.in_valid
B.in_ready  = B.out_ready
B.out_data  = {B.in_data[6:0], B.in_data[7]}
```

`sel_*` 是顶层残余的逻辑边界，不是一个已经提供实现的 mux 实例。公共行为说明中必须定义选择关系；模型不能凭 opaque 名称猜它。相应边界原语类型与绑定应给全部条件，划分器依据原语规则生成拥有者集合，不为每个例子人工手填结果。

| 单位 | 由规则得到的拥有者 | 写入或构建责任 |
| --- | --- | --- |
| B 的实例与端口绑定 | 程序 | 固定实例/接口与 wire 声明；不提供旋转算法 |
| selector→B 的完整 tuple 直连 | 程序 | B.in_data=sel_data、B.in_valid=sel_valid、sel_ready=B.in_ready |
| B→y 的完整 tuple 直连 | 程序 | y_data=B.out_data、y_valid=B.out_valid、B.out_ready=y_ready |
| selector 的四项耦合输出 | 模型顶层残余 | sel_data、sel_valid、p_ready、q_ready 必须一起实现 |
| B 的数据/协议实现 | 模型组件体 | B.out_data、B.out_valid、B.in_ready；模块内部责任不伪称程序逻辑 |

**手工推演：** 满足 B 接口要求时，y 的接受事件等于被选输入的接受事件，未选输入接受事件为零；mode/source 保持义务保证输出被阻塞时数据稳定。reset 时外部三个握手输出为零。这是给定方程下的设计推演，未执行模型或 HDL 验证，也不能说明模型会生成这些方程。

此例可展示“保留程序实例/直连＋顶层局部模型逻辑”。它本身很简单，也可用普通 mux 模板实现；方法价值必须来自跨案例一致的分组规则、边界保护及相对于匹配基线的证据，不能凭一个手工例子认定创新。固定 M4 是否拒绝或错误处理必须记录其真实行为，不故意削弱基线。

## 7. 正例、反例与退化情况

| 检查 | 预期行为 |
| --- | --- |
| 全部顶层义务受支持 | 顶层没有残余，退化为原固定 M4；记录而不强行制造差异 |
| 上述完整混合例 | tuple 直连/实例留程序，四项 selector 输出归同一残余组 |
| 同样结构更换标识符 | 划分仅随显式绑定改变；不因名称含 ready/valid 而猜线 |
| 删除必要 tuple/域/时延声明 | 资格失败，不把缺规范作为模型残余 |
| 只把 selector 数据给程序，控制另归模型 | 违反 E_c，不接受该划分 |
| 模型试图写 sel_ready 或 B 输入连接 | 超出残余写集合，失败；不能靠后续仿真碰巧通过 |
| 缺 p_ready、重复写 q_ready、非法树或宽度不一致 | 解析/完整性失败，不免费修补 |
| 将 y_ready 经残余反向构成组合环 | 首版按顶层表达式树及已验证的叶接口依赖拒绝；缺实际叶依赖核对时，不报告全工程无环；不能仅检查 E_c 或声明图无环 |
| 叶模块使用层次写入绕过边界 | 必须由叶边界/前端检查拒绝；若检测能力未实现，不能通过全工程所有权验收 |

这些是机制开发的预期检查，不是已运行的研究结果。普通不支持、契约错误、模型越界和基础设施未决按不同原因保留，均不静默移出分母。

## 8. 匹配对照与最小证据

建议将**新分区对粗粒度顶层委托**作为最直接的机制比较：后者同样固定组件接口/实例，遇到不支持的局部时把相关顶层互连整体交给模型，保持叶行为输出方式、表达式承载、公开事实、模型和调用机会一致。这样才能区分局部分工与单纯增加顶层表达能力。粗粒度条件的精确定义、与新方法可编辑对象的差异在最终协议中写明。

原固定 M4 可作为第三条件，展示旧覆盖范围与全支持退化；先前 M3 完整工程生成是另一参照，是否保留为第四条件须讨论工作量，不自动删除或执行。仅比较原 M4 对新方法，最多支持新增处理组合，不足以声称局部划分优于整块委托。此处是对原两条件方案的拟调整，尚未锁定运行计划。

任务须预先区分原 emitter 已支持形态与规范完整的混合形态，防止只选新方法专门增加的案例。完整功能/综合通过、结构和边界错误、实际成本及全部上游/方法失败均保留。不能仅用固定 M4 对新形态的预期能力缺口当作性能优势。

最小设计证据需要：规则驱动的全支持正例、至少一个混合例、输入缺失/错误及越界负例；独立参考与协议边界核对；划分日志可重建；以及相同任务/契约下的新方法与匹配基线。样本、模型、工具和预算待后续 P04–P07 确定，本稿不以一个案例或若干种子承诺充分样本量。

## 9. 新颖性和开发前验收

补充查新发现，[MLIR Dialect Conversion](https://mlir.llvm.org/docs/DialectConversion/)已经按目标合法性进行部分转换并保留部分未转换操作。因此“支持部分程序化＋保留残余”不能作为新的编译思想；连通组求解也不是新算法。本篇仍待成立的领域机制是：从公开硬件协议义务导出共同实现关系、在 model 参与时核对跨区责任、以及与匹配委托方式比较。若 E_c 只是逐例手工写死，或差异只剩是否提供更多提示，方法增量仍不足。MLIR 的保留操作不等于把其语义交给模型，这个区别本身也不是充分贡献证明。

与 [CPPL 的预置/延后实例](https://github.com/SawyDust1228/CPPL/blob/d7ebbb5f4036ac57a768bc362996ab05e8c39b9f/cppl/agents/worker.py#L106-L119)等近邻的待核区别是：共同实现闭包、局部能力委托和固定跨区责任，而非 JSON、程序与模型混合或确定性发射。[HINT](https://arxiv.org/html/2608.07625v2)、[VeriGraphi](https://arxiv.org/html/2604.14550v2)及普通编译器分区/部分编译仍需按具体规则比较。当前没有方法首创认定或 SCIE 充分性结论。

进入开发前应明确：补充声明和 E_c/E_r 的可检查来源；混合例的正式任务修订及独立参考；表达式承载、叶模块边界与实际依赖检查的具体范围；新条件身份及注册格式；修改共同准入/失败语义的实际表面；最终最少比较条件。上述未闭合就保留设计状态，不把本方法卡当作实现、实验或正文授权。

## 10. 规则—反例—普通分区基线：当前立项缺口

[TVM BYOC 分区 RFC 的 Steps 1–4](https://discuss.tvm.apache.org/t/rfc-byoc-an-extended-graph-partitioning-flow/6028)已提出原子支持区域、互斥编译归属、全覆盖、依赖合并和显式边界；部分步骤在该历史 RFC 中仍为提案，不能声称当时全部实现。[MLIR 部分转换](https://mlir.llvm.org/docs/DialectConversion/)也已有依能力转换部分、保留残余的机制。当前只能把它们作为应正面比较的先例，不能以换到硬件模型后端自动取得算法新颖性。

| 当前规则或拟主张 | 可手工构造的反例／普通基线结果 | 评审处理 |
| --- | --- | --- |
| 给定 E_c，连通组中全支持则程序，否则模型 | 普通原子区域标记＋双后端分区可得到相同结果；若把 selector 标成一个 atomic region，就复现当前手工例的划分 | 属既有算法骨架，不作为新分区算法贡献 |
| data/valid/ready 必须同一拥有者 | 对明确的恒等 LINK，程序写 data alias、模型正确写 valid/ready alias，也能满足协议；不能仅由字段相关推出分属两方必然错误 | 当前同组是保守责任政策，不是已证明的协议必要条件 |
| selector 四个输出同归模型即可保持选择一致 | mode 选 q、p_valid=1、q_valid=0；模型用 q_data 却用 p_valid。写集合/宽度/同组均可合法，仍产生错误 valid | 同组不足以证明关系正确；必须另有真实语义约束及评价，不借所有权保证功能 |
| 全部读取依赖闭包就是协议责任闭包 | ready向上游、valid/data向下游的串联链会被整条吞并；跨固定边界读取并不必然要求同一实现者 | 已区分 E_c/E_r，但该区分本身也不自动构成新机制 |
| 有限表达式树＋唯一写者足以证明新机制有效 | 同类型表达式可选择错误的合法数据源；普通类型/权限系统也能执行相同检查 | 是必要工程控制，不作新颖性或功能效果的独立证明 |

继续该研究前应完成一轮有界规则设计：给出可执行的协议关系输入，说明如何由该关系**自动导出**此前未手工标注的责任/一致性约束；再给一个普通支持/原子区域策略无法同样处理或明显过粗、而新规则有可验证区别的非平凡案例。案例、普通基线和输入事实必须匹配，不能仅给新方案更多原语标签或正确答案。

如果最终仍需按案例手填 E_c，或普通基线得到相同分区且相同约束，本方向就没有在目前证据上跨过新增方法门槛；应明确停止将其包装为已找到的论文创新点。纯生成原型仍可能有工程价值，但不能替代这项研究判断。本轮尚未提出或证明上述自动推导规则，也未将其实现。
