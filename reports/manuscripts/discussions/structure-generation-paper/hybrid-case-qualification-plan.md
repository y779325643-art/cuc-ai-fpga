## 1. 模型公开要求与责任

所有比较条件接收同一公开需求、契约字节、接口/协议及环境事实；按条件不同仅改变结构写入责任。公开材料应包括：

- p、q、y为8位无符号stream，明确data/valid/ready端点、方向、单时钟域与采样点；mode=0选p，mode=1选q。不要求仲裁公平性。
- 固定接口组件B将8位数据左旋1位，最高位回绕到最低位；零周期，不含存储。B的valid/ready精确透传。
- reset外，所选输入ready与y_ready逐采样相等，**不以所选valid为前提**；未选输入ready恒0；y_valid等于所选输入valid。此处要求精确透传，不只是接受事件最终等价。
- reset_active=1的采样周期，外部y_valid、p_ready、q_ready均0；不要求B内部ready清零。无效周期数据不约束。
- 所有条件固定B实例/接口与sel_*逻辑边界。局部条件由程序保留selector至B及B至y的tuple直连，顶层模型残余只写sel_data、sel_valid、p_ready、q_ready；整体委托条件的模型写集合包含全部可委托顶层赋值。两者均由同一次工程调用提供相同叶路径的B体；这些是条件责任规定，不是不同的任务行为事实。
- sel_*是逻辑边界，不是程序已实现的mux实例。原语类型/绑定、表达式允许项、允许读集合及各条件写集合需公开；模型不读取参考RTL、私有测试、原始结果或答案方程。

公开要求应说明选择、旋转和时序语义，但不提供评价方参考实现。本文后面的手工例是内部核查材料，不能直接整体作为模型输入。

## 2. 跨采样环境义务与非法刺激

在非reset的相邻采样点之间，p和q分别满足：本周期valid且不ready，则下一周期valid保持且data不变。若本周期所选事务阻塞，下一周期mode保持。进入reset时解除这两类跨周期保持义务；释放reset后按新事务处理。控制信号应为明确二态值，X/Z处理须在正式任务修订中固定。

非法环境必须保留刺激、监视结果及原因，标为环境/测试材料无效，**既不记候选成功，也不记候选功能失败**。不能因候选错误的ready/valid而取消刺激、跳过检查或把设计错误改称环境非法。应按受信公开语义组织刺激，并先记录可定位的候选协议违约；环境监视器不能以候选异常输出来重新定义合法需求。

## 3. 仅评价方的三层独立真值

| 层次 | 参考与交叉核对 | 不应采用的循环论证 |
| --- | --- | --- |
| 数据变换 | 独立按位规定输入位i移至输出位(i+1)模8；用单一置位及混合位模式手算交叉核对 | 直接复制方法卡或候选表达式作为唯一答案 |
| 事务来源与守恒 | 从合法外部输入和选择规则追踪来源/值；核对输出接受与被选输入接受一一对应、未选输入不接受 | 用候选自身ready/valid决定哪些错误事务可不检查 |
| 周期协议 | 独立监视精确valid/ready、reset、mode/source保持与输出阻塞保持 | 只比较最终输出值就声称握手与时序正确 |

评价侧还需保存正确参考、错误变体的独立真值理由、环境监视器、刺激和判定记录。**不能让同一个顶层表达式树解释器既充当oracle，又成为被验证实现。** 可共享公开需求定义，参考求值、事务追踪及程序发射应保留独立实现/人工核对途径；共用代码缺陷不构成相互验证。

## 4. 十五条手工预期检查

下表是尚未执行的设计预期，不是测试结果。接受指采样点valid与ready均为1；未列数据在无效周期不作要求。P为合法环境正例，N为候选错误/越界反例，E为非法环境反例。

| 编号 | 刺激或候选变体 | 手工预期 |
| --- | --- | --- |
| P1 | reset=1，p/q valid均1，y_ready=1 | y_valid、p_ready、q_ready全0，无外部接受；不检查无效数据 |
| P2 | mode=0，p_valid=1，p_data=0x81，y_ready=1 | y_valid=1、y_data=0x03，仅p接受 |
| P3 | mode=1，q_valid=1，q_data=0x01，p_valid=0，y_ready=1 | y_data=0x02，仅q接受 |
| P4 | 两输入valid均1，p_data=0x80、q_data=0x7F，mode=0，y_ready=1 | 输出0x01，q_ready=0；不能混接数据与valid来源 |
| P5 | mode=0，p_valid=0、q_valid=1，y_ready=1 | y_valid=0、q_ready=0、p_ready=1，且无接受 |
| P6 | mode=0，p_valid=1、p_data=0x80，y_ready连续两周期0，输入保持合法 | y_valid保持1、y_data保持0x01，两输入ready均0，无提前消费 |
| P7 | P6后y_ready变1，接受周期其余保持；接受后源撤销该valid | 该旧事务恰好接受一次，撤销后不得再输出旧事务；不把源持续valid的合法后续接受误算重复 |
| P8 | 上周期p已接受；下一周期合法切至q，q_valid=1、q_data=0xFE、y_ready=1 | 输出0xFD并接受q，不保持旧p事务 |
| P9 | q_valid=1且未选，q_data合法保持0x55；随后合法选q且y_ready=1 | 未选期间q_ready=0，随后输出0xAA |
| P10 | 阻塞时进入reset，同时改变mode/source；随后释放 | reset解除旧保持义务且无外部接受；释放后只评价新事务，无旧事务幽灵输出 |
| N1 | 候选将y_valid额外依赖y_ready | P6应发现valid错误，不能因当时没有输出接受而放过 |
| N2 | 候选选q的valid却取p的data | P3/P4应发现来源或数据错误 |
| N3 | 顶层残余写sel_ready、程序连接，或重复写q_ready | 完整性失败；不能以仿真偶然通过取得信用 |
| E1 | 非reset阻塞时改变mode | 保留记录，标非法环境；不据输出变化判候选成功/失败 |
| E2 | 非reset阻塞时改变source data或撤销valid | 保留记录，标非法环境；不能要求无存储组合设计吸收该违约 |

关键不变量：每个写入唯一拥有者；E_c完整tuple/选择组不拆开；跨区读取只走声明边界；未选输入接受为0；合法事务来源和值一致；输出接受与被选输入接受一一对应；合法阻塞时输出valid/data稳定；reset无外部接受；声明与实际依赖没有内部组合环。前三项完整性检查不能代替后三类功能/协议评价。

## 5. 超出单一toy mux的结构覆盖准备

| 覆盖类别 | 待准备形态 | 预期机制边界 |
| --- | --- | --- |
| 串联直连 | 两个固定接口组件串联，所有tuple关系受支持；可参考既有TD流水等结构组织 | 无顶层残余，退化到固定结构；不得强行制造差异 |
| 混合 | 分别考虑输入选择、输出条件路由、中间局部数据关系三种位置；例如既有FIR之外加公开输入选择包装 | 仅委托不支持的共同实现组，保留独立完整直连；不能仅改mux标识符充数 |
| 可委托顶层义务全残余 | 固定实例/接口仍保留；所有可委托顶层关系均含不支持的组合关系，没有独立可保留的tuple直连组 | 应自然退化到粗粒度委托；不能人为合并无关E_c关系制造此形态 |

这些是结构类别，**不是三个独立任务、独立设计簇或样本量**；位置变体、标识符变化、seed/输入变化也不自动增加独立数。若实例和端口绑定始终归程序，就不能将最后一类称为“整个工程全残余”。候选覆盖须记录实际关系与分组理由，不声称现有九任务已经覆盖这些新形态。
