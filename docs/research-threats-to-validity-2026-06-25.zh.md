# SR2FPGA Threats to Validity —— 审稿人视角评审（2026-06-25）

用 nature-reviewer skill 对 SR2FPGA 研究计划（reframe spec + 今天的基础设施 + discovery 级 pilot）做的一次
**审稿人视角**模拟评审。作为活的 threats-to-validity 记录，供论文规划、消融设计、诚实界定范围用。英文版：
`...-2026-06-25.md`（不一致时以英文版为准）。

**框架说明：** 没有 manuscript 草稿——这评的是*研究计划 + 早期基础设施*；目标期刊是 **IEEE TCAD / TRETS，
不是 Nature**。Nature 专属的轴（广泛跨学科读者、非专家可读性）弱适用；改以 **EDA 方法新颖性 + 可复现性** 加权。

## 评审设置

- **输入范围：** reframe spec + System-HIS v1.2 freeze、L0–L5 设计、baseline pilot、失败-修复日志、约束解码设计。
  无结果 manuscript；无训练模型；无 L4 数据。
- **评估边界：** 对*计划 + 基础设施 + discovery pilot* 的有界评审，不是完成的结果论文。凡需训练模型、规模数据、
  物理 L4/L5 的，**尚不可评估**。
- **共同主张：** 工具验证学习——把 EDA 工具预言机蒸馏进一个模型，经 System-HIS + L0–L5 + 工具验证轨迹 +
  (a)/(b)/(c)，生成/诊断/修复/预测项目级、多文件、可物理实现的 FPGA RTL；以 System-HIS 约束解码为方法新颖性核。
- **可见证据：** v1.2 schema 已实现；L0 交叉检查经验证能抓注入失配；~30 run + 25-issue 失败-修复日志；
  baseline (a)/(b) pilot（修复膝点 T3；T4 失败前沿推下 L0→功能）。N≈1/档、单一模型、探索性协议。
- **缺失材料：** 训练模型 / (c) 结果；规模数据集；任何 L4/L5 结果；约束解码实现；冻结协议测量；置信区间。

## 审稿人 1 —— 侧重：经验证据与严谨性

- **总评：** 基础设施扎实，但作为结果贡献**尚未成立**——核心主张押在没跑的实验上。
- **谁会感兴趣：** LLM-for-EDA / FPGA-CAD 研究者（可复用轨迹数据集 + L0–L5 评测）。
- **优点：** 客观工具监督；(a)/(b)/(c) 设计干净；诚实区分 discovery vs evidence。
- **担忧：** headline RQ3 (c) 点**不存在(没训模型)**；pilot N≈1/档、单模型、作者自称"discovery 非 evidence"；
  T3 膝点 + 失败逐层下移在规模复现前只是轶事。
- **必须解决的技术缺陷：** (1) 训≥1 个模型、按档报 (a)/(b)/(c) 带置信区间；(2) Line B 扩到个位数/档以上；
  (3) 冻结 prompt——prompt 收紧泄漏(Issue 4)污染 b−a/c−a；(4) 修数据质量(reset/clock 噪声标签、Yosys-L3 假 LUT)
  再谈 LOG2DIAG/QOR_PRED。
- **态度：** 作为结果论文未就绪；规模化执行后再议。

## 审稿人 2 —— 侧重：新颖性与定位

- **总评：** framing 新颖；是不是*方法*贡献取决于一个没建的组件。
- **谁会感兴趣：** 硬件中间表示、工具反馈学习的研究者。
- **优点：** "蒸馏工具非 LLM"把前沿模型变基线；System-HIS 作需求级 IR 正是 Representation Bottleneck(2026)写成
  future work 的"分离意图/实现的 IR"；硬件语义分类法 × L0–L5 是新的组织性贡献。
- **担忧：** 裸 pipeline 逐组件看是成熟技术拼装(RL+工具奖励、修复回路、约束解码——都有，作者也承认)。所声称的
  *方法*新颖性——System-HIS 约束解码——**只有设计、未实现/未验证** → 最强新颖性主张目前无支撑。
- **必须解决：** (1) 实现+验证约束解码(L0 按构造→~0；下游有帮助且不伤 L2)；(2) 在共享任务上和 RL 簇正面对比；
  (3) "无 HDL 约束解码先例"需穷尽检索。
- **态度：** 对专业期刊有条件看好；新颖性押在约束解码核上。

## 审稿人 3 —— 侧重：方法学、可复现性、现实意义

- **总评：** 方法学 + 可复现是最强部分；物理实现是最大未验证风险。
- **谁会感兴趣：** FPGA 从业者 / 买不起商用 EDA 的小团队(免授权开放流 + 公开数据集)。
- **优点：** L0 检查器产出单文件 benchmark 做不到的"跨文件一致性错误率"；异常有威胁意识(CDC 亚稳态/板级信号已划范围外；
  检测≠预防；accessibility–competence 悖论)；一个检查器复用为约束源 + 验证者。
- **担忧：** 物理 L4/L5——TCAD 核心卖点——**完全卡在未验证的 OpenXC7 spike**(XC7Z020 chipdb = 单点失败)；当前
  "measured QoR"是假的(Yosys-L3 LUT=0)；很多贡献是"已承认 gap"，执行卡住就塌成"把已知方法移植到 FPGA"。
- **必须解决：** (1) 一个设计端到端到 bitstream + 上板、版本锁定；(2) 任何资源/QoR 数字前用 synth_xilinx/L4 替掉假 LUT；
  (3) 全层诊断模式，使 L0 短路(Issue 5)不审查掉 L1–L4 分布。
- **态度：** 一旦有一个物理结果 + 规模测量，在以可复现性加权的期刊可发。

## 交叉评审综合

- **共识优点：** 客观工具监督 + (a)/(b)/(c) 公平较量；System-HIS 需求级 IR 带显式 future-work 锚；硬件语义分类法 ×
  L0–L5；诚实、可复现、全开放 framing；异常的威胁意识。
- **共识技术风险：** (1) 无执行结果——headline (c)/RQ3 需要不存在的训练模型；(2) 方法新颖性核(约束解码)未建 →
  是方法学非方法；(3) 物理 L4/L5 卡在未验证 spike + 单点 chipdb 风险；(4) 测量效度——prompt 泄漏已观察、数据质量缺陷
  已记录、N≈1/档。
- **侧重差异：** R1=规模跑；R2=建并证明新技术；R3=拿一个物理结果 + 可复现。三者是前提，不是替代。
- **广泛读者读出：** 对专业 EDA 期刊意义真实；Nature 式广泛兴趣不是相关轴、也未声称。
- **成强论证前最重要的事：** (i) 规模化、冻结协议的 (a)/(b)/(c) + 训练模型 + 置信区间；(ii) 约束解码实现并证明让 L0
  按构造成立且不伤 L2；(iii) 一个验证过的物理 L4/L5 结果；(iv) 修数据质量 + 加全层诊断。

## 风险 / 无支撑主张

- **不可评估(无证据)：** 任何 (c)/内化结果；小追大；QoR 预测相关性；L4 物理主张；约束解码有效。
- **声称但未验证：** "无 HDL 约束解码先例"(仅快速检索)；OpenXC7 XC7Z020 chipdb 可用性；PICARD 确切引用。
- **已承认但承重：** "已承认 gap"类贡献只有交付 L4/上板 + 真轨迹数据集才成立(spec 自己的警示)。
- **要保留的诚实优点：** 该计划不过度声称——区分 discovery vs evidence、把物理本质的限制划在范围外。

## 底线

强、诚实的*计划 + 基础设施*；**还不是带证据的贡献。** 把它从"有希望的方法学"变成"站得住的 TCAD 方法论文"的三件事，
正是 spec 已列为 gated 的三件：**训练一个模型(规模化、冻结协议)、把约束解码做出来、拿到一个物理 L4/L5 结果。**
