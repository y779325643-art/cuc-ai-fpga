### 0.2 规范与事实分开

**研究规范链：** 明确采纳的本计划 → 冻结的实验／分析协议 → 与其一致的代码架构 SPEC、注册 contracts 和 campaign 配置。

**实现事实链：** 实际代码与测试版本 → 不可变原始事件／工具产物 → 可重建状态与结果。

二者冲突时记录 `implementation_protocol_drift`，修实现或显式修规范；代码已经这样运行不等于研究标准已经改变。文件名里的 freeze、注册过的 schema、存在的报告或模型自报 `pass` 都不自动授予新研究结果。

本文件供本轮研究设计采用，不等于正式 campaign 许可。用户提出重写计划不自动授权昂贵模型调用、数据下载、正式隐藏评测或板级操作。正式运行只需与当前风险对应的核验，不恢复旧版相互叠加的 G0–G9／训练授权链。

## 1. 科学问题、研究价值与可否证主张

### 1.1 一句话研究问题

> 在冻结公开需求、模型、工具权限和总预算下，显式张量／数值／事务契约、确定性工程构建与受限修复，能否提高量化 AI 加速子系统在独立验证下的工程成功率，并减少跨模块不一致？

研究对象不是“让模型填好 JSON”，也不是提出一个更快的卷积或 GEMM 微架构。研究生成方法如何维护需求、架构选择、源码与验证对象之间的关系；物理结果检验相应工程意义，不预设 PPA 优势。

### 1.2 一致性必须分成三个层次

| 层次 | 例子 | 本方法的直接作用 | 正确性证据 |
|---|---|---|---|
| 结构一致性 | 实例绑定、位宽、驱动、record／lane 展开 | 静态检查和确定性构建 | 检查器、真实 RTL 解析／elaboration |
| 声明语义一致性 | 同位宽不同布局、不同尺度直连、部分和组顺序不匹配 | PC 2.1 的类型与有限关系检查 | 对实际声明的机械比较 |
| 实际行为一致性 | RTL 发错通道、两支路错配、重复累加、缓冲停顿 | 通过约束和诊断间接帮助，不能自证 | 独立位精确参考、协议／事务监测、适用形式或物理证据 |

局部乘法算错首先是局部行为错误；生产者和消费者对同一数据的坐标、数值或有效时刻解释不同，才属于跨模块不一致。一个错误可以有多个标签，但不能把所有 hidden failure 都归因为模块一致性。

### 1.3 为什么这三类任务有工程意义

Depthwise→Pointwise 取自深度可分离卷积结构，残差块取自残差学习结构；二者分别有 MobileNet 与 ResNet 的原始工作作为结构来源。[E1–E2] Gemmini 的装载／执行／存储控制及依赖处理提供矩阵加速子系统协调问题的实例。[E3] FINN 文档说明并行度影响打包，hls4ml 使用 RTL 协同仿真分析层间 FIFO 占用；它们说明接口解释与缓冲是实际工程责任。[E4–E5]

这些来源只证明问题与任务背景，不证明当前模型频繁出错，不证明 PC 是首次相关表示，也不保证所选有限配置具有现场应用效果。

### 1.4 拟检验的贡献

**C1：有限而可执行的契约机制。** 将形状、数值编码、lane 布局、调用／坐标关系和部分和责任与不可变需求绑定；区分静态可检验部分与仍待验证行为。

**C2：契约约束的工程构建与修复。** 以真实结构构建和受控行为装配减少模型必须重复维护的关系，并通过共享 PC 和等预算对照测量增量。

**C3：面向三类量化子系统的独立工程证据。** 提供完整任务、独立 oracle、自然错误分类、修复与全成本结果，以及代表性 FPGA 物理证据。

这三项是目标，不是已经成立的新颖性。若要声称“张量检查本身造成成功率提升”，还需要 §13 的独立消融，不能仅凭 M4−M3 得出。

### 1.5 主要可否证情形

如果强 Direct-Repair 已经稳定通过、PC 带来的前置失败抵消下游收益、失败主要发生在契约无法检查的算法内部、或等预算后优势消失，则完整方法优势不成立。若只有结构错误减少而总成功率不变，只报告局部机制现象。方法负结果不允许删任务、改 oracle 或把次要案例升格为真正主问题。

## 2. 研究范围与任务总体

### 2.1 三个主家族

| 家族标识（拟注册） | 计算范围 | 组合机制 | 主关注义务 |
|---|---|---|---|
| `ai_dw_pw_block` | Depthwise 卷积→阶段量化／激活→Pointwise 卷积→输出 | 串行算子链 | 张量遍历、通道／lane、权重与 per-axis 参数对应 |
| `ai_quantized_residual_block` | 主支路计算＋跳跃支路＋对应相加／激活 | 分支与汇合 | 数值尺度、调用／坐标配对、背压、复位、缓冲 |
| `ai_tiled_gemm_pipeline` | 矩阵接收／存储、分块乘加、归并、Bias／重量化、提交 | 分块计算与状态归并 | 部分和身份、清零／提交、累加精度、阶段语义 |

三个家族共享基础运算，不宣称相互统计独立的全部机制。主要推断条件于这三个命名家族及冻结抽样范围，不外推所有 AI 模型或所有 FPGA 工程。

### 2.2 最小论文边界

核心输入是已裁定 ready 的完整公开需求，不同时研究任意模糊自然语言理解。输出是完整 FPP：全部必需 RTL、声明式源码清单、外部 ABI、合法初始化／权重引用及适用构建配置。PC、候选 testbench、QoR 预测不属于所有方法共同必填。

论文以完整子系统工程而不是单个乘法器为单位。多文件与模块划分应来自实际职责；若任务未规定内部结构，则合并或拆分的合法实现由共同评测接受，不能为 PC 有利而强制隐藏参考拓扑。无意义的空模块／文件不增加复杂度。对确有公开复用接口、分块装载或容量义务的任务，所有方法遵守相同规定。

必须完成三个家族的资格、M0–M5 主结果、两个主要比较、独立验证、失败／成本分析和三个家族的预选 L4 深度研究。完成研究不要求所有方法通过或所有假设显著；但只有三份固定示例、缺少独立需求簇时，应定位为有限案例研究而不是广泛 benchmark。

### 2.3 旧资产与非目标

旧 UART loopback、通用 fork/join、matched-filter、Sobel 移至开发／回归或独立非 AI 诊断；FIFO、RAM、MAC 等基础测试继续支持工具与构建器验收。它们不进入新三家族均值，旧通过不能转移给 AI 家族。

Q-table 从近期主执行路径移出。EA／RL 架构搜索、训练生成模型、学习型 QoR、任意 ONNX importer、通用神经网络编译器、完整 ResNet／MobileNet 端到端、DDR／PCIe／相机／SoC、L5 和应用质量评价均非核心依赖。固定预训练权重作为任务输入不等于训练生成模型；本研究不做任务特定参数更新。

## 3. 问题形式化与公开需求契约

### 3.1 统一输入与输出

令公开需求为 R，目标配置为 T，能力配置为 C，冻结生成模型为 L，资源上限向量为 B。方法 m 只能使用公开反馈 E_pub，在预算内输出一个终止 FPP A_m 或有原因的无候选终止。E_hidden 在候选封存后独立评分。

PC 方法中：`L(R,T,C) → design`，控制器注入原始输入绑定形成 PC，检查后构建结构并实现行为。Direct 接收相同事实与 ABI，自由生成工程。有效性不是与某个参考文件布局相同，而是在指定环境与输入域内符合 R，完成规定工具阶段并遵守执行边界。

### 3.2 每条义务的来源与角色

| 维度 | 需要表达的内容 |
|---|---|
| 来源 | 外部规范／模型来源、研究者工程设定及推导、公开允许的默认 |
| 角色 | 不可变保证、环境假设、软偏好、允许的实现自由度 |
| 适用域 | 形状／输入范围、初始化、调用方式、背压与复位条件 |
| 验证责任 | 静态、RTL 仿真／形式、综合映射、物理或更深阶段 |
| 状态 | 结果由证据层填写：通过、失败、未验证、不适用及理由 |

冻结需求、目标时钟、精度和事务规则不能被模型通过 `notes`、`intent` 或新假设削弱。判题规则、合法输入和环境假设全部公开；隐藏的是具体测试向量、编排与期望输出，不是语义规定。内部 FIFO 深度和模块数量不因存在于参考设计就成为强制要求。

### 3.3 AI 任务必须公开的具体信息

公开任务至少包括：精确运算图与先后顺序；tensor shape、命名轴与外部遍历／lane／mask；元素代码范围；scale／zero-point 与 per-axis 索引；权重、Bias 和初始化；padding、stride 和边界；中间精度、溢出／舍入与激活位置；输入接受、输出提供／接受和调用终止；复位取消规则；允许停顿及完成条件；目标 profile；完整交付范围。

禁止只写“INT8 Conv”“同样精度”“正常 AXI”或“适当缓冲”。正式前必须能由任务文本与冻结公开资产唯一确定适用域内的期望行为。

### 3.4 环境假设自洽

第一版采用可暂停的有序文件／事务回放源，固定形状调用不交织；无完整 DMA 或多时钟平台义务。多个调用可以连续进行，但边界与旧状态清理必须定义。

无停顿 II、接受到提供的延迟、接受到最终接收的延迟分别命名。只有在明确定义的源／接收端服务条件下才有有界完成声明；最大连续停顿长度未必单独足够，应同时冻结恢复服务或具体压力模式。有限缓存、无限输出停顿和无条件连续输入零丢失不能同时作为无条件要求。

## 4. PC 2.1：机制、检查范围与未解决问题

### 4.1 一份设计权威，四类逻辑对象

| 对象 | 责任与权威 |
|---|---|
| 公开需求／profiles | 决定必须实现什么、在哪个目标及能力域下实现 |
| PC | 控制器绑定，模型提出层次架构与边界承诺 |
| FPP／构建记录 | 构建器确认实际文件、ABI、依赖与来源 |
| 验证证据 | 独立评测确认实际满足了什么 |

完整 PC 为 `schema_version / bindings / design`。`bindings` 引用 requirements、target_profile、capability_profile 的身份和实际字节 SHA-256；hash 不是签名或授权。模型输出 schema 的根直接是 design，不再套一层 design，也不能填写 bindings。两份 schema 的设计定义同源生成或在 CI 验证一致。[R2; R5a–R5b]

`design` 包含 entry、modules、requirement_map 和可选 notes。入口签名引用 `requirement_boundary`；内部模块自行声明。结构／行为模块分离，状态局部归属；参数使用有限 AST，不能 eval 任意字符串。

### 4.2 张量与事务增量

| 位置／规则 | 语义 | 能够机械检查的部分 |
|---|---|---|
| `signature.tensor_contracts` | shape、element、quantization、layout、sequence | 命名轴、范围、每轴表长度、当前配置求值 |
| `tensor_beat` | 引用局部契约，推导每拍类型 | lane／mask 宽度、拍数及边界匹配 |
| 直接 net | 两端不发生隐式语义变化 | shape、编码、遍历与序列一致 |
| `identity / fork / repack` | 保持、复制或改变布局的行为关系 | 声明的输入输出条件自洽 |
| `requantize / zip_add` | 显式数值转换和同调用同坐标相加 | 数值模式、形状／序列／条件相容 |
| `reduce_sum` | partial_sum 归并为 dense 输出 | 组定义、尺度、宽度、清零／提交声明 |
| `compute` | 公共任务定义的任意运算 | 端口／域／事实引用，不证明 Conv／GEMM 数学 |
| `buffer_rules` | 一个 FIFO 条目绑定一个完整 beat | 状态类型、域、容量单位与流关系 |

局部契约按展开内容而非名字比较。order 从最慢到最快，当前 profile 的 lane_axis 为最快轴，lane0 在低位；zero_pad_mask 的无效 lane raw bits 为 0 且不参与运算，不等于量化实数零。不得把张量换成 raw bits 来保留“仍有张量检查”的声明。[R2, §§3–8]

### 4.3 能力配置与重要限制

核心首选固定实例化形状、密集有序张量、一个 lane 轴、单用户时钟、已验证的同步复位和 `ready_valid_v1`。不声称支持任意 stride/gather、稀疏／ragged、交织乱序、任意标签、多时钟或完整 AXI。静态 shape 中可使用参数，但报告只覆盖实际实例化配置。

本版不修改 PC 2.1 字段或算法；真实实现发现缺口时显式版本化，不在论文协议中凭空假定 checker/emitter 已支持。PC 能表达不等于工具链可综合，也不等于满足物理容量。

### 4.4 声明通过不是功能证明

双方都声明 HWC、某个 RTL 实际发送 CHW，静态边界匹配可能仍通过；双方把错误尺度抄成相同值，也可能逃过内部比较。`requirement_map` 是引用覆盖，不是需求蕴含证明。低容量 FIFO 可静态合法，但仍需实际占用、启动与稳态活性证据。

报告分开保存静态规则结果和 `verification_obligations`。后者初始为 not_evaluated，不能由模型自行关闭。完整 oracle 从 R 建立，不根据候选 PC 的 compute 意图、关系删减或生成 testbench 修改答案。[R2, §9]

### 4.5 本论文允许的有限保证

在受支持 PC 与已验证构建规则下，构建器保持声明的模块签名、类型布局和连接；被接受的行为补丁不改变受保护结构。这一条件性不变量由正反例、真实 RTL 解析与装配测试支持，不声称普适形式证明。

不会自动保证正确算法、实际张量顺序、量化结果、残差配对、所有参数域、无组合环／死锁、资源映射或时序。评价必须检验结构优势是否最终保留到独立功能与综合终点。

## 5. 确定性构建、行为实现与修复

### 5.1 构建链

```text
冻结需求／目标／能力
  → DesignProposal → 控制器组装 PC
  → 严格解析／schema／引用与类型／能力／义务关联检查
  → ResolvedDesign → BuildPlan／AbiMap
  → 确定性结构源码＋受保护行为签名
  → 一次批量行为实现 → 完整 FPP
  → 公共检查 → 有预算的修复
  → 封存唯一候选 → 独立隐藏验证 → 指定 L3／预选 L4
```

展开图、BuildPlan 和 ABI 是派生对象，不能由模型独立修改。共享 PC 准入检查不得先成功运行 M4 emitter 再决定 M3 是否准入。

### 5.2 构建器做结构，不藏行为答案

允许生成模块头、参数特化、实例、连接、常量、record／lane／mask 展开、ready 反向线、文件清单和声明式工具入口。遍历说明进入生成上下文与验证责任，但仅靠换接线不能完成时序重排。

禁止静默插入 FIFO、fork/join、仲裁、流水线、repack、requantize、Conv、GEMM、累加控制或 CDC。显式关系仍由模型实现行为；示例 builder 不能进入运行时答案库。公共行为 IP 若启用，必须对所有对照提供等价内容与机会，并单列模板／库干预。

### 5.3 批量行为与结构保护

M4 初始行为阶段一次逻辑模型调用覆盖全部必需单元；相同特化单元复用实现但实例状态独立。漏单元、截断、非法格式不能用空 body 或免费补调用掩盖。无行为单元时可按明确条件跳过并记不适用。

保护以行为单元＋真实解析／elaboration 为边界，不只依赖注释哨兵。结构哈希、输入依赖和来源映射由受信程序维护。量化、遍历、lane、组顺序或规则改变，即使总位宽相同也不能自动复用旧 body/cache。

### 5.4 两层修复与 Direct 的有效修复机会

M5 可用一次已计费响应替换 design，重新绑定原需求并检查／构建；需要新行为时另用剩余调用生成。首版可全量失效相关行为，避免错误增量复用。旧候选与其配套 PC 永不覆盖；新分支未形成完整工程时，仅按既定选择规则保留旧完整候选。

M5 的行为修复只替换允许单元。M1 可以替换完整工程，也可使用预先冻结的通用 model-owned 文件替换协议；共同装配器只应用字节变更并重新检查，不补接线或算法。**允许 M1 文件级修复是本版明确的实施修订**：避免强制它每轮重传整工程，而 M5 可以局部替换带来的无必要序列化劣势。两者仍不是相同编辑策略，此差异属于系统比较，必须记录输出格式与成本。

主流程使用确定性控制器，模型只提出设计／修改，不拥有放宽需求、提升预算、修改评分器或开放 hidden 的权限。额外 router／诊断模型调用也计入 B4，不能藏入“Agent 内部”。

## 6. 三个 AI 家族的目标规格

本节是需要落实为任务卡的研究规格，不是现有 JSON 示例已经完成的能力认证。选择形状、权重与约束时兼顾参考可执行性和机制覆盖，不能根据哪种配置更容易让 PC 赢而选择。

### 6.1 共同数值与接口配置

核心任务优先使用 INT8 输入／权重、显式累加宽度和有限输出量化；每个算子明确中心化乘加、中间范围、Bias 的加入位置、舍入、饱和与激活次序。累加位宽通过合法输入和权重范围分析支持，不能因为叫 INT32 就假定任意 K 都不会溢出。

量化基本解释为 `real=(q−z)×s`，per-axis 参数按逻辑坐标索引而不是 lane。[E6] PC 2.1 的精确有理数转换／加法是本项目明确算法，不自动逐位兼容某个 LiteRT、FINN 或其他 kernel。[R2, §5] 核心先选能被实际 RTL 与工具实现的有限尺度范围；是否仅使用二的幂或小整数比必须在任务卡中公开，不能把这种选择写成通用量化支持。外部 kernel 语义采用独立命名 profile 和交叉验证，不与核心偷偷混合。

**三种“零”必须区分：** 数学 padding 的实数零，对 affine 输入通常编码为 zero-point；无效 lane 的物理填充 raw 0 必须由 mask 排除；普通有效 raw 0 仍按自身尺度与零点解释。oracle 的 packer 与模型说明应从同一公开规则出发，但实现需要独立交叉核对。

输入传输和输出传输统一按有效时钟边沿的 valid && ready 计数；所有附带数据与 token 一起保持。多调用不交织、结果顺序、复位取消和重新启动均明确。clock、reset、物理 ABI 与运行时数据不得被模型换成更方便的任务。

### 6.2 家族 A：量化 Depthwise→Pointwise

**计算对象。** 对一个输入特征张量执行深度卷积、规定的中间量化／激活，再执行逐点卷积及最终量化／激活。初始能力可限定 depth multiplier=1，kernel=3×3、stride=1；这些是开发起点，不是必须永久固定的所有正式实例。

```text
输入与合法权重
  → Depthwise 计算
  → 公开规定的中间数值转换／激活
  → Pointwise 计算
  → 公开规定的输出转换／激活
  → 输出流
```

结构来源为深度可分离卷积 [E1]。任务不要求产生完整 MobileNet，也不把输入图像的业务标签当作算子正确性判据。

| 任务卡字段 | 必须裁定的内容 |
|---|---|
| 数学 | DW 每通道核、PW 输入／输出通道映射、卷积采用的核索引方向 |
| 形状 | N/H/W/Cin/Cout、输出尺寸、padding、stride、depth multiplier |
| 数值 | 各阶段累加范围、Bias、量化尺度／零点、每通道参数、舍入／饱和／激活位置 |
| 资产 | 权重与 Bias 字节、排列、来源、公开交付方式和哈希 |
| 外部 ABI | 轴顺序、lane、尾部 mask、接受／完成与复位规则 |
| 环境 | 源可暂停性、输出停顿、连续调用、完成预算 |
| 实现自由度 | 内部模块划分、存储方式、资源复用和是否需要独立 repack |

内部前后阶段可以使用相同合法布局，不强制制造一个转换器。只有外部接口或真实复用约束要求不同布局时才将其设为硬义务。需要转换时，PC 显式表达关系，实际重排仍由行为实现和 oracle 验证。

验证至少覆盖：非对称空间／通道数据；不同输出通道的不同权重／尺度；非零零点；数值边界；公开支持时的非 lane 整除通道；padding 与 mask 区别；间歇停顿；连续调用和中途复位。全零与完全相同权重只能是部分边界用例，不能掩盖通道交换。

### 6.3 家族 B：量化残差计算块

**计算对象。** 主支路 F(X) 与跳跃支路 S(X) 在相同调用和逻辑坐标上相加，随后按任务规定输出。初始 S(X)=X，输入输出形状相同；主支路选定两段有限卷积及其数值边界。投影旁路或更深 bottleneck 只有在能力与参考资格完成后才可列入新的预声明层次。

```text
                ┌→ 主支路 F(X) ─────────┐
输入 X → 分发 ──┤                      ├→ 对应相加 → 激活／输出
                └→ 跳跃支路 S(X) ───────┘
```

残差结构背景来自 [E2]。函数 F、S、每次量化与激活的确切位置属于本任务，不能以“标准 ResNet”省略。

**数值义务。** 同编码相加必须处理零点；异尺度相加必须按冻结算法解码、求和和输出量化。`same_scale_centered_sum` 与 `exact_affine_sum_v1` 不可互换；两路先各自舍入再相加也不等于先精确相加后舍入。数据源、需求、PC 和 oracle 应对运算边界保持一致。

**事务义务。** 需要满足 `F(X)[n,h,w,c] + S(X)[n,h,w,c]`，并保持同调用配对。可采用严格顺序和计数器，不强迫硬件携带完整坐标标签。固定时钟延迟只有在公开停顿规则与实现确实保证对应关系时才合法。

**缓冲与完成。** 模型可以选择旁路容量、分发方式或主支路调度，不指定参考 FIFO 深度。任务要求在冻结环境条件下无丢失／重复、合法恢复并完成；有限仿真通过只能支持所测条件。FIFO 深度影响资源和活性，不能从 PC 的静态容量合法直接推导无死锁。[E5; R2, §8]

验证覆盖两路不同停顿进度、接收端长停顿后恢复、主支路启动阶段、连续调用、全部无命中／饱和边界、异尺度正负值、半帧复位和旧数据不可混入新调用。整体超时先记 bounded-completion failure；没有等待链证据时不能直接标为已证明死锁。

### 6.4 家族 C：分块 GEMM 加速子系统

**计算对象。** 完成公开定义的 `C = Q(A×B + bias)`，包含数据接收、有限存储／分块执行、完整 K 维归并与结果输出，而不是一个孤立 MAC。数据访问组织与状态协调以 [E3] 为工程参照，不复现完整 Gemmini ISA、CPU 或 SoC。

```text
A/B 接收与片上存储
  → 分块调度／乘加
  → 同一输出坐标的 K 维归并
  → Bias／最终重量化／激活
  → 有序结果提交
```

公开义务规定矩阵维度、转置和遍历、外部数据提供方式、存储上限、完成条件及数值顺序。K 分块若属于输入协议则必须明确；内部 partial-sum 总线是否存在、块尺寸与 PE 组织，在需求允许范围内由方法选择，不能强制所有实现暴露参考流水线。融合累加的合法实现不因没有显式 `reduce_sum` 模块失分。

对于显式部分和接口，PC 的 shape 表示输出坐标，reduction_axis 表示额外 K-group，groups 和 group_order 决定传输次序。每个输出累加在新归并开始时初始化，全部组正确到齐后只提交一次。Bias 添加一次；重量化发生在冻结边界，不能提前逐组舍入／饱和而改变最终结果。

初始核心优先采用有限顺序分块、片上存储和明确依赖，不强制双缓冲、DMA 或乱序。整齐 K 分组可作为初版支持域；非整除 K 的合法尾块必须有独立公开语义和实现资格，否则不把当前 PC groups 字段当成已经支持 ragged 分组。双缓冲后续启用时需定义最后读取、装载完成和所有权移交，不能仅添加 `bank_id` 宣称已解决。

验证覆盖多 K 组、不同坐标的非对称部分和、清零过早／过晚、Bias 重复、最后组提前提交、负数与溢出边界、输出暂停和连续矩阵调用。权重／B 是否固定、可运行时更新或与激活共用装载接口，必须按任务声明，不能由候选自选以简化任务。

### 6.5 开发算例与正式规模分开

| 家族 | 可用的首个开发算例 | 身份限制 |
|---|---|---|
| DW→PW | N=1、8×8、Cin=4、Cout=8、3×3 DW＋1×1 PW | 新提议的开发配置，不是正式任务或物理可行性结果 |
| 残差 | N=1、8×8、C=4、两段主支路与 identity skip | 先写完整数值、停顿与复位规则，不把图示当 oracle |
| GEMM | A 为 8×12、B 为 12×8；若采用 K=4 分块则有三组 | 不要求生成结果必须使用相同内部架构 |

这些参数用于启动闭环，不自动进入正式 hidden，也不证明能达到任何时钟／资源目标。正式配置通过参考实现、工具能力和输出容量分析决定。每家族既保留基本控制配置，也覆盖布局／数值／事务耦合；不为了制造方法差异一律选择最复杂情形。

## 7. Benchmark 构建、设计簇与留出

### 7.1 独立单位重新定义

采用以下研究身份；字段名是逻辑约定，落实时复用或版本化现有 catalog，不建竞争任务数据库：

```text
family_id
  └── design_cluster_id            # 独立需求／子图来源与实质义务组合
       └── semantic_instance_id    # 一个具体、冻结且可评分的任务配置
            └── replicate_id      # 同一方法的重复生成
                 └── validation_cases  # 同一工程内输入／停顿／复位用例
```

`design_cluster_id` 是主要依赖与重采样单位；原 `semantic_instance_id` 继续标识具体可执行任务，不再无条件等同于独立样本。来自同一基础模板／子图的尺寸、lane、权重替换和措辞变体应共享设计簇。仅变更 ID、作者、权重 seed 或文件数不能证明独立。

若多个簇仍共享同一参考模板的细小改动，建立更高层 `dependency_group_id`。同一来源跨家族重复出现时，须按共同依赖组协调抽样／重采样，或在正式前划分无交叉的来源簇。不能一边记录共享来源，一边在统计中按独立处理。

### 7.2 来源与覆盖

三类任务可来自：明确出处的模型子图与工程需求；独立编写且语义完整的研究配置；受控组合的开发与边界任务。每项记录来源、抽样框、是否参与方法开发及人工设计理由。

| 配置轴 | 设计目的 | 统计身份 |
|---|---|---|
| 外部布局／lane／尾部 | 检验 ABI 与有效元素映射 | 通常为同簇配置 |
| per-tensor／per-axis、零点、尺度 | 检验数值接口与运算边界 | 是否形成新义务簇须有依据 |
| 支路／分块／配置生效结构 | 检验状态与事务关系 | 可能改变设计问题，但不能自动宣称独立 |
| 形状、通道、K 维大小 | 覆盖执行规模与资源压力 | 通常为同簇配置 |
| 输入图像／矩阵／随机激励 | 验证一个工程的行为 | 不增加生成样本 n |

权重内容是公共任务资产，不是答案 RTL。固定非退化权重可用于算子工程研究，但不授予真实模型质量结论；采用真实模型权重时冻结来源、提取与量化流程。不得用测试成功率挑更好生成的权重。

### 7.3 三个开发与评测分区

**开发域：** 旧基础任务、已有 PC 示例以及用于 prompt／checker／lowerer 调试的 AI 任务。可迭代，永久记录开发暴露。

**排除式 pilot：** 新的非正式设计簇，运行冻结候选方法与预算，用于估计方差、配对依赖、失败、输出和工具成本；不进入主测试。

**正式测试：** 未用于生成侧调试的完整设计簇；其所有配置、改写、权重近重复与相关参考实现整体留出。评测方编写 oracle 不等于向生成侧提供参考，但需要区分人员／访问责任。

三类家族已参与 PC 2.1 设计，默认只主张已知机制上的需求／组合／配置留出，不主张模型预训练未见或严格 family-held-out。正式前审计需求、RTL/AST、接口、子图来源和组件图近重复；阈值和处理规则预先固定。

### 7.4 避免人为偏向 PC

任务必须有真实计算与接口义务，不以“能触发某个 checker”为唯一入选理由。接受合理的内部融合、统一布局、不同 FIFO 和合法数值实现；只有公开契约确实要求时才限制结构。Direct 获得同样的事实表、量化算法、公开资产与接口说明。

采用共同的外部输入／输出评价；内部信号名、模块数量和 PC 关系条数不能成为跨方法正确性的秘密判据。模块划分的可观测性差异单独报告，不因某方法显式写了更多模块就默认拥有更多一致性问题或更多机制信用。

### 7.5 任务资格与不能降级的规则

正式前，每个实例须有完整公开任务、独立参考、协议／时间监测、正确参考路径、缺陷检出资格和工具配置。若任务本身不自洽、参考不支持或约束不可行，在看到该正式任务模型结果前按预定规则修订／排除，保存理由与流转表。

正式方法产生不支持的架构、超限 PC 或过大 body，属于该方法在既定任务上的失败，不可回写任务为 capability_gap 从分母删除。三个家族均须完成资格才能宣称“三家族基准”；不足时在正式前降低研究范围并建立新版本，而非结果后静默去掉一个家族。

## 8. 独立 oracle 与验证协议

### 8.1 数学、数值与事务三条验证线

| 验证线 | 判题依据 | 关键产物 |
|---|---|---|
| 算法／位精确 | 从公开任务独立实现的整数／有理数或指定 kernel 参考 | 完整输入到输出的期望值 |
| 协议／事务 | 公开 ABI、接受事件、mask、调用边界、复位与完成规则 | 接受记录、scoreboard、丢失／重复／错配证据 |
| 时间／资源 | 公开环境下周期要求、指定综合／目标约束 | 周期统计、超时、映射与物理报告 |

浮点模型可作算法交叉核对，但不能替代冻结整数舍入和溢出的 oracle。PC2.1 的 tensor_reference 辅助函数不能成为 checker、生成器和最终 oracle 共同且唯一的答案实现。通过独立实现、手工可解析小例、全域或边界整数用例和适用第三方 kernel 的交叉验证建立信任；不要求所有复杂算子都穷举。

### 8.2 Oracle 资格

正确参考工程必须在所有计划配置和 suite 中通过。人工变异覆盖布局／lane、scale／zero-point、per-axis 参数、padding／mask、错配、部分和、复位和提前终止等类别；等价、不可执行与未检出变异分开记录。局部 schema 错误、声明不匹配、真实 RTL 行为变异分别计数，不能用大量简单拼写错误抬高语义检出成绩。

资格报告说明覆盖、已知盲区与版本，不把 mutation score 称为完备证明，也不把人工变异率称为自然 Agent 失败率。基础设施异常或 oracle bug 不能归因为生成模型能力。

### 8.3 Public 与 hidden

Public 提供冻结 smoke／边界测试和受控诊断，可供修复；hidden 使用独立保留的定向、固定随机、停顿／复位及适用真实负载用例。二者检查同一组公开义务，不能出现 hidden 才规定的数学或接口规则。

所有核心、已纳入第二模型／Agent／消融／probe 的终止候选或无候选状态按研究分组完成封存后，经过预定义批次屏障再开放相关 hidden 结果。屏障等待计划位置闭合，不等待全部成功。不得通过其他方法、案例或人工观察把隐藏结果送回生成侧。

每个预声明评分槽最多提交一次语义结果；一个固定 suite 可以包含多个用例，不等于允许多轮候选选择。suite 的完整运行／提前停止策略预先确定，未执行用例保留未观察，不记作通过。

### 8.4 标准不能由候选提供

候选 testbench、`TEST_PASS`、进程提前 `$finish` 或退出码为 0 不构成语义通过。受信 harness 核对预期事务数量、结束条件和全部适用输出；不能让候选脚本选择源文件、删测试或放松时钟。

主评分不要求 Direct 暴露与参考相同的内部信号。需要内部定位时，使用预声明、方法中立的观测策略或只读调试副本；说明影响范围，不以调试改动后的输出替换原候选成绩。后验根因研究单列，不通过增加 hidden 调用给原方法新成功机会。

### 8.5 核心测试内容

每家族包含常规正确性、非对称位置／通道数据、正负边界与舍入临界值、多个调用、适用 reset 中断和停顿恢复。DW→PW 加入窗口／通道与 per-axis；残差加入支路进度与同坐标配对；GEMM 加入多 K 组、Bias 一次和最终提交。

用例用于区分真实错误，不以设置不可能环境或未公开恶意输入惩罚模型。仿真超时是约定预算下未完成，只有额外证据支持时才进一步归类为死锁。

### 9.1 研究问题

| 编号 | 问题 | 证据地位 |

| RQ1b | 同一个生成 PC 下，确定性构建／受限编辑是否改善结果？ | M4−M3，主要确认性比较 |

### 9.2 唯一方法表

| 方法 | 首发阶段 | PC／构建权限 | 修复与主要终点 |
|---|---|---|---|
| M0 Direct | 一次生成完整工程提议 | 不要求 PC，无结构构建器 | 无修复；@initial |
| M1 Direct-Repair | 共享 M0 的初始尝试 | 同样无 PC 要求／构建器，可使用公共工具 | 总预算内自由工程修复；@B4 |

| M5 PC-Online | 共享 M4 初始 PC／完整工程或失败 checkpoint | 可修 design 或行为，不能改需求 | 与 M1 相同总预算；@B4 |

M0/M1/M2 的 H-stage 为 not_applicable，不按失败处理。M3/M4 的共同 PC 失败也属于各自端到端失败；PC 合法条件下的结果可另报，但不能替代全分母。

### 9.3 比较能解释什么

M5−M1 是完整表示、生成、诊断与编辑策略的系统比较，不是纯 repair-policy 效应。M4−M3 在相同 PC 与检查机制下，联合改变确定性构建和编辑边界；不是纯 skeleton 文本或“张量检查单独有效”的效应。M3−M2 改变表示、提示、检查与长度，只作为联合表示比较。

M1−M0 与 M5−M4 描述追加公开反馈机会的增量，包含修复能力与额外计算，不能说为零成本的策略提升。M4−M0 可作为简单参考，但不能只因为两者总上限相同就声称实际初始计算相同。

### 9.4 公平信息与模型选择

所有核心方法共享冻结模型／推理配置、公开事实、数值规则、权重、ABI、公共工具与全局预算政策。格式与工具权限的差异只能是预声明 treatment；不向某分支额外给标准 PC、参考 RTL 或人工提示修正。

主模型选择依据开发域的可执行性、能力与可核验计量，不限定必须小模型、开源模型或某块显卡；也不根据正式结果挑最有利模型。模型权重、版本、量化、上下文和 decoding 固定。持久答案缓存、跨任务经验检索和 family recipe 核心默认关闭；通用语法说明和开发示例提前固定。

Schema 在未明示时只是验证器，不自动启用受限解码。若采用结构化输出／logit masking，必须作为显式方法配置，给其他分支相应可用的输出格式支持并解释剩余差异；不能在看到格式失败后只给 PC 分支加自动 JSON 修复。

## 10. B4、共享起点、终止与完整成本

### 10.1 B4 是候选实验预算，不是方法的永久性质

新 AI 核心的首选配置为：M1/M5 最多四次逻辑模型调用、最多四个公开完整检查周期，并受共同累计输入／输出 token、单次输出、上下文、工具子调用、CPU／内存／活动时间与 EDA 预算约束。M0 最多一次；M2/M3/M4 每个声明阶段最多一次。

| 方法 | 正常前置调用 | 剩余调用机会 |
|---|---:|---:|
| M1 | Direct 生成 1 | 最多 3 次工程纠正／替换 |
| M5 | PC 规划 1＋批量行为生成 1 | 最多 2 次 design／行为纠正 |

PC 先失败时 M5 按实际已用调用计算余量，不能再给 PC correction 和 RTL repair 各发一份预算。相同工程多模块不免费拆为多调用；调用输出不完整也计费。

具体 token／超时必须在 AI 开发测量后、排除式 pilot 前填实。若 B4 与必要输出或工具测量不适配，可以在任何新 pilot／正式结果前统一改为另一命名预算并版本化；不能在正式过程中临时改 B8、提高输出长度或只放宽一个分支。主要结论仅覆盖最终冻结配置。

### 10.2 共享 DAG

```text
S_D：Direct 首发 ───────────────→ M0、M1
S_C：PC 规划＋共同检查 ─────────→ M3 自由生成
                  └→ S_B：构建＋批量行为 → M4、M5
U_P：M2 无类型计划 ─────────────→ M2 自由生成
```

共享对象包括失败：非法 PC、缺完整工程和已完成 FPP 分别有 checkpoint。有效 PC 但尚未生成工程只是规划产物，不伪装为工程。共享前置成本完整归因给每个消费者；M5 后继 PC 不回流 M3/M4，M1 修好工程不回流 M0。

按依赖图中的可执行节点分块随机化与平衡顺序，使用独立本地 schedule seed。provider decoding seed 单独记录，不因为 replicate_id 相同就声称共享实现随机流。主模型不支持可验证 seed 时可使用冻结配置的 stochastic_blocked，不能因此自动否定研究，也不能声称逐位重放。

### 10.3 终止与最后候选

修复方法在最早满足冻结公开接受谓词时停止；否则在资源边界处选择最后一个完整且边界有效的候选，没有则 terminal-null。公开谓词涵盖共同 FPP/L0、指定 L1、public L2、预算内 L3 和适用编辑保护。

空补丁、重复代码、被拦截的越界修改消耗调用，但不产生有效修复 transition，也不自动触发未经冻结的 NoProgress 提前停止。实际破坏受信文件与被成功拦截的提议要分开。

没有完成最后公开检查的候选可以封存，但不能自动获得 pass；固定的最终只读检查可补齐必需证据，作为最终验证成本，不反馈模型，不挑新候选。同候选、同 suite、同工具的有效公开报告可以按冻结政策复用，不免费增加检查机会。

### 10.4 三种成本视图

**实际去重成本：** 原始事件按身份计一次，反映本次 campaign 实际消费。

**独立运行归因成本：** 每个方法承担完整前置依赖及后续事件，主要系统比较使用此视图。不能因共享而给 M4/M5 免费规划或仅向最先运行者收费。

**增量成本：** 从预声明共同 checkpoint 之后计算，明确比较边界，只解释相应追加阶段。

核心 B4 全部路径可执行时，每完整配对块最多 11 个实际去重逻辑调用、15 个六方法独立归因调用；共享初始分别为 6 和 10，M1/M5 正常追加最多 3＋2。失败路径由总预算自动推导，不对跳过阶段仍计假调用。此处不是 API 请求数；transport、工具、hidden 与 L4 另行记账。[R3, §10]

成本表必须覆盖失败者；较低均值若来自更多提前失败，不等于更高效率。费用计量、服务时间、排队与独立端到端时延分开；并行服务时间相加不冒充真实 wall-clock。离线任务、oracle、构建器和数据处理投入单列，不能暗记为某个方法的在线优势。

### 10.5 预算不确定与重试

操作先预留再分派；确定未分派可以释放并留记录。远端执行状态不明确时记录 unknown；只有真实幂等机制可重取同一请求，不能用网络重试免费获得新样本。再次问模型修 JSON、补文件或解释错误都消耗新调用。

`budget_status` 区分 compliant、exceeded、unverifiable。计量缺失不是真实超限证明，也不能当成合规。语义结果继续保存；无法核验配对预算时不支持等预算优势声明。上下界或预留上限可以安全限制后续调用，但不能冒充实测 token。

## 11. 结果指标与一致性错误分析

### 11.1 主终点：VPP-L3

同一终止候选在共同 FPP／外部接口、L0 工程一致性、指定 L1、public L2、一次独立 hidden L2、指定 L3 均通过，且没有实际边界／来源／预算违规，才具有相应 VPP-L3 通过证据。PC 额外 H 检查不是所有方法共同准入条件。

L3 必须命名实际工具、脚本与 mapping 深度：generic cell 数不叫 FPGA LUT。L3 成功只关闭该阶段已验证的义务，不证明 L4 时钟、板级运行或所有应用条件满足。

记录工程结果与预算／完整性资格两个维度：仅有 token 缺失，不重写已观测的功能结果为失败；但等预算确认性主张需要可核验性。资源上限内生成失败、输出不全、功能错误、不可综合或候选导致的超时为设计失败。可信构建器 bug／工具环境失效导致无法评分则是基础设施问题；实际泄漏／评分槽破坏是完整性问题，不按普通模型失败抹平。

### 11.2 必须报告的指标

| 维度 | 指标与边界 |
|---|---|
| 端到端 | 各方法 VPP-L3@initial 或 @B4、分家族与三家族宏均值 |
| 阶段 | H0–H3、L0/L1/public-L2/hidden-L2/L3 的状态、首失败阶段、转移 |
| 一致性 | 结构、声明语义、实际事务／数值错误，及无法归类比例 |
| 修复 | 纠正调用、合法非空修改＋重跑、公开接受、最终隐藏结果 |
| 成本 | 全分母 token／调用／工具／时间／缺失及三视图 |
| 公私差距 | public 接受者中的 hidden 失败与完成情况 |
| 实现负担 | 构建来源、受保护结构和模型行为责任；不以代码行数代替问题难度 |
| 物理 | 预选全分母 VPP-L4、L3 存活者条件结果、资源与约束范围 |
| 外部效度 | 模型来源、设计簇／配置、真实负载／模拟输入身份、明确未验证项 |

### 11.3 统一错误分类

| 类别 | 典型证据 | 不应混淆 |
|---|---|---|
| 结构／工程 | 端口、引用、驱动、参数、依赖错误 | schema 格式错不等于算法错 |
| 张量声明 | 同位宽不同轴序、lane／mask 或 shape 矛盾 | 声明一致不代表真实顺序正确 |
| 数值声明／实现 | scale／zero-point、per-axis、Bias、舍入边界错误 | 只有最终数值差异时不直接认定错在接口 |
| 对应事务 | 丢失／重复、同坐标或同调用错配、复位污染 | 模块名或静态关系条数不是行为证据 |
| 部分和／状态 | K-group、初始化、累加、提交或装载生命周期错误 | 局部乘法错与归属错分开 |
| 有界完成 | 启动／稳态停滞、约定环境下超时 | 超时不自动等于已证明死锁 |
| 局部算法 | 核索引、乘加、激活等模块内部实现错误 | 不强行包装为跨模块一致性 |
| 非模型原因 | 工具、oracle、runner、绑定或完整性故障 | 不计入自然模型缺陷率 |

静态错误来源使用固定规则与原始诊断；真实行为根因采用方法盲审或冻结定位规则，保留 confirmed、suspected、unclassified 及依据。一次输出差异可以触发多个假设，但不能让同一事件反复计为独立缺陷。前层失败导致后层不可观测时标 not_observed，不记零错误。

如果 M4 强制更多显式关系，可能更容易定位错误；因此跨方法比较不能只比较“被 checker 命名的错误数量”。共同外部功能终点是主标准；错误观察覆盖和不确定性必须并列报告。

### 11.4 公共／隐藏差距与过程曲线

```text
HFPA = N(public_accepted AND hidden_completed AND hidden_failed)
       / N(public_accepted AND hidden_completed)
```

同时报告公共接受总数、隐藏完成率、基础设施未知及最坏／最好界限；分母为零时记未定义。不同方法的条件人群可能不同，不能把 HFPA 差直接当作修复泛化因果效应。

只有终止候选获得 hidden 分数，不画未经观测的隐藏收敛曲线。可报告首次公开接受成本与公开阶段进展；失败者在预算边界截尾，不能把“首次公开接受”改名为“首次真正正确”。

## 12. 统计设计、开发诊断、pilot 与规模

### 12.1 两个主要估计量

令 f 为三个家族，i 为设计簇，j 为该簇的冻结配置，r 为重复，m 为方法。`Y_fijrm` 为相应终止 VPP-L3。对 X−Y，先保留相同配置／重复的配对差，然后按预声明配置权重和重复平均：

```text
D_fi(X,Y) = sum_j w_fij × mean_r(Y_fijrX - Y_fijrY)
Delta_f   = mean_i D_fi
Delta     = (Delta_DW_PW + Delta_Residual + Delta_GEMM) / 3
```

默认簇内配置等权、家族内簇等权、三个家族等权；不同分配须在结果前冻结。不能让配置多的簇或图像多的任务主导均值。

主要终点为 `Delta_system=M5@B4−M1@B4` 和 `Delta_build=M4@initial−M3@initial`。它们估计所选三家族、抽样框、模型及预算下的差异，不是所有未来 AI 家族的总体效应。

### 12.2 最小有意义效应与检验

本版为完整计划提供以下**建议科学规划值**，取自旧计划的候选值但必须针对新 AI 总体重新采纳。它们不是已知效果、不是样本量充分性的证据；需要改动时在新 pilot 前完成书面版本化，不依据 pilot 的处理效应修改。

| 比较 | 最小有意义效应 δ | 用于功效设计的备择 Δ* | 科学解释 |
|---|---:|---:|---|
| M5−M1 | 0.05 | 0.15 | 系统复杂度应换取非微小的端到端增益 |
| M4−M3 | 0.03 | 0.10 | 检验共享 PC 后较局部构建／编辑增量 |

检验 `H0: Delta <= δ`，两项同属单侧 familywise α=0.05 的 Holm 族；报告原始与调整 p、两侧 95% 区间和负方向结果。单个对比通过只支持对应结论；两者均通过且信息／预算／完整性条件成立才提出组合优势。两侧区间默认不是经多重比较调整的同时区间，不拿它们重复增加未经说明的门槛。

若规划价值判断改变，可以在新 pilot 前改为估计性研究或修改阈值并解释；不能在正式结果后改成只检验大于零。功效必须在 Δ*>δ 处设计，不能宣称在零假设边界 δ 达到 80% 功效。

### 12.3 聚类与统计实现

默认在家族内对完整独立设计簇重采样，保留该簇所有配置、方法与重复及两个对比的协方差；使用预先验证的 studentized cluster bootstrap、边界零假设居中、固定分析 seed 和建议 19,999 次重采样。若存在跨家族依赖组，按整体依赖组协调重采样并固定家族目标权重；不得仍按家族独立抽样。实际实现和抽样设计应先在模拟数据中验证，复杂依赖不应被一个方法名称掩盖。

配置、replicate、权重 seed、测试图像和随机激励不作为独立 bootstrap 单元。簇数很少、方差为零、极少配对分歧或某家族只有一个可辨识来源时，保留原始结果与有限描述，不伪造精确 p 值或沿用渐近区间。只有三个固定设计时，定位为三案例研究。

功效／精度模拟应覆盖配对分歧、簇内相关、两个对比相关、失败／缺失和保守情形。若计划保留组合主张，目标联合统计功效至少 0.80，同时报告边际功效。完整性错误不是随机“普通失败率”参数，不能假设一个概率来提高表面功效。

### 12.4 缺失与资格规则

所有冻结位置先从 manifest 创建，随后左连接结果。已确立设计失败为 0；无充分设计失败证据但必要步骤因基础设施不可判断为 NA；不适用不按失败。实际完整性破坏停止受影响范围与声明，按预定规则保留失效记录，不能简单改作 NA 后继续比较。

主要描述给出全分母上下界。确认性默认采用比较方向的保守未知赋值：未知 X 为 0、未知 Y 为 1；这是分析界限，不改写底层语义状态。另报相反界限与完整配对敏感性；该组合推断须先在预声明情形的模拟中检查错误率表现。不能只删除“不好分析”的未知行。

候选缺失上限建议仍为单方法 5%、主要比较两侧差异 3 个百分点，须在新 pilot 前重新确认。超过时保留结果但不提出对应确认性优势；不通过删样或放宽阈值恢复声明。成本未知与工程未知分开；主预算轴不可核验且无法重建时，等预算确认性声明停止，即使观察成功率可继续报告。

### 12.5 分阶段规模：不沿用旧四家族的 30×3 结论

| 阶段 | 规划规模／形式 | 用途与限制 |
|---|---|---|
| 开发诊断 | 可从 3 家族×2 开发配置×3 重复的 18 次 Direct-Repair 开始 | 可调试；观察自然错误，不是 18 个独立设计或正式方法比较 |
| 排除式 paired pilot | 3 家族×4 新设计簇×1 配置×2 重复×6 方法＝144 个方法结果 | 12 簇、24 配对块；估计干扰参数，不能宣称方差估计已精确 |
| 正式核心 | 3 家族×n 簇／家族×c 配置／簇×r 重复×6 方法 | n、c、r 由新功效／精度与成本分析冻结 |
| 第二模型（规划次级） | 预选每家族 6 簇×1 配置×2 重复×M1/M3/M4/M5＝144 个方法结果 | 18 个设计簇；不同模型家族，独立结果分组 |
| 原生 Agent（规划次级） | 预选每家族 3 簇×1 配置×2 重复×C0/C1＝36 个 Agent episode | 9 个设计簇；仅描述性系统比较，不用 B4 外层次数替代计量 |

开发诊断可以先少量试运行以调试工具，18 是建议上限结构而非必须跑满的正式矩阵。用于调试的实例和参考不得流入正式测试。paired pilot 一旦开始按冻结矩阵运行，不因方法效果负或失败率高而只补容易样本。

**正式容量算例，不是确定样本量：** 取 n=20、c=2、r=3，则有 60 个设计簇、120 个具体任务配置、360 个配对块、2,160 个方法结果；最多 3,960 个实际去重逻辑调用、5,400 个独立归因调用，不含扩展／transport／工具。总 episode 数碰巧与旧计划相同，独立单位和估计对象却不同，不能继承旧功效结论。一般公式为 `blocks=3ncr`、`method_results=18ncr`、核心调用上限 `11×blocks / 15×blocks`。

最终 n 不强制等于 20 或 30。若可获得独立设计簇不足，减少声明强度；增加配置和重复可降低某些测量噪声，但不能制造新的需求独立性。

### 12.6 冻结顺序

开发阶段先确定可行任务范围、模型、单次输出、工具流程和候选预算；WP3 在 paired pilot 前固定方法、信息、δ／Δ*、缺失规则、pilot 矩阵、分析算法与估计目标。pilot 只估计干扰参数和资源需求，WP4 再锁定正式样本与全部实际执行值。

如果 pilot 后需要实质改变方法、checker、提示、数值语义或预算，形成新候选协议与新的排除式 pilot；不将修改前后结果合并为同一条件。正式模型或 hidden 结果开放后不扩样、换家族、挑模型或改终止规则。

## 13. 机制研究、外部基线与原生 Agent 对照

### 13.1 相关工作的比较粒度

| 相关工作／工具 | 本次核对的直接相关能力 | 本研究不能据此宣称的内容 |
|---|---|---|
| HORIZON [E7] | 将硬件设计作为仓库级演化，包含项目包、工具评测与迭代 | 不能以“第一次自动跑工具／修 RTL”作为贡献；M1 不等于原协议复现 |
| CPPL [E8] | 类型化／可检查的电路表示，经确定性路径 lowering 到 CIRCT | 不能只以“加 JSON IR 和构建器”宣称新颖 |
| HINT [E9] | 显式硬件意图、RTL 前检查及 lowering 义务 | 需要具体说明张量／事务边界、生成责任与实证增量 |
| FINN／hls4ml [E4–E5] | 量化数据流、打包与缓冲处理的已有工程路线 | 神经网络到硬件本身不是新问题；成熟编译器可作工程参考，不自动是相同输入的 LLM 基线 |
| Codex [E10] | 非交互运行可记录命令／文件等事件，并支持 schema 化最终输出 | 不能把通用 Agent 当作只生成一次文本；日志和 JSON 不是本方法独占能力 |

本轮对 E7–E9 只核对摘要页的定位，不搬用其成功率横向排名，也不声称完成系统综述或证明本研究最新／首次。外部实现若纳入可执行对照，需冻结其版本、输入翻译、支持范围、人工适配和工具／预算条件；无法公平运行时报告原因，不用原论文数字充当本 benchmark 对照。

### 13.2 错误机制的主分析

将 M0–M5 的完整结果与共同错误分类对应，观察三件事：结构／声明错误是否提前消除；这些减少是否转移为更多 hidden 行为错误；成功率变化是否值得额外成本。人工 PC／RTL 变异仅用于检查器和 oracle 资格，不证明模型自然容易犯这些错误。

必须保留 `compute` 或融合实现导致的有限可观察性。PC 字段数量、拒绝率和关联覆盖不能单独成为机制成功指标；实际成功率、错误证据与构建来源共同支持解释。

### 13.3 张量语义检查消融：可选且不能偷换主比较

若论文拟提出张量／量化检查的独立因果贡献，应在结果前设计 A_tensor_on／A_tensor_off 子实验。一个可行方案是共享同一未经该检查筛选的初始 proposal，保持公开事实、模型、结构构建、编辑范围、工具和预算不变，仅控制指定语义检查／诊断是否参与纠正。

两侧共同保留安全、JSON 和真实构建所必需的基础类型规则；需要禁用的检查不能同时承担 ABI 生成的必要计算。若关闭某检查使任何后端都无法解释对象，说明该方案同时改变了支持域，不能称纯诊断消融。可以改为仅控制语义诊断的暴露并明确其估计对象。

本稿不默认启动此实验，不新增主 Holm 假设。没有这一独立对照时，只提出完整机制组合的证据，不把 M4−M3 说成 tensor checker 的单独收益。

### 13.4 自然失败修复 probe

从冻结 M4 的公开自然失败中按预先阶段优先级和随机平局规则选择，每家族建议最多 3 个独立设计簇，每簇一个 checkpoint。两分支 R_generic／R_PC 获得同一 PC、FPP、公开需求、原始公共诊断、模型和编辑范围；R_PC 只增加可追溯的义务关联与重检依赖。

建议每分支最多 2 次纠正与 2 个公开检查周期，其他预算等价冻结。没有足够自然失败如实报告，不注入故障补齐，不据 hidden failure 选择。它是条件于选择人口的描述性机制研究，不能替代 M5 成功或证明整体修复率。

### 13.5 原生通用编码 Agent 子实验

这是优先规划的次级系统对照，解决“合理配置的成熟 Agent 已经能做到什么”。在 WP3/WP4、任何相关结果之前决定是否纳入；没有完成时，论文不得声称优于 Codex 产品。

| 条件 | 基础环境 | 额外机制 |
|---|---|---|
| C0 Native-Direct | 完整公开任务、合理 FPGA 指导、同工具与公开 harness、受保护 hidden／目标配置 | 自主规划、编辑和工具迭代，不强制 PC |
| C1 Native-PC | 同一 Agent 引擎／模型／基础指导与任务／工具 | PC2.1 检查、确定性结构构建和受控行为装配 |

两者共同获得全部公开事实，不能只给 C0 一句短提示。PC 权限与结构约束是 C1 的 treatment，不要求 C0 模仿其受限策略。尽可能固定同一引擎、模型、版本和计量方式；无法控制的差异明确列出，只作系统级比较。

**原生 Agent run 不是核心逻辑模型调用。** 官方文档的一个 `codex exec` 会话可包含多种事件及工具操作。[E10] 外层执行四次不能等同 B4；应冻结可实际核验的 token／工具／活动时间等预算，记录内部推理与 turn 的可见范围。计量不足时不声称等 FLOPs 或与 M1/M5 完全等调用。

C0/C1 使用独立 population／condition、唯一终止槽和相同外部 oracle。分开报告不与核心均值混算；第二模型、原生 Agent、消融可选项不要求全部同时启动。优先做核心闭环和一个能回答关键质疑的对照，不扩成对多个 Agent 产品的排名项目。

## 14. FPGA 物理证据与工作负载来源

### 14.1 L3 与 L4 的工具资格

开放工具流是复现优先路线：指定 lint／RTL 仿真／Yosys 综合及经资格验证的 OpenXC7／布局布线路径；工具、器件、封装、速度等级和版本以实际环境为准，不从历史板卡或旧报告推断。可用 Vivado 对同一候选做代表性参考，不将其设为期刊强制规定。

AI 权重、存储读延迟、DSP／BRAM 意图、mask 和数值转换都需要实际映射证据。工具不支持某种合法算术时，在能力与任务资格阶段明确，不能执行后偷换舍入或数值结果。没有真实活动率及明确方法不报告功耗。

### 14.2 三家族的预选物理子集

建议每家族预选 3 个正式设计簇，每簇 1 个固定配置，replicate 1，覆盖 M0–M5 全部对应终止位置：共 54 个物理评测位置。这是新三家族的描述性起点，不是实际 route 次数或功效充分性结论。参考路径须事前证明所选配置可测。

选择依据为不同机制、规模与参考工具可执行性，先于模型结果；不能只选已通过者。进入 L4 要求同一封存候选完整 VPP-L3 通过。未进入的设计失败、基础设施缺失或资格原因留在原 54 个位置的分母，不能用别的成功候选替换。

报告全分母 VPP-L4 和 L3 存活者条件通过率，逐家族列资源、目标时钟、slack、工具支持的原生频率结果、实际路径覆盖、源码／网表／约束哈希及成本。未分析 hold／I/O 等范围不能标通过；OOC 内部时序不等于板级闭合。L4 失败不改写已经成立的 L3 功能事实，也不进入核心修复循环。

### 14.3 真实负载是独立证据维度

核心可以使用非退化人工权重／激励研究算子工程正确性；真实模型子图／固定权重／实测或数据派生激活用于增强来源和外部效度。三种身份分开：研究者定义的数学任务、有出处的模型子图、实际采集的运行负载。

真实样本不要求相机、DDR 或上板即可在 RTL 仿真中回放，但必须冻结来源、选择、预处理、量化、布局和哈希。数据标签不自动成为位精确 oracle；没有端到端网络与任务指标，不能宣称分类／检测准确率改善。

本版不再以 MVTec／Sobel 缺陷检测案例作为独立核心前提。真实负载来源按三个 AI 子系统需要选择，未实际处理前不称已加载。公共权重对所有方法等价提供；具体隐藏输入、期望值和 suite 编排与生成域隔离。

### 14.4 平台与应用声明

未来可接入可信固定 host／DMA／相机接口，但必须标明平台与生成子系统的边界；平台基础设施不计作模型生成成果，公共组件机会对方法等价。

板级执行、bitstream、端到端时延、能耗和应用质量均需独立协议。核内周期、数据搬运和总运行时间分别测量。核心只报告具备证据的算法符合、负载回放、综合映射与有限物理范围，不能由任务名称推出“真实可部署 AI 加速器”。

## 15. 执行边界、评分槽与证据管理

### 15.1 简单控制架构

默认采用模块化本地控制程序、受限模型网关、独立 public／hidden／physical worker 和离线分析器，先串行或有限并发。不是多个 Agent 自由协商，不先建微服务／消息总线或复杂授权数据库。

生成域只见公开投影、自己的候选和允许公共诊断；hidden 原始材料、参考实现、运行时答案生成器、无关仓库和密钥不挂载到候选。目录分开或 Python 类名不同不等于隔离，要验证真实读写／执行权限。[R3, §§2,13–15]

### 15.2 不可信 FPP

所有候选使用声明式 manifest，可信 launcher 决定编译源、顶层、工具与约束。候选脚本不直接成为评测入口。检查路径、符号链接、依赖闭包、绝对 include、层次窥探、DPI/FFI 和系统调用等攻击面；正常初始化数据只允许访问已声明并核验的公开资产。

真实负载经受信 harness 输入，不把 hidden 文件路径提供给 DUT。模型输出与工具日志中的文字当作数据，不能改变指令、权限和 budget。边界保护需覆盖编译后实际依赖，不只扫描几个关键词。

### 15.3 唯一评分槽

```text
HiddenSlotKey = (
  campaign_id, population_id, semantic_instance_id,
  replicate_id, condition_id
)
```

设计簇身份保存在实例映射中；同一槽预先固定候选 hash、任务／suite／工具配置。候选 hash 不是可以通过换候选来新增槽的主键。同槽换候选或换 suite 必须拒绝；不同模型、probe 或原生 Agent 条件只有预声明的独立身份。

`hidden_execution_status = completed | not_run | infrastructure_error | integrity_error`；`hidden_semantic_status = pass | fail | null`。completed 恰好对应一次语义提交。无候选以 not_run／null 闭合，上游失败仍在分母；基础设施重试仅对同候选同配置，提交后只能读取旧回执。

### 15.4 恢复与原始事件

原始响应、PC／候选快照、诊断、修改和实际重检以不可覆盖对象＋追加事件保存；summary 由事件重建。事件区分来源 natural_model／synthetic_fixture／reference 与错误原因，不用一个 `failure_origin` 承担两种含义。

模型响应已落盘但事件未完成时恢复提交，不重复请求；远端状态未知不盲目采样；新候选未完成保留旧完整候选；共享节点恢复只读复用；hidden 提交回执丢失读取原结果。本地幂等不承诺远端 exactly-once。失败恢复不重新发预算。

### 16.1 第一个可交付闭环

先完成一个开发 DW→PW：公开任务与合法资产→独立位精确参考→可信 ABI／结构→真实模型的 PC／行为→公共失败诊断→预算内修复→独立终止评测。用自然失败检验真实修复；只有人工注入失败时这样标注，不强求通过破坏任务制造自然 transition。

开发阶段可调整任务、工具和方法，但保留版本并把暴露对象永久留在开发域。不要求先完成全部三家族、原生 Agent、完整 oracle 发布或 EA 才能第一次调用真实模型。最低安全前提是公开域、预算硬上限、受信文件保护和基本事件，不增加无关治理门槛。

### 16.2 完整三家族的进入条件

正式前，三个家族均须具备真实可执行参考、共同 FPP／suite、自然模型数据闭环与可辨识失败来源。pilot 不要求 PC 优于 Direct 才算可继续；效果小或负会影响研究选择与功效，但不构成删数据理由。

任务缺资格就修任务／参考，不让 emitter 凭空补算子；支持域过小就明确修订范围，不拿模型失败说明任务本身不合法。仍不足以形成 benchmark 时，在正式前转为有限案例或估计性研究，不能只减少样本后保持原有强声明。

### 16.3 模块边界建议

实现沿用新 SPEC 的 `requirements / pc / build / methods / execution / gateway / accounting / storage / workers / analysis` 分工。张量规则属于 pc，ABI 展开属于 build，独立 oracle 属于 evaluator，不让方法侧导入答案库。现有纯函数和工具封装可以重新验证后复用；没有兼容要求不等于必须删除所有旧实现。

全量重建优先于复杂缓存；文件／单元替换优先于复杂协同 Agent。每个新增模块必须对应方法机制或可解释风险，不为了“完整平台”先创建大量空目录。

## 18. 风险、反例与预先处理

| 风险 | 可观察信号 | 处理与允许解释 |
|---|---|---|
| 方法比问题更复杂 | 主要工作是新增 manifest，真实闭环迟迟没有 | 优先 WP1/WP2；关闭扩展不建设空依赖 |
| 新增字段只产生表面一致 | checker 通过但 hidden 同样失败 | 报告语义与行为差距，不用静态通过替代终点 |
| PC 前置失败抵消收益 | H-stage 失败多、下游候选少 | 保留端到端分母，判断表示成本与能力边界 |
| 强基线已足够好 | Direct-Repair 高成功、差异小 | 保留负结果；不在正式后添加刁钻任务 |
| 基线被不公平限制 | Direct 缺数值事实、不能局部修改或预算无法使用 | 同一事实投影和可用机会；记录 §5.4 文件级修复修订 |
| 构建器藏入答案 | 自动生成 Conv／FIFO／算术控制 | 禁用或单列公共库干预，不能当结构效果 |
| 为张量检查强制错布局 | 实际可统一布局却要求必经 repack | 接受合法统一布局，只有公开接口义务才限制 |
| 类型擦除或粗 compute 绕过 | 输出正确但许多关系无静态信用 | 不强迫参考拓扑；如实报告覆盖和有限解释 |
| 定点数学不对应 RTL | 精确有理数算法与实际中间截断不同 | 冻结可实现算法和 kernel profile，独立位精确核对 |
| oracle 与 checker 共用错误 | 同一辅助函数产生全部答案 | 独立实现与解析边界例，区分参考复用责任 |
| 有界超时误称死锁 | 没有等待链却归因活性 | 只报告 bounded-completion failure，根因不明保留 |
| 伪独立样本 | 大量尺寸／权重变体来自一个模板 | 设计簇／依赖组聚类；不足则降低泛化声明 |
| 方法开发污染测试 | 已有 AI 示例被当未见家族 | 整簇隔离，承认已知机制和实例留出 |
| 任务过小或仅硬编码权重 | 只跑零输入或固定输出也能通过 | 非退化权重、输入域和多调用独立验证；公开完整义务 |
| 物理证据被外推 | L3／OOC 被写成上板或 PPA 成功 | 按阶段／配置／范围报告，保留全物理分母 |
| 版本／提供方漂移 | 运行条件实际改变 | 停止受影响片段并披露；新条件不拼成同一模型结果 |
| 原生 Agent 计量不等价 | 用外层 exec 次数匹配 B4 | 单独预算和系统解释，不能宣称等内部计算 |

## 19. 论文组织、允许声明与退出

### 19.1 建议论文结构

Introduction：从真实 AI 子系统的跨模块语义问题引出研究，而不是从“LLM 会写 Verilog”开始。Background/Related Work：区分通用 Agent、硬件 IR、神经网络编译器与本方法。Method：PC2.1、检查边界、确定性结构和受限修复。Benchmark/Protocol：三个家族、独立设计簇、oracle、预算和暴露审计。Results：系统成功与成本→共享 PC 构建增量→错误／修复机制→物理深度→已纳入原生 Agent／消融。最后明确限制与有效性威胁。

建议主表报告 M0–M5 的各家族与宏平均 VPP-L3、失败／未知、调用和成本；主图给两个对比的家族／总体效应区间。其他表分别为一致性错误、PC 到 hidden 的失败转移、三家族物理全分母和独立 Agent 对照。没有结果就不画预计提升或填占位成功率。

### 19.2 证据与表述边界

| 实际结果 | 允许表述 | 不允许外推 |
|---|---|---|
| 两个主比较均满足规则 | 在冻结三家族、模型、预算与工具范围内有系统与构建机制增量 | 所有 AI／FPGA 任务通用优越 |
| 仅 M5−M1 成立 | 完整流程增益有证据 | 全部收益都来自 checker 或 lowerer |
| 仅 M4−M3 成立 | 同 PC 下构建／编辑边界有局部增益 | 从需求开始整体优于 Direct-Repair |
| 结构／声明错误减少而整体不变 | 有限结构现象与代价 | 已解决实际张量行为一致性 |
| 未单独运行张量消融 | 完整 PC2.1 组合方法结果 | 张量检查单独造成 X% 增益 |
| 没有合格原生 Agent 对照 | 优于或不优于本研究 M1 的结果 | 已经胜过 Codex 产品 |
| 真实模型子图回放通过 | 冻结负载与位精确范围内一致 | 端到端精度、现场应用或实时部署已成立 |
| 部分 L4 成功 | 指定器件／工具／子集物理证据 | bitstream、L5、一般 PPA 或跨平台成功 |
| 主要效应小、负或不精确 | 负结果／估计与机制边界 | 不显著即证明完全没有效应；事后换主问题 |

任务来自 MobileNet／ResNet 思路不等于完整模型复现，采用有限 GEMM 不等于复现 Gemmini。目标 TRETS 是研究定位，不是录用保证。

### 19.3 最小退出标准

研究结束时须能回答：三个家族的公开义务是什么；哪些设计簇独立、哪些只是配置；PC 实际检查与未检查什么；构建器贡献了哪些结构；Direct 是否获得等价信息和有效预算；每个正式位置发生了什么；隐藏结果是否独立；两个主要效应与成本如何；三家族物理确认到什么范围。

至少形成完整、可重建的结果与限制，不以正向显著为完成前提。若新家族资格、独立簇或计量不足，诚实转为有限案例／估计性研究并修改声明。训练、EA、Q-table、完整平台、所有可选消融和上板没有完成，不阻塞核心；已启用扩展即使结果不理想也保留全分母。
