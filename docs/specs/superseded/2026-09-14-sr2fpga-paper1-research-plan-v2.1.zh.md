## 1. 研究目标与最小论文范围

### 1.1 一句话研究问题

> 在模型权重、公开需求事实、工具权限和总预算受到控制时，项目契约约束下的确定性工程构建与受限修复，能否减少多文件 FPGA 工程的不一致，并提高独立隐藏评测下的项目成功率？

研究不等同于“让 LLM 写一段 Verilog”。输出必须是能由统一工具入口消费的 FPGA Project Package（FPP）：完整 RTL 源码、顶层接口、文件清单、适用的公开约束引用、构建元数据及必要的初始化文件。

本稿中的“从需求到工程”指从**已独立裁定可评分、已冻结公开事实的需求**出发。它不是对任意短提示、未解决歧义或未知平台请求的开放世界能力声明。[S0, §§1, 5.2]

### 1.2 最小论文必须完成什么

最低主链为：

```text
冻结的公开需求事实
    → 模型生成 PC 或 Direct 对照
    → 完整多文件工程
    → 有预算的公开检查与修复（适用时）
    → 唯一终止候选封存
    → 独立隐藏功能评测与指定 L3 综合确认
    → 预声明子集上的固定目标 L4 物理确认
    → 成功率、错误分布与完整成本分析
```

最低交付包括：明确的 PC 支持域和结构保证、M0–M5 端到端路径、两个主要比较、独立 oracle、全部失败与成本记录、代表性 L4 结果或明确的物理失败证据，以及可重建论文表格的产物。

“完成研究”不以所有假设显著为前提。负结果、效应不确定或某些物理任务失败必须保留。物理证据不足时缩小论文声明，不通过换子集或放松约束制造成功。

### 1.3 不阻塞最小论文的扩展

| 内容 | 本稿地位 |
|---|---|
| 完整需求歧义／澄清审计 A_req、原 RQ0 | 独立可选研究；核心只保留必要的停止与来源追踪一致性测试 |
| 目标配置适配 | 独立可选扩展；不得影响主方法或主分母 |
| DSC/DP 下的 EA 搜索、原 RQ5 | 独立可选扩展；默认关闭 |
| 自然失败上的 PC-aware repair probe | 预声明的描述性机制分析；没有足够自然失败不阻塞主论文 |
| 应用约束与验证阶段追踪 | 适用任务的公开需求责任，不新增主要假设 |
| 视觉真实负载回放、Q-table 案例 | 优先规划的独立描述性案例；不增加核心四家族的统计分母，不以案例成功为主论文前提 |
| 小型冻结权重推理任务 | 储备任务，启用或替换次要案例必须先于相应结果；不是通用 CNN 生成器 |
| Vivado 商用参考 | 可选；不在本稿中设为期刊强制条件 |
| 模型训练、SFT、蒸馏、RL、学习型 QoR 预测、L5 上板 | 不属于 Paper-1 最小范围 |

历史训练代码可留在仓库，但不进入主实验依赖、模型选择、结果或发布义务。论文应写“冻结基础模型权重、无任务特定参数更新”，不把已经预训练的模型称为“未训练模型”。Q-table 更新是被生成硬件的工作负载，不是训练生成模型；使用已有冻结推理权重也不意味着进行 SFT 或模型训练。[S0, §§3, 5, 8; D1]

### 1.4 应用约束是输入，应用结论须逐项取得证据

本版采纳的路线是：**以有来源标注的应用约束设计任务，以独立 oracle 验证工程，并优先增加一个冻结真实负载回放案例；完整现场部署不成为 Paper-1 的前置条件。** 该路线来自 v2.0 后的任务讨论 [D1]，是研究规划，不是应用有效性结果。

保留 [S0, §12] 关于不得从 synthetic shells 推导 RL／vision／radar／SoC 应用真实性的限制。它约束的是无证据外推，不禁止完善算法、接口、工作负载或物理证据。任务名称、目录归类、`architecture_obligations` 字段或一份寄存器表都不能自行证明真实部署；同样，也不能只凭这条禁止项断定每个现有家族均无实际行为。

将证据分为以下互相关联但不可替代的维度，不新增或重编号 L0–L5：

| 待支持的结论 | 所需证据 | 不能自动推出 |
|---|---|---|
| 约束有可追溯来源 | 外部资料或工程设定的身份、版本、适用条件与推导记录 | 工程已满足约束、约束已在现场验证 |
| 实现符合指定算法和协议 | 冻结需求、独立位精确参考、接口／角落测试及阶段结果 | 算法具有业务有效性 |
| 能处理选定真实负载 | 冻结输入、预处理、完整回放与独立结果核对 | 已接相机、已上板、已达到在线帧率 |
| 完成指定接口集成 | 固定平台接口、生成边界、实际连接及相应测试 | 全部平台由模型生成、完整 SoC 正确 |
| 满足指定物理要求 | 器件／工具／约束、实际映射与时序证据；运行声明另需板级记录 | 通用可部署、跨平台可移植 |
| 达到应用质量或现场目标 | 与所述应用相符的数据分布、业务指标、端到端集成与运行证据 | 从少量通过样例推导普适实用性 |

真实输入可以在 RTL 仿真中回放；板级运行也可能只覆盖简单人工输入。两者分别增加自己的证据，不把“真实数据＋完整 I/O＋L5”当成所有有限结论都必须满足的一道统一门槛。没有相应证据时，只撤回该维度的声明，不把已建立的其他结果抹去。

主研究保持为工程生成与修复方法研究，不要求每个 FPGA 任务都是 AI 推理。局部窗口图像算子不能仅因有行缓存而称为 CNN；有限匹配滤波不能称为完整雷达；Q-table 运算正确不能称为 RL 控制效果提升。

## 2. 研究定位与拟检验的贡献

### 2.1 与相关工作比较的正确粒度

v2.0 记录的一手资料支持以下有限定位，本次保留其研究定位，不把本轮文字整合当作新的全面文献综述：[D0]

| 工作 | 已明确涉及的内容 | SR2FPGA 需要进一步证明的区别 |
|---|---|---|
| HORIZON [S1] | 项目包、仓库级硬件演化、工具评测与运行轨迹 | 不能以“自动调用工具、修 RTL、记录版本”作为独立新颖性 |
| CPPL [S2] | JSON 电路 IR、接口和层次检查、确定性 lowering 到 CIRCT | 必须说明 PC 的项目义务、行为编辑边界及跨文件作用；不能只强调有 JSON IR |
| HINT [S3] | 显式硬件意图、RTL 前检查与 lowering 义务 | 必须实证区分“增加意图表示”和“以契约约束工程构建与修复”的增量 |

M1 是本文自己的 Direct-Repair 对照，不自动等于 HORIZON 复现。对 CPPL/HINT 的概念比较不能替代可执行基线；若引入外部实现，需要单独冻结其输入、任务支持域、预算和适配规则。无法公平运行时，明确报告不可比原因，而不是引用原论文百分比横向排名。

### 2.2 拟检验的三项贡献

**贡献 C1：项目义务与实现决策分离的契约化方法。** 由不可变公开需求约束模型生成的工程结构，明确哪些结构由可信程序构建、哪些行为仍由模型负责。

**贡献 C2：契约约束的构建与修复机制。** 用共享 PC 的 M4−M3 检验确定性构建／编辑边界这一联合干预；用 M5−M1 检验完整流程在相同总资源机会下的价值。

**贡献 C3：面向多文件 FPGA 工程的独立证据。** 用同一公共交付标准、隐藏 oracle、分阶段失败和代表性物理证据说明收益在哪些层次成立、在哪里失效。

这些是待验证贡献，不是已成立的创新性结论。“首次”“全面保证正确”“普适提升”均不属于预设结论。

## 3. Project Contract 的硬件语义与支持域

### 3.1 术语与序列化

PC 为 Project Contract；FPP 为 FPGA Project Package；DSC 为 Design-Space Contract；DP 为 Design Point。保留 System-HIS 作为当前 PC 的历史／内部标识，不把 PC 改名为 EA genotype。[S0, 开头术语说明]

源计划将 PC 序列化为 System-HIS v1.2。本稿先定义**逻辑责任**，不声称下面的逻辑字段已经兼容 v1.2。实施阶段应制作“逻辑义务—现有字段—checker—lowerer—测试”映射：能兼容的直接绑定，需扩展的使用显式版本或受控 sidecar；不得一边修改语义一边维持旧版本号。原 H0–H3 的名称保留，具体检查含义以审计后的注册合同映射为准，不在本稿中凭空重定义。

### 3.2 不可变需求义务与可变实现决策

PC 在逻辑上由三部分构成：

| 部分 | 来源与职责 | 生成／修复权限 |
|---|---|---|
| `requirement_binding` | 绑定冻结 Requirement Envelope、公开 fact IDs、版本及哈希 | 控制器写入；模型不能替换来源或削弱义务 |
| `design_decisions` | 模块分解、内部连线、状态归属、资源组织及需求允许的实现选择 | 模型生成；须在能力域内，并通过约束检查 |
| `obligation_trace` | 从公开需求义务到 PC 元素、FPP 元素、公开检查项的关联 | 可生成候选关联，但可信检查器验证可验证部分；不等于正确性证明 |

冻结的公开事实同时提供给所有方法。PC 方法不获得标准答案 PC、参考 RTL 或隐藏测试。受信控制器绑定需求，不替模型选择内部算法、拓扑或家族模板。

例如，需求规定 signed 16 位输入、饱和输出、固定三周期延迟，则这三项都是不可变义务；内部乘法器数量是否可变取决于需求。不能通过改为回绕、增加延迟或减少精度“修好”工程。

### 3.3 最小语义覆盖矩阵

| 对象 | 需求／PC 必须明确的内容 | 主要检查责任 |
|---|---|---|
| 顶层接口与参数 | 名称、方向、位宽、signedness、参数域、表达式依赖 | 公开事实一致性、跨字段和 elaboration 检查 |
| 时钟与复位 | 时钟域、复位极性、同步／异步行为、优先级、复位期间输出和状态 | 连接检查＋公开／隐藏复位场景 |
| 流接口 | 数据接受事件、背压保持、顺序、丢弃规则、复位中的事务处置 | 协议监测与事务 scoreboard |
| 并发事件 | FIFO 同时入出、满／空边界、清零与写入、重置与启动优先级 | 定向角落用例及变异资格测试 |
| 数值行为 | 中间位宽、符号扩展、舍入、截断、饱和／回绕 | 位精确 oracle，不能用浮点近似替代整数义务 |
| 存储 | 端口、同步／异步读、读延迟、同址读写语义、初始化 | 语义测试＋实际映射报告 |
| 时间行为 | 延迟起点、时钟周期／有效事务计数、停顿时的计数规则、吞吐要求 | 周期级或事务级检查，明确环境假设 |
| 工程结构 | 实例绑定、信号驱动、状态归属、文件依赖、top 选择 | 确定性结构检查、工程构建及 elaboration |
| 平台约束 | 硬约束、软偏好、目标器件／时钟、资源预算、允许例外 | 受控 target profile 与指定工具阶段 |

有界测试只能为列明的性质提供有限证据。若某条自由文本义务不能静态验证，必须标为“需要 oracle”，不能因为已写进 PC 就标成“已证明”。禁止把缺少 checker 等同于不需要满足该义务。

存储映射需要实际工具证据：Yosys 文档区分异步读与同步读所允许的映射，并指出某些资源强制属性无法实现时会报错。[S4] 本研究因此分别记录“需求／PC 的映射意图”和“指定综合阶段的真实映射”，不以 `ram_style` 替代 BRAM 证据。

### 3.4 核心能力域：建议从有限配置开始

建议核心配置采用单一用户时钟域、可综合整数／定点 RTL、寄存器／同步 FIFO／明确语义的 RAM、valid-ready 或明确周期协议，以及固定或明确允许变化的延迟。禁止未声明的内部生成时钟、跨域设计、任意 DPI/FFI、外部可执行脚本和未经许可的器件原语。

复位形式由统一能力配置列明并覆盖对应测试，不要求任意复位组合都支持。UART 类任务必须固定串行采样假设；若包含输入同步器，应作为所有方法等价获得的公开 shell，其可观测延迟进入需求与 oracle。核心不因此宣称解决一般 CDC 或亚稳态验证。

未初始化存储、读写冲突、环境背压等不能依赖未声明的“常识默认”。任务只在其适用输入和状态域内计分；允许的未定义行为须在所有方法收到的需求中明确，而不是事后为失败免责。

### 3.5 应用约束进入公开需求的规则

应用来源不直接变成隐藏 Family Recipe，也不只进入 PC 分支。统一路径为：

```text
场景、外部资料与研究者选择的工程配置
    → 裁定公开需求事实、环境假设与 target profile
    → 各方法获得内容等价的输入
    → PC 绑定不可变义务并表达合法实现决策（适用时）
    → 构建／修复 → 在所声明阶段验证
```

在现有 Requirement Envelope、公开 fact IDs 与 `obligation_trace` 中增补必要信息，优先映射现有字段，不另建一套并行事实权威。至少区分以下责任：

| 维度 | 必须区分的内容 | 例子与处理 |
|---|---|---|
| 来源 | 可追溯外部要求、研究者明确选择的工程配置、由模型提出的实现选择 | 引用某接口规定不同于研究者选择 640×480；没有来源时不能称产线要求 |
| 义务角色 | 不可变功能／接口／性能义务、环境假设、软偏好、可变实现决策 | “背压不丢数据”不等于“必须用深度 32 的 FIFO” |
| 适用条件 | 允许输入、复位状态、背压上界、到达节奏及配置模式 | 有界延迟声明须写清源和接收端的行为条件 |
| 验证责任 | 对应检查器／独立 oracle、验证阶段和范围 | 周期级延迟可在相应仿真中检查，目标器件时钟要求需物理证据 |
| 实际结果 | 证据引用、已验证／失败／未验证／不适用及原因 | 这些是逻辑状态要求，具体字段复用现有合同，不由模型自报 |

来源不明的条目可在冻结前明确改列“研究者设定”，但不能静默包装成实际客户要求；若影响可评分性或支持域，则先完成需求裁定再进入正式任务。

凡影响可观测正确性的规则都必须公开：像素格式、坐标定义、寄存器语义、量化、事务顺序、配置生效和时延起点等，不得只藏在 `architecture_obligations` 或隐藏测试中。**隐藏的是具体用例与期望输出，不是判题规则。** 对超出公开适用域的输入，不得事后增设错误处理义务；若需要验证非法输入处理，必须事先写入任务。

除非公开需求确有结构或复用约束，不强制参考实现的 FIFO 深度、内部模块数量、文件布局或资源分配。PC 方法不能获得额外拓扑答案；Direct 方法不能被要求猜中参考实现。`line_buffer_order` 只表达相关行为义务；是否执行卷积及其数值规则须由算法规格独立定义。

### 3.6 分阶段满足义务，不把 L3 当作全部应用要求通过

每个任务冻结 L3 及之前可判定的义务集合、L4 适用义务和任何更深证据的边界。加入物理目标不改变 `VPP-L3` 的既有定义：L3 成功只支持声明的 L3 范围，不能替代未运行的 L4；物理失败也不追溯改写已经成立的 L3 结果。

例如，公开需求含“无停顿时每周期接收一个像素”和“指定器件达到目标时钟”时，前者由周期／事务监测检查，后者由固定 profile 的物理结果确认。还未执行物理阶段时，后者标为未验证。若论文声称满足完整应用配置，则该配置要求的全部维度均需相应证据，不能只展示 `VPP-L3=1`。

将应用义务写清并不重新启用完整 RQ0/A_req。核心依旧使用方法分派前独立裁定、冻结为 ready 的需求；DSC 只在 EA 扩展启用时约束可搜索决策，不能用 DSC 替代普通任务的公开需求。

## 4. 确定性工程构建与受限编辑

### 4.1 构建器应做什么

输入为通过共同 PC 合法性／支持域检查的 PC；输出为结构骨架、行为编辑位点、FPP 清单和构建来源映射。

核心构建器负责由 PC 推导顶层／子模块声明、参数绑定、实例和连线、文件依赖、通用构建元数据及受保护边界。它不根据隐藏 family ID 选择参考实现，不静默注入完整 FIFO、仲裁器、滤波器或其他家族行为。

若使用含行为的公共组件，必须事先声明其内容、版本、来源和成本，并向对照方法提供等价的可用信息和调用机会；否则这属于额外的库／模板干预，不能归入主机制比较。主配置优先采用结构性 lowerer，减轻该混杂。

### 4.2 可检验的有限保证

设 `C` 为 PC，`K(C)` 为确定性构建结果，`P` 为模型行为补丁。本研究计划验证：

```text
合法且受支持的 C
    ⇒ K(C) 的受保护结构与 C 的接口、实例绑定和工程依赖一致

补丁 P 通过边界校验
    ⇒ Apply(K(C), P) 不改变被保护的结构义务
```

上述是拟实现和测试的有限不变量，不是本稿已经给出的普适形式证明。它不保证算法、协议、数值和时序全部正确。PC 本身错误也可能生成结构一致但功能错误的工程，必须由独立需求 oracle 检出。

验收应覆盖正反例、参数边界、AST／elaboration 检查与破坏性补丁，而不能只验证生成文本含有某个字段。

### 4.3 编辑范围与 PC 修正

行为补丁必须指向受控行为区域或明确允许的 AST 节点。仅使用字符串哨兵或注释边界不足以认定安全，需在补丁后重新校验工程结构和有效依赖。

M5 可以在冻结策略允许时修正**实现决策**，但不能修改冻结需求。PC 修改产生新版本和哈希，重新检查并重新构建；受影响行为区域失效并重生成，不允许沿用已经不匹配的旧补丁。对应模型调用、检查和工具重跑全部计费。

M4 的初始候选、所有历史 PC 和补丁保持不可变；M5 创建后继版本，不覆盖共享起点。

### 4.4 构建来源映射

每个候选记录 `construction_origin_map`，至少区分：冻结公开需求直接绑定的结构、通用 lowerer 推导的结构、已声明公共组件，以及模型生成／修改的行为。

报告结构对象与行为责任的分布、被保护的工程关系以及相关错误变化。代码行数仅作辅助，不把“模型少写了多少行”直接解释为解决了多少硬件设计问题。

### 4.5 可信平台接口与被生成子系统的边界

后续集成采用“**可信固定平台接口与数据搬运基础设施＋被生成的多文件算法子系统**”作为优先路线，而不是要求模型同时生成 PCIe／DMA、驱动、相机接口与算法。核心当前仍以其声明的单用户时钟和有限接口能力为范围；平台集成是否需要扩展该能力，由独立协议决定。

平台 shell 与 synthetic application shell 不混为一谈：前者必须真实说明已有接口和服务，生成子系统仍承担明确运算；后者不能仅靠应用名称取得应用证据。所有比较方法获得等价 shell、接口文档、组件使用机会和预算规则，shell 本身不自动成为模型生成的成果。

`construction_origin_map` 分开标注可信平台、公共组件、通用构建结构与模型行为；独立 oracle 仍验证被生成边界及适用集成交互。第一版允许文件回放与受信接口模型，但必须标为仿真环境。后续真实平台替换不得改变冻结算法义务；新平台或新约束的结果使用独立身份，不能覆盖原主实验结果。

## 5. Agent 执行架构与诊断接口

### 5.1 确定性控制器组织有限模型决策

研究采用明确 workflow，而非多个自由协商 Agent。模型负责设计与补丁提议；控制器负责状态、预算、允许动作、文件权限、终止和证据记录。固定代码路径与自主 Agent 的区别可参照 [S5]；本研究选择前者作为主框架，是工程设计取舍，不是普适优越性结论。

```text
PREPARED
  → PLAN_OR_GENERATE
  → VALIDATE_PC（适用时）
  → MATERIALIZE_OR_FREE_GENERATE
  → PUBLIC_EVALUATE
  → DIAGNOSE_AND_PATCH（适用且预算允许时）
  → PUBLIC_EVALUATE
  → TERMINAL_SEALED
  → HIDDEN_EVALUATED
  → L3_CONFIRMED
  → PHYSICAL_CONFIRMATION（预声明子集）
  → REDUCED
```

这是逻辑状态图。public evaluator 可以包含预算内的 L3 检查；最终 L3 证据可复用同一候选、工具与配置的有效报告。隐藏结果不能回到生成／修复状态。

### 5.2 三类共享起点

共享起点不假设一定已生成工程。定义：

| 类型 | 含义 | 用途 |
|---|---|---|
| `pc_failure_checkpoint` | 有 PC 尝试及诊断，但没有有效 PC/FPP | M4 以失败终止；M5 可按剩余预算纠正 PC |
| `project_failure_checkpoint` | 有输入／可选有效 PC，但没有完整 FPP | M0/M4 记录失败；M1/M5 可修正或重新生成 |
| `project_checkpoint` | 有完整、不可变 FPP，可公开通过或失败 | 作为成对修复起点 |

checkpoint 绑定已消费事件、输入和产物哈希、失败阶段、模型历史及剩余预算。恢复路径不能把已发生的失败清零。

### 5.3 PC-aware 诊断对象

建议统一诊断逻辑接口：

```text
failure_stage
public_evidence_refs
violated_public_obligation_ids
related_pc_elements
related_fpp_elements
allowed_edit_targets
required_rechecks
diagnostic_origin = rule | tool | model_hypothesis
```

`rule/tool` 必须可追溯；模型推断必须标成假设。系统不能伪造“工具已经证明违反某条义务”。例：公开监测器发现输出在背压期间改变，可关联流接口保持义务，并限制修改输出寄存器的更新条件，而不能允许改写顶层协议。

公开日志中的候选文本以数据形式传递，不具有修改 Agent 指令、工具权限或实验规则的效力。模型提出动作，不能授予自己权限，也不能给自己的结果签发评测通过。

### 5.4 上下文与重试

每个方法分支有独立会话，不跨方法／任务共享修复记忆。共同规范和格式示例可使用，但必须提前冻结、来自开发域并对比方法信息等价。检索、技能库、持久记忆和 family recipe 在核心中默认关闭。

模型返回无效格式时，只有预声明、语义保持的确定性提取可不算模型调用。再次询问模型、修 JSON、补文件、改 schema、改 PC 都是新的逻辑调用，消耗总预算；不得藏在“首发”内部。

网络请求失败后，不在无法确认原请求是否执行时盲目重新采样。具备提供方幂等机制时重取同一请求结果；无法消除歧义时记录成本不确定性和基础设施状态，按冻结规则停止或处理。

## 6. 研究问题、方法和预算公平性

### 6.1 研究问题重组

为避免误用历史编号，本稿保留 RQ1/RQ2/RQ4 等标识，但明确新版本中的地位：

| 编号 | 本版问题 | 比较及地位 |
|---|---|---|
| RQ1a | 相同总预算下，完整 PC 流程是否改善项目成功率？ | **M5−M1，主要确认性比较** |
| RQ1b | 共享生成 PC 时，确定性构建和受限编辑是否有收益？ | **M4−M3，主要确认性比较** |
| RQ2 | 修复在哪些失败上有效，代价如何，公开改善能否保持到隐藏评测？ | M5−M4、M1−M0、自然失败 probe，次级分析 |
| RQ4 | 在固定目标与预选任务上，L3 收益能否延续到物理实现？ | 代表性 L4，描述性 |
| RQ0 / RQ5 | 需求审计／EA 搜索 | 独立可选扩展 |
| 原 RQ3 | 训练／内化 | 继续移出 Paper-1 |

两个主要假设组成**同一个**多重比较族。旧版 M4−M0、M5−M4、R_HIS−R_generic 的确认性地位不自动沿用。

### 6.2 M0–M5 定义

| 方法 | 初始生成 | 公开反馈修复 | 关键边界 |
|---|---|---|---|
| M0 Direct | 需求事实→完整 FPP，一次模型调用 | 无 | 不要求 PC，不因 H 阶段不适用而失分 |
| M1 Direct-Repair | 共享 M0 的初始尝试 | 有；可修补或在剩余预算内重新生成 | 不能改冻结需求、评测器或公共目标约束 |
| M2 Structured-Direct | 无类型计划→自由生成完整 FPP，共两个阶段 | 无 | 不使用 PC 专用语义 checker 或 skeleton |
| M3 PC-Free | 生成 PC→自由生成完整 FPP，共两个阶段 | 无 | 与 M4 共享同一初始 PC 和共同 PC 准入检查；不消费 skeleton |
| M4 PC-Skeleton | 同一 PC→可信结构构建→模型填行为，共两个模型阶段 | 无外层修复 | 限制行为编辑范围；初始 PC 失败照常进入分母 |
| M5 PC-Online | 共享 M4 初始尝试／checkpoint | 有；可纠正实现决策或修行为 | 所有修正、重新构建和重生成消耗同一总预算 |

共同 PC 准入检查只判断预声明的合法性与支持域，不利用成功 skeleton、参考实现或隐藏反馈挑选 PC。对 M3/M4 共同 PC 失败，两个方法都保留端到端失败；另报 PC 合法条件下的机制结果，不能只报筛选后的成功子集。

M3−M2 是表示、提示、长度和检查器组成的联合比较，不是“typing alone”。M4−M3 是确定性构建与编辑边界的联合比较，不是纯文本 skeleton 或纯 lowerer 效应。

### 6.3 共享配对块

基本身份为 `(semantic_instance_id, replicate_id)`，另设稳定 `paired_block_id`。M0/M1 共享 Direct 初始尝试；M3/M4 共享初始生成 PC；M4/M5 共享初始 PC/FPP checkpoint。任何共同起点失败也须共享其诊断、来源及已用预算。

共享事件只实际执行一次，但每个方法的独立运行成本必须完整计入自己需要的前置工作。M5 修正后的 PC 不回流至 M3/M4；M1 修复后的工程不回流至 M0。

随机化遵守依赖图：先随机化同层共同前置任务，再对可执行的分支做分块平衡调度；不能为了宣称任意六方法排列而违反共享起点依赖。执行时间窗和顺序记录用于检查服务端漂移。

### 6.4 核心预算提案：B4

本稿建议将主要 M5−M1 比较设为 **B4：每个独立方法最多 4 次逻辑模型调用**，而不是给二者相同“修复次数”。这是新提案，须在排除式 pilot 前冻结。

| 路径 | 正常初始调用 | 剩余额度 |
|---|---:|---:|
| M1 | Direct 生成 1 次 | 最多 3 次修补／纠正／重生成 |
| M5 | PC 规划 1 次＋行为生成 1 次 | 最多 2 次 PC 或工程纠正；若上游提前失败，按实际已用调用结算 |
| M0 | 1 次 | 不使用追加调用 |
| M2/M3/M4 | 每声明阶段 1 次，最多 2 次 | 无模型级内部重试和外层修复 |

M1/M5 同时受相同的累计输入／输出 token 上限、单次输出上限、公开工具调用上限、有效运行时间和 EDA 时间约束。核心规划值为最多 4 个公开完整检查周期；每个周期的子工具列表和超时必须固定，并分别记录实际子调用。任何单工具额外重跑也不能免费。

具体 token、时间和内存上限依据开发沙箱的真实上下文与运行需求确定，在排除式 pilot 前锁定；本稿不伪造适用于未知模型／工具的秒数。正式 manifest 不允许这些轴留空，且没有 token 计量依据时不得声称 token 等预算。

给 M1 可合法利用的剩余额度，避免“相同名义预算但 Direct 无法使用”的伪公平。实际不必耗尽预算：所有方法遵守同一公开停止原则，报告实际消费。若平台提供 reasoning token 计量，应纳入模型输出／计算预算并记录；若内部计算不可计量，须声明仅控制可观测调用及 token 轴，不能声称完全等 FLOPs。

M4−M3 使用相同两阶段调用策略和阶段预算，是主机制比较。M4−M0 留作一阶段与两阶段系统路径的次级参考，不承担等推理资源的主张。

### 6.5 首发、终止与修复窗口

`@initial` 对应旧稿“每个声明阶段一次调用”的 `@1`，不表示整个两阶段方法只调用一次。`@B4` 为上述总预算内的终止结果；旧 `@A` 导出必须绑定具体预算配置，禁止只写“多轮”。

修复方法选择最早达到冻结公开接受谓词的候选；否则在预算耗尽时选择最后一个完整且边界有效的 FPP。最后一次补丁失败时可保留其之前仍有效的完整候选，但不能根据隐藏结果回溯选择。没有完整候选即设计失败。

公开接受谓词应包含共同工程检查、指定 lint/public L2 和预算内的指定 L3 检查，保持 M1/M5 一致；选择规则不依赖预测 QoR。最后一个候选没有完成公开接受检查时仍可被封存，但不能推断该检查已经通过。

这是有限预算修复研究，不宣称长程收敛。若以后增加 B8 等预算点，须在独立预声明子实验中真正运行对应终止策略，不能从一条 B4 轨迹推断未观测预算下的隐藏正确率。

## 7. Benchmark、oracle 与泛化边界

### 7.1 保留候选目录，不把候选状态写成资格通过

延续 [S0, §6.1] 的候选组织，避免无依据地重建任务库：

| 分组 | 候选家族 | 用途 |
|---|---|---|
| 开发域 | `sync_fifo`, `single_dual_port_ram`, `valid_ready_stream_accumulator`, `mac_array`, `matrix_vector_mac`, `fir_filter`, `peak_detector`, `pattern_matcher`, `p_stream_trigger_filter` | 能力检查、提示与模型选择、开发和排除式 pilot |
| 主要测试候选 | `uart_fifo_loopback`, `stream_fork_join`, `matched_filter`, `sobel_threshold` | 四个预选家族的主结果；必须重新核验 oracle 和开发暴露 |
| 单独旗舰候选 | `qtable_update_core` | 参数／拓扑留出展示，不并入四家族主要统计；不阻塞核心 |

原目录并不证明当前所有 oracle 可用。[S0] 曾记录其中两个测试家族的独立 oracle 缺口，本稿不据此判断今天是否仍未完成；实施盘点必须重新核验。

### 7.2 以项目机制而非文件数量制造任务难度

任务应覆盖真实的跨模块义务：协议组合、参数传播、数值位宽、同时事件、缓冲与背压、流水对齐、存储访问及复位一致性。记录模块／接口数量、状态归属、最长数据路径、协议边界和语义耦合，不用“生成了几个文件”代替项目复杂度。

确有必要时，需求可以规定系统分块或可复用模块接口，但必须作为所有方法相同的公开事实。不能只为 M4 指定有利拓扑，或让 Direct 被迫猜隐藏文件布局。不同合法内部架构由方法中立评测接受。

### 7.3 独立语义实例

独立单位为 `semantic_instance_id`。改写措辞、重复随机测试、同一行为的位宽／深度变体不自动产生独立样本。多个任务若只是共享一个模板、参数抽样器或微小编辑，应共享依赖簇；无法支持独立性时在更高层聚类。

每个实例记录公开需求、可观测行为、环境假设、参数域、实例间依赖及作者／生成来源。规格中某些合法变化确实改变算法或协议义务时，可以成为不同语义实例，但需要事先记录理由而不是靠编号宣称独立。

### 7.4 “留出”必须说明相对于什么

本项目不训练基础模型，不能证明 UART/FIFO 等概念从未进入模型预训练。允许的主张是相对于 SR2FPGA 的生成侧开发、提示、规则、检索和样例选择的留出，且必须有暴露审计。

特别注意：原计划中的多个测试家族已有仓库实现。历史暴露不能通过移动目录或改名消除。若生成侧开发实际使用过该家族的模板、解法或参考工程，就不能称为严格的 family-held-out；应预先标成实例／组合留出，或在正式结果前从已冻结顺序的合格储备家族替换。评测侧编写 oracle 的接触也应与生成侧使用分开记录。

记录需求重复、RTL/AST 近重复、接口签名、组件图重叠以及共享语义机制。主结果按 `seen-primitives/unseen-composition` 等实际证据分类。仅四个预选家族时，统计推断条件于这些家族，不推及所有未知 FPGA 家族。[S0, §§6.1–6.2]

### 7.5 独立 oracle 资格

每个正式家族必须具有基于冻结需求的 evaluator-owned oracle，独立于候选 PC、候选 testbench 和候选 RTL。功能参考、协议 monitor 与时序计分分别绑定需求义务。

资格验证至少覆盖参考实现通过、已声明缺陷类别的非等价变异检出、公开／隐藏用例隔离和确定的适用输入域。等价变异、无法执行的变异和未检出的变异分别记录；mutation score 仅为 oracle 资格证据，不等于证明 oracle 完备或模型更强。

不得用同一个模型同时生成设计与 testbench，互相通过后当作独立正确性。公开 checker 和隐藏 oracle 可检验相同义务，但不共享候选可见的隐藏向量、私有期望输出或答案 PC。

任务难度来自接口、时间、状态和数值之间的耦合，而非外设名称或文件数。正式结果前完成参考可执行性与能力域检查；正式后不为了增加方法差异而追加约束。`paper2_bridge` 仅是待核查的资产组织线索，不预设下一篇论文的科学问题。

### 7.7 优先案例：流式图像处理与异常标记子系统

**目标名称与范围。** 在未评估工业检测有效性前，使用“带配置接口的流式图像处理与异常标记子系统”，而不是“已经可部署的工业缺陷检测器”。任务对灰度流执行一个明确的局部窗口算子和阈值判定，产生像素标记或帧统计；具体输出模式在任务卡中选定，不能让模型自行更换任务。

下列职责用于需求分解和评测覆盖，不强制参考文件布局：配置接收与帧级快照、输入帧行状态、窗口构造、数值算子、判定与坐标跟踪、结果缓冲。内部合法实现由各方法选择，跨模块必须保持的关系由公开规格约束。

| 规格项 | 任务卡必须给出的裁决 |
|---|---|
| 像素和几何 | 像素位宽、灰度定义、尺寸及参数域、扫描顺序、合法帧／行长度 |
| 传输事件 | 数据何时被接受，帧／行标记与哪次传输对应，停顿时哪些信号必须保持 |
| 数值算法 | 选定算子与系数、符号、中间位宽、运算次序、绝对值／截断／饱和规则 |
| 窗口与边界 | 窗口对应中心坐标或其他明确位置；边界采用裁剪、补零等哪一种行为 |
| 输出 | 选择像素标记流或帧结果；数量、首个标记坐标、扫描优先顺序及有效标志 |
| 无命中 | `found` 与无命中时其他字段的定义，不允许猜测坐标哨兵 |
| 配置 | 阈值／模式的寄存器或配置事务；第一版建议更新只在下一帧起点生效 |
| 复位 | 极性与方式、半帧终止、缓存和结果状态、后续合法帧恢复规则 |
| 背压与缓存 | 可暂停回放源还是不能随意暂停的到达流；最大停顿模式、缓存及丢弃政策 |
| 时间 | 无停顿启动间隔、延迟计量起点、完成时限，以及停顿时如何计时 |
| 平台与存储 | 允许的片上资源、是否允许全帧缓存／外部存储、目标 profile 与验证阶段 |

协议先选定再命名。若采用 AXI4-Stream Video 的指定子集，按 [S7] 的协议规定处理帧起点和行终点；前一轮讨论引用的约定是 `TUSER0` 对应帧起点、`TLAST` 对应行终点，不是帧结束。具体版本和支持子集需在执行前绑定。若只实现简化 valid-ready 协议，则用该名称，不宣称完整 AXI 兼容。

**用于制定规格的算例，不是冻结参数或已测结果。** 假设 640×480、8 位灰度、60 帧／秒，则有效像素速率为：

```text
R_active = 640 × 480 × 60 = 18.432 Mpixel/s
D_active = 18.432 MB/s（仅有效像素，十进制 MB，不含额外传输开销）
```

若设想 100 MHz、每周期接收一像素，则理想输入处理能力为 100 Mpixel/s，单帧输入占用约 3.072 ms。该计算不包含额外流水排空、接口等待或物理频率验证，不能写成实际端到端延迟或已经实现 60 fps。

采用两条历史行的 3×3 窗口组织时，仅两条逻辑行存储为：

```text
M_lines = 2 × 640 × 8 = 10,240 bit = 1,280 byte
```

这说明局部窗口任务可以规划为不依赖 DDR 的有限子系统；尚需计入其他缓存、元数据和实现开销，实际 BRAM 数仍以指定工具报告为准。该结构是推导示例，不自动成为所有方法必须采用的拓扑。

**平均吞吐不是完整的实时条件。** 依据公开环境假设检查峰值到达、持续停顿和帧间行为，不以平均像素速率替代缓存分析。上轮讨论引用的 [S7] 区分有效像素、行与帧平均速率及相应缓冲问题。任务不能同时允许无限输出停顿、有限缓存和无条件连续输入不丢失；没有合适环境界限的实时要求须在冻结前澄清，不把不可能的要求交给模型后算作方法失败。

首版优先使用可暂停的文件回放源；若要验证有界实时源，则在相应案例结果前另行冻结到达和服务条件。仿真验证周期行为，目标时钟经 L4 验证，真实相机或板级端到端声明另需相应证据。

### 7.8 第二案例：定点 Q-table 更新子系统

范围为具有配置接口、状态存储和受控事务顺序的 Q-table 更新子系统；执行更新运算不等于完整强化学习系统。Q-learning 的算法出处沿用前轮引用 [S9]，本研究的判题权威是冻结的位精确任务规格与独立参考。

| 规格项 | 任务卡必须给出的裁决 |
|---|---|
| 运算表达式 | 更新的精确步骤及 target 的计算方式；是否有终止状态等额外输入，适用时才定义 |
| 数值格式 | 总位宽、小数位、signedness、乘法／加法中间位宽、负数舍入、各步截断、饱和／回绕 |
| 状态存储 | 地址布局、深度、初始化及未初始化条目可否读取 |
| 事务顺序 | 何时接受与提交；第一版建议按接受顺序生效，连续同址更新使用前次应当生效的值 |
| 读写交互 | host 读取与更新冲突的可观测值、禁止或允许的并发、配置生效边界 |
| 流控与复位 | 结果停顿的保持／丢弃规则、在途更新和复位处理 |
| 时间与资源 | 受限吞吐／延迟条件、片上存储限制、目标 profile 和验证阶段 |

不能只写“Q16”或“使用定点”。例如 `Q + alpha*(T-Q)` 与 `(1-alpha)*Q + alpha*T` 在实数域的等价，不保证经过逐步定点截断后逐位相同；任务必须明确使用的运算序列及舍入位置，独立 oracle 按整数语义验证。

连续两次更新同址时，后一次不得悄悄读取不符合顺序语义的旧值。实现可以停顿、转发或使用其他合法结构；若要求更高吞吐，必须同时明确相关依赖情形下的允许行为，不能靠扩大并发而模糊正确性。

`argmax_first_tie_break` 只在输出动作索引或后续可观测行为依赖该索引时作为义务。如果只需要最大数值且相同值对应的动作选择不可观测，则不为增加难度强行加入 tie-break 条件。实际规格与接口决定是否需要该项。

先用冻结更新序列或有来源的模拟环境轨迹验证长期状态一致性。标注为 `simulated_trace` 的输入不能写成真实机器人数据；真实记录轨迹也需记录来源、采集条件和处理过程。报告数值／状态正确性、吞吐、延迟和资源，不由此声称提升学习收敛、控制效果或机器人闭环实时性。

### 7.9 有限信号处理与冻结权重推理储备

`matched_filter` 保留为核心数值信号处理候选，重点为系数和样本顺序、累加位宽、块边界及吞吐。`p_pulse_radar_signal` 若后续复用，先核实其实际运算；没有采样链路、负载和任务指标时只称有限处理核心，不宣称雷达系统。信号处理不是 AI 也不降低它作为 FPGA 工程一致性任务的价值。

若需要真正的神经网络推理案例，优先限定为**已有固定权重、固定结构和固定量化的小型子系统**，而不是补建任意网络编译器。可复用矩阵向量计算等已有机制，但是否能复用以当前代码和能力域盘点为准。

启用前冻结结构、权重／偏置及文件哈希、张量排列、层间接口、量化和预处理；优先选择经参考资格验证可在目标片上资源内实现的范围，不预设未知模型一定能装入。各方法获得相同的合法权重与规格。权重是任务输入，不是隐藏 oracle；隐藏测试样本及私有期望输出保持隔离。

将三种问题分开：量化前后任务质量、RTL 对冻结量化模型的位精确符合性、指定平台上的物理或运行性能。没有做前者不能说量化不损失精度；后两者也不能相互替代。FINN [S10] 作为前轮提及的相关实现路线保留，不以“也做了小网络”宣称新颖性；核心仍是契约约束的工程生成与修复。

本储备不新增强制任务、不启用模型训练、不并行扩成第三条主线。替换次要案例须先于相关正式结果，并保留变更理由、样本和预算身份；不能替换主统计中的失败家族。

### 7.10 真实负载回放与独立验证组合

**来源与用途分离。** 每份输入注明人工定向、固定随机、由真实数据派生、原始实测记录或模拟环境轨迹。来源标签说明它是什么，不直接授予难度、独立样本或应用有效性。

| 输入／测试类别 | 主要用途 | 必须保留的边界 |
|---|---|---|
| 定向边界用例 | 极值、全零、边界尺寸、并发、无命中、复位等可裁决义务 | 只测公开定义的适用行为 |
| 固定随机与协议压力 | 数据组合、停顿恢复、长序列状态与时序 | 随机种子固定；不增加工程独立样本数 |
| 真实图像派生回放 | 检查选定真实内容下 RTL 与参考是否一致 | 预处理后不冒充原始相机流，不自动计算业务准确率 |
| 模拟轨迹或真实记录轨迹 | Q-table 长期状态与事务关系 | 分清模拟／实测，保留来源和处理身份 |

视觉优先考虑一个可复现的 MVTec AD [S8] 子集作为候选来源，而不是本稿已经选定的数据集。采用前须完成样本、许可、规模和预处理核查；没有实际处理记录，不声称已加载或跑通过数据。若选用其他来源，也必须在案例结果前冻结，不依据模型成功与否换数据。

预处理应固定原始数据版本及身份、灰度转换、裁剪／缩放、数值舍入、像素顺序、帧行标记生成、输出输入文件的哈希及执行代码版本。图像经过缩放或裁剪后，表述为“由真实图像派生的回放负载”。数据集的缺陷标注不是 RTL 位精确判题答案；只有另行声明算法质量研究时才用于对应业务指标，不能靠调阈值迎合隐藏标签。

独立位精确参考、协议监测和时间监测分别核对输出。真实负载不能替代人工边界与随机压力用例；同一封存候选的预声明隐藏 suite 一次包含适用的各类用例，并按固定规则提交一次最终语义结果。不能先看隐藏回放失败再增加修复、换输入或追加正式评分。

数据源公开不等于已取得“未见数据”保证。方法可见的规则、数据格式和公开示例对比等价；正式选中的样本列表、测试编排及期望输出按评测域策略隔离。公开源数据的历史暴露在有效性威胁中记录，不承诺基础模型从未见过相关图像。

报告每个工程是否完成各类回放、首次已观测差异、协议／数值／时间错误和输入／预处理身份。像素数、图像数、周期数和重复随机种子只是工程内验证覆盖，不作为独立生成任务的 n。完整 suite 的组成、接受规则及超时在模型结果前冻结；不能选择性只报告通过的图像。

### 7.11 应用案例的独立实验安排与污染防护

案例是主实验之外的描述性工程研究，不增加 RQ 或主要 Holm 比较族，不改变四家族等权总体。规划起点为：

| 案例 | 建议规模 | 地位 |
|---|---|---|
| 视觉子系统 | 1 个完整项目规格 × 2 次重复 × M1/M3/M4/M5＝8 个方法结果 | 优先准备与预声明的描述性案例 |
| Q-table 子系统 | 可采用同样规模，另计 8 个方法结果 | 在视觉之后，依资格和预算预先决定是否纳入 |
| 冻结权重推理 | 本版不预设运行数量 | 储备或预结果替换一个次要案例，不自动追加 |

八个方法结果不是八个独立语义实例，更不能与真实图像数量相乘得到大样本。该规模用于展示具体工程、错误和修复路径，不独立支持统计优越性。案例输出、分母和成本与 §9 的核心／第二模型／repair probe 分开；若同一产物被多个表引用，保留同一身份，不重复计为新工程。

M1/M5 沿用 B4 总调用与预算公平原则，M3/M4 共享同一初始生成 PC，M4/M5 共享同一初始 checkpoint，失败亦保留。案例未列 M0 结果行不免除 M1 的 Direct 前置成本。更长任务若需要不同 token／工具上限，必须为案例比较各方法等价地预先冻结，并明确它不是核心 B4 配置的直接合并结果。

在 WP3/WP4、相应模型结果之前，决定是否纳入案例并锁定任务卡、方法、重复编号、负载、独立 oracle、预算与物理选择。纳入后尝试全部计划位置，保留无候选、失败、缺失和未进入 L4，不以最后成功样例替代整组结果。参考路径的资格检查由评测域执行，不向生成侧提供答案工程。

**保护核心留出。** 正式视觉案例不得在主方法冻结前用于提示、模板、规则或模型选择，否则其覆盖的算法与机制必须计入开发暴露。优先在核心方法与总体冻结后运行预声明案例，且在核心与案例所需终止候选封存之前不开放隐藏结果。若 WP2 使用视觉／Q-table 开发版本，必须使用独立开发身份，并审计与 `sobel_threshold` 等候选的机制／实现重叠；只换输入或改名不能维持虚假的 family-held-out。

案例可以为未来工作提供开发证据，但已暴露的案例和隐藏结果不能回流改变本次主方法或正式集。发现实质错误需要修订时建立新版本和新的研究身份，不覆盖原有结果。

### 7.12 任务卡是具体执行前的最小交付

每个拟升级家族先形成一份可独立阅读的任务卡，包含实际计算、公开接口、义务与环境、数值／时间规则、来源和可验证阶段；再绑定私有 oracle、负载和冻结身份。附录 C 给出逻辑清单，不要求一字段一文件，也不要求新建与现有 catalog 竞争的任务数据库。

任务卡中的待定值须在相关实验冻结前解决；本稿中的 640×480／100 MHz 等算例不是自动默认。开发准备可使用占位值，正式任务不可通过隐含默认或模型猜测补齐关键语义。任务仅因名字与某目录匹配，不能被裁定 ready。

## 8. 评测隔离、失败与证据完整性

### 8.1 三个执行域

| 执行域 | 可访问内容 | 输出去向 |
|---|---|---|
| 生成／修复域 | 公开需求、适用 PC、自己的 FPP、公开工具诊断 | 不可变候选、补丁、公开轨迹 |
| 公开评测域 | 冻结公开 harness、候选、声明的构建工具 | 可修复可见的有限诊断 |
| 隐藏评测域 | 已封存终止候选、私有 oracle 与固定用例 | 仅评测器与离线 reducer 可见的结果 |

推荐在整个正式生成批次、已纳入应用案例及已选 repair probe 的终止候选全部封存后，再开启隐藏评测与结果披露。至少必须存在阻止跨分支、跨任务、跨案例和人工调参利用隐藏结果的屏障，而不只是禁止当前方法再次 repair。真实回放输入经受信 harness 注入；候选不能读取评测器的原始数据路径、期望输出或其他隐藏文件。

### 8.2 把候选工程当作不可信输入

候选 FPP 用声明式 manifest 说明源文件、top、参数和允许数据文件，实际构建由可信 launcher 执行。候选提供的 shell/Tcl/Python 脚本不能直接变成评测入口。

检查相对路径、目录穿越、符号链接、绝对 include、跨工程层次引用及依赖闭包；禁止候选 DPI/FFI、任意系统调用和访问评测器层次的引用。`$readmemh` 等确有合法用途的能力仅允许读取 manifest 中声明、已哈希且位于候选隔离域的数据文件，不能一律放行或为方便直接禁用所有合法初始化。

使用独立权限／挂载、关闭非必要网络、限制文件和进程资源，并对工具日志做可见性标注。隔离和语言限制共同组成威胁模型，不宣称防住工具链未知漏洞或所有恶意 HDL 行为。

### 8.3 隐藏评测的一次语义提交

每个 `(campaign, instance, replicate, method)` 最多提交一个终止候选的隐藏语义结果。结果绑定 candidate hash、evaluator hash 和用例承诺。内部幂等键用于恢复：若结果已经原子提交但回执丢失，只读取原结果，不重新评分。

保留两个正交状态字段：

```text
hidden_execution_status = completed | not_run | infrastructure_error | integrity_error
hidden_semantic_status  = pass | fail | null
```

`completed` 必须恰有一个 pass/fail；已提交的失败不能触发任何生成、替换或再次测量。提交前的固定基础设施重试只能重放相同候选与同一评测配置；不得换 seed。物理重试与语义提交次数分开记账。[S0, §5.3]

应用案例的一次隐藏提交可以包含预先固定的定向、随机及真实回放用例组，但这些是一次固定 suite 内的测量，不是多轮终止候选选择。suite 的提前停止或完整运行规则须冻结；未执行子用例保留未观测状态，不按通过或零缺陷记录。事后添加的新负载只能另列非确认性追加研究，不能改变已提交的正式分数或冒充原计划覆盖。

### 8.4 失败分类

| 情形 | 记法与后果 |
|---|---|
| 格式错误、无有效 PC、无完整工程、功能失败、不可综合、候选导致的有界超时、预算耗尽 | 设计结果；VPP=0，保留在分母 |
| 模型提出越界补丁，边界检查成功阻止 | 无效尝试，消耗相关预算；根据剩余预算和终止规则处理 |
| 越界补丁实际进入受信文件，隐藏泄漏，重复语义提交，谱系或预算被篡改 | 完整性事件；停止受影响范围并按预声明规则判无效，不能冒充普通设计失败 |
| 提供方中断、工具安装故障、评测器内部异常 | 基础设施状态；固定重试后仍不可评分则记缺失，不伪记模型错误 |
| 没有终止候选所以隐藏阶段未运行 | hidden=`not_run`，上游已成立的设计失败仍为 VPP=0 |
| token 计量缺失但功能可判定 | 保留正确性结果，单独影响成本／预算可核验性，不伪造 token 数 |

候选耗尽公开约定的 CPU／内存／仿真周期属于有界设计失败；基础设施异常须有可审核原因码，不能为了减少失败数自由归类。

### 8.5 成本与故障恢复

采用追加事件作为事实来源，summary 由事件归约，不依赖 Agent 自报成功布尔值。记录请求、解析、PC 检查、构建、补丁、公开工具、封存、隐藏提交和物理评测的输入输出哈希、成本与状态。

必须支持“模型返回后中断”“补丁校验失败”“隐藏结果提交后回执丢失”等有限恢复场景。无法确认的调用成本保留 `unknown` 与原因；不得用零或平均值填齐正式结果。

## 9. 指标、统计计划与规模选择

### 9.1 主要结果：方法中立的 VPP-L3

`VPP-L3=1` 当且仅当同一终止候选满足：共同 FPP 与冻结接口标准、L0 工程一致性、指定 L1 检查、public L2、一次隐藏语义验证、指定 L3 综合流程，并且没有未解决的候选边界／来源／预算违反。[S0, §7.1]

“指定 L3”必须写出实际工具版本和脚本；generic synthesis 与器件映射综合分别命名，不把通用 cell 数称为 FPGA LUT 数。任何阶段无法验证时，不从历史 `pass_level=L3` 字符串推断完整 VPP。

PC 的 H 阶段只属于方法内部机制结果；M0/M1/M2 标记 `not_applicable`。PC 准入失败导致未生成工程时以一般设计失败进入共同 VPP 分母。

**VPP-L3 的含义不随应用描述扩大。** 按 §3.6 同时报告目标配置中尚未验证的 L4／集成／板级义务。真实负载若预先属于某任务的隐藏 suite，其符合性参与该任务的固定计分；不能在结果后新增为主指标条件。应用案例使用独立结果分组，不混入四家族主均值。没有物理或运行证据时，只能表述“在所述仿真／综合范围通过”，不能表述“满足所有真实部署约束”。

### 9.2 必须报告的次级指标

| 类别 | 指标 |
|---|---|
| 过程 | H 阶段、L0/L1/public-L2/hidden-L2/L3、首个失败阶段及阶段转移 |
| 结构机制 | 接口、参数、连线、驱动、复位和文件依赖的错误；来源映射与边界拒绝 |
| 硬件语义 | 协议、数值、并发事件、存储、时延错误；无法归类单列 |
| 修复 | 实际诊断→非空有效补丁→重跑次数，修复前后公开结果与终止隐藏结果 |
| 公开／隐藏差距 | 公开接受者中的隐藏失败率、隐藏完成率和缺失上下界 |
| 成本 | 所有 episode 的输入／输出／缓存 token、调用、重试、工具子调用、活动运行时间和 EDA 时间 |
| 物理 | 预声明子集的全分母 VPP-L4、L3 存活者条件通过率、资源与时序、约束覆盖 |
| 数据质量 | 设计失败、基础设施缺失、完整性事件、不可评分及成本轴缺失 |
| 义务覆盖 | 适用义务、验证阶段、通过／失败／未验证及证据范围；不以写入 PC 视为已经满足 |
| 应用案例（纳入时） | 每个工程的回放类别、完整性、位精确／协议／周期行为、预处理身份与全分母；图像／轨迹数量不增加独立 n |

错误诊断须绑定工具证据；可多标签，并另设首失败阶段。无法完成后续测试不意味着没有后续缺陷，不能把未观测错误数量记成零。跨方法错误标签由固定规则或方法盲审处理，避免只给 PC 方法提供细粒度诊断而造成统计假象。

公开接受后的隐藏失败率仍使用：

```text
HFPA = 公共接受且隐藏已完成并失败的数量
       / 公共接受且隐藏已完成的数量
```

同时报告公共接受的总数、隐藏完成率及未知结果的最坏／最好界限。不同条件的 HFPA 若对应不同选择人口，只作各自诊断，不能直接当成修复泛化的因果差值。

### 9.3 不能从终止评分推出隐藏收敛曲线

只有终止候选接受隐藏评测，因此只绘制公开检查进展、调用成本和状态转换。可以记录达到**首次公开接受**的成本，失败者在预算处截尾；不得将其改名为达到首次真实正确设计的成本。

隐藏结果用于 `@initial` 或真实运行的 `@B4` 终点。没有评分过的中间候选不能回填隐藏成功标签，也不能追加 hidden 调用补画曲线。

### 9.4 三种成本视图

保留 [S0, §5.2] 的三视图：实际 campaign 去重成本、每个方法完整独立运行归因成本、共享 checkpoint 之后的增量成本。

主要系统比较按独立运行视图；实际共享节约不能给某个方法免费前置计算。生成／公开修复成本、隐藏最终验证成本和 L4 确认成本分别列出，再给出总验证成本。构建 benchmark 的人力和共同需求裁定是离线开销，应单列而非只向某一方法计费。负载采集／获取、预处理和 oracle 开发作为相应离线开销单列；案例的在线生成与验证成本独立报告，不隐藏在核心共享成本中，也不因复用权重或平台而给某个方法额外免费能力。

服务时间、排队时间和端到端 elapsed time 分别保存。共享／并发事件的时长之和只能作为归因服务时间，不能冒充某方法实际独立部署的 wall-clock latency；后者需要单独计时的复核实验。

核心假设是固定预算下正确性，不预设效率优势。更低平均成本若伴随更多提前失败不能自动称为更高效率；任何正式成本优越性检验需要额外冻结正确性非劣界限与主要成本轴。

### 9.5 两个确认性假设与建议阈值

设 `Delta_system` 为 M5@B4−M1@B4 的四家族等权成功率差，`Delta_materialization` 为 M4@initial−M3@initial 的相应差。

建议在排除式 pilot 前采用以下科学规划值，须由研究负责人明确接受；它们不是文献结论或已估计效应：

| 比较 | 最小有意义效应 delta | 功效设计备择 Delta* | 理由 |
|---|---:|---:|---|
| M5−M1 | 0.05，即 5 个百分点 | 0.15 | 完整方法引入额外工程复杂度，主张应超出极小收益 |
| M4−M3 | 0.03，即 3 个百分点 | 0.10 | 在共同 PC 上检验较局部的结构性机制 |

检验分别为 `H0: Delta <= delta`，采用同一 Holm 族、单侧 familywise alpha=0.05；同时报告两侧 95% 区间和负方向效应。只有相应阈值零假设被拒绝且完整性、信息、预算及缺失规则通过，才提出该项局部优势。两项都通过才提出“系统价值与构建机制均得到支持”的组合声明。

不再额外设置重复的事后效应门槛，也不把次级 M3−M2 或 repair probe 用于挽救主要假设。设计备择必须严格大于最小效应；不得报告“在 delta 处达到 80% 功效”。

### 9.6 聚类估计与分析实现

对每个比较，先在 replicate 内求方法差，再在语义实例内平均，得到 `D_fi`；家族内求均值，最后对 F 个冻结家族等权平均：

```text
D_fi      = mean_r(Y_fir,X - Y_fir,Y)
Delta_f   = mean_i(D_fi)
Delta_hat = (1/F) * sum_f(Delta_f)
```

重复输出、改写和隐藏随机向量不增加独立 n。`replicate_id` 不等于 provider seed；即使提供方记录 seed，也不宣称不同提示共享同一实现随机流。采用 documented seed control 或冻结提供方配置的 stochastic blocked 模式之一，不混用。[S0, §§5.2, 7.5]

建议采用家族内按完整语义簇重采样的 studentized cluster bootstrap，保留每簇所有方法和重复测量；边界零假设以 delta 为中心，生成两个单侧 p 值后进行 Holm 调整。默认重采样 19,999 次，固定分析 seed；两侧区间使用同一已冻结实现。零方差／退化情况不得伪造 p 值，保守标为无法形成该确认性检验，并报告原始结果。

统计单元测试覆盖完全相同结果、恒定差值、稀疏配对分歧、家族不均衡、缺失和重复 ID。正式代码必须在模拟数据上验证错误率和区间行为；不把上述方法名本身当作统计审计完成。

### 9.7 缺失结果与保守确认

保留所有预声明实例。基础设施导致的未知语义结果为 NA，不改写成真实失败。主要报告给出全分母上下界；完整配对分析只作补充，不能静默删除缺失。

建议确认性分析采用比较方向上的保守赋值：未知 X 按 0、未知 Y 按 1，得到效果下界数据；这是分析界限，不改变底层状态或声称对照真的通过。若在此规则下仍拒绝阈值零假设，才允许含未解决缺失的优势声明。另报相反赋值的上界与 complete-pair 敏感性分析。

规划上限建议为：单方法未解决基础设施不可评分率不超过 5%，主要比较两侧差异不超过 3 个百分点；须在 pilot 前明确采纳并冻结。超过阈值时停止确认性声明，保留结果与原因，不能删行或降低阈值。

完整性失败与普通缺失分开。协议／方法需实质修改时，新建版本与 campaign；已暴露结果的测试集不能继续冒充未见测试。只恢复同一封存产物的基础设施重放，须严格按预声明规则进行。

### 9.8 开发、pilot 与正式规模

| 阶段 | 本稿规划默认 | 用途与限制 |
|---|---|---|
| 开发垂直闭环 | 3 个开发家族，每家族约 2 个语义任务 | 可调试真实模型；不产生正式结论；接触过的实例永久退出正式测试 |
| 排除式 paired pilot | 6 类机制×2 个新实例×2 次重复×6 方法＝144 个方法结果 | 估计配对分歧、依赖、失败与成本；不能调科学效应阈值 |
| 正式核心 | 候选 4 家族×30 独立语义实例×3 重复×6 方法＝2,160 个方法结果 | 30 是规划目标，不是已经充分有功效或已获得的数据 |
| 第二模型复核 | 建议每家族预选 10 实例×2 重复，运行 M1/M3/M4/M5，共 320 个方法结果 | 次级稳健性；模型与子集在主结果前冻结，不扩大主确认性族 |
| 视觉应用案例 | 1 项目规格×2 重复×M1/M3/M4/M5＝8 个方法结果 | 预声明的描述性独立分组；不是 8 个独立语义实例 |
| Q-table 应用案例 | 纳入时另计相同结构的 8 个方法结果 | 排在视觉之后；不补入核心或用于挽救主假设 |

正式样本量由预声明模拟决定：冻结 delta、Delta*、联合功效目标至少 0.80；pilot 仅估计方差、配对依赖、缺失、运行时间等干扰参数，不能用观测处理效应回填 Delta*。12 个 pilot 语义簇是运行规模提案，不保证方差估计稳定；模拟必须覆盖保守的干扰参数范围并展示敏感性，不能把一个 pilot 点估计视为确定事实。每项边际功效也应报告。资源不足时，在正式结果前降低声明层级或重新设计研究，而不是声称 30 一定够。

pilot 可以失败；失败后应版本化修改并使用新的排除式 pilot，不追加有利样本凑齐同一 pilot。模型选择和提示调整只使用开发域；正式条件不得依据测试通过率挑模型。

在第 6 节共享结构下，每个完整配对块的逻辑模型调用上限为 15 次独立归因、11 次实际去重调用；正式规划 360 个块对应最多 5,400／3,960 次。该上限不含另列的 repair probe、第二模型、应用案例及基础设施重试；也不是 API 请求数或 token 预算。上游停止会减少调用。实施时须由调度图自动核算，禁止沿用 v1.8 旧预算公式。

## 10. 修复机制与跨模型稳健性

### 10.1 自然失败 probe 的地位

从 M4 的公开失败 checkpoint 选择对象，在任何隐藏结果开放前冻结选择。默认只做描述性分析，不再要求每家族达到最低失败数才能完成 Paper-1。

建议每个家族最多选择 3 个独立语义实例，每个实例最多一个 checkpoint；按固定失败阶段优先序及平局随机键选择。没有足够自然失败就报告实际数，不注入故障、不扩大官方集、不根据隐藏失败补选。

### 10.2 公平的 R_generic / R_PC

两条 probe 分支获得完全相同的 FPP、PC、公开需求、工具日志、模型、编辑范围和预算。`R_generic` 获得一般标准化诊断；`R_PC` 仅增加第 5.3 节定义的、由公开事实和工具结果派生的义务关联与重检依赖。两者均已能看到同一 PC，避免把“多了一份 PC”和“诊断映射机制”混在一起。

建议每条分支最多 2 次纠正调用和 2 个公开检查周期，token 上限同等冻结。终止候选各接受一次隐藏评测。probe 与主要方法拥有独立 episode ID、预算和条件标签，不能把 probe 成功替换为 M5 成功。

报告分母、失败分层、真实修复链、终止差值及区间。样本很少时提供逐例机制证据，不做缺乏功效的显著性宣传。合成故障另列为 conformance 测试，不混入自然失败修复率。

### 10.3 第二模型复核

主模型精确版本、量化、tokenizer、上下文、解码参数和提供方配置须冻结。第二模型选不同模型家族，运行预选实例和相同关键方法定义，报告结果能否保持及成本差异。

第二模型不是在正式数据上寻找更有利答案；不基于主结果选择样本或改变提示信息。不能将不同 tokenizer 的原始 token 数直接当作同一种跨模型计算量；分别报告 token、时延、费用来源与硬件条件。

若无法完成第二模型，论文只能在一个冻结基础模型范围内主张效果；该限制不以“模型无关框架”措辞掩盖。

## 11. FPGA 综合与代表性物理证据

### 11.1 固定目标配置而不是候选自行改约束

由受信 `target_profile` 指定器件／封装／速度等级、工具版本、时钟、适用 I/O 时序、shell、资源预算、允许原语、存储映射政策和 timing exceptions。实际可支持的器件和命令以资格通过的配置为准，不从板卡名称或历史截图推断。

候选可以选择需求允许的内部实现，不能放宽时钟、删约束、添加隐藏 false path、改评测器 launcher，或将硬资源预算改成软偏好。AMD 文档指出 false path 会被时序分析忽略；因此本研究必须审核例外及约束覆盖，而不能只读取一个正 slack 数值。[S6]

没有明确 I/O 约束的 out-of-context 结果应准确命名为相应范围内的内部时序证据；不能宣传完整板级时序闭合。

### 11.2 物理子集与选择规则

核心最低物理描述建议覆盖三类测试机制：`stream_fork_join`、`matched_filter`、`sobel_threshold`；每家族预选 5 个正式语义实例，使用固定 replicate（建议 replicate 1），运行 M0–M5 的所有对应终止候选。选择依据为语义／规模覆盖和参考路径可执行性，必须在模型结果前冻结。

另保留 `single_dual_port_ram`、`fir_filter`、`matrix_vector_mac` 的开发域参考与工程展示，但不与正式留出结果混算。`qtable_update_core` 单列可选旗舰；它的缺席不成为主实验退出障碍。这是对原六家族物理清单的显式收敛，而非静默删除。

§7.11 应用案例的 L4 位置、重复编号和方法在相应结果前独立预选，并与核心物理子集分组报告；可优先对该案例已规划的八个方法位置定义 L4 资格和分母。案例不能替换核心预选失败候选。若案例只是引用核心同一候选、同一任务和同一冻结评测结果，复用原结果而不再次提交隐藏语义评分，也不重复计作独立物理样本。不同负载 suite、任务或约束的评测必须在结果前另有明确研究身份，不能借案例名在看过失败后重新评分。

正式物理集合只从预选位置取候选：VPP-L3 失败仍在该物理子集分母内，标为未进入 L4；不能用其他已通过候选替换。参考工具流资格不足应在正式结果前解决，不能看模型结果再换家族。

### 11.3 阶段顺序与报告

核心 M0–M5 的正式 L4 只在同一封存候选通过完整 VPP-L3 后运行。布局布线结果不进入主生成／修复反馈，不改变终止选择。开发阶段的提前 route 有开发标签，不能升级成正式物理结果。

每项至少记录：source/netlist/constraints/tool hashes、目标 profile、布局布线状态、工具支持的资源字段、已覆盖的时序路径、目标时钟下的 slack／通过状态、工具原生 Fmax（适用时）、有效运行时间、失败与缺失原因。没有工具和约束依据时不手算或反推“真实最大频率”。

物理通过定义为同一候选的 `VPP-L3=1`、约束合规、布局布线完成，以及目标 profile 明确要求且工具实际支持的时序／硬资源条件全部满足。未分析的 hold、I/O 或其他路径不能视为已经通过；报告中的物理通过范围必须与真实覆盖一致。

报告两种分母：预声明物理子集上的无条件 VPP-L4，以及其中 VPP-L3 存活者的条件通过率。开发、主测试和旗舰分开；方法物理收益不作未经注册的显著性检验。

L4 不等于 bitstream 或 L5。没有活动率与经说明的方法，不报告功耗；没有同一候选的 Vivado 成功产物，不写商用参考通过。[S0, §§7.2, 9]

### 11.4 从接口模型到固定平台的后续路线

当前案例先使用文件回放和受信接口模型；后续可在独立平台协议下将同一生成边界接入固定 host／DMA 或相机适配设施。AXI DMA 仅作为前轮讨论提及的内存映射与流式数据搬运参考 [S11]，不是本版新增的必须实现模块，也不证明平台目前具备它。

分开记录算法子系统、可信 shell、主机软件、外部接口及各自产物来源。比较时冻结相同平台服务和使用机会；集成测试必须覆盖接口假设是否成立，不能以受信 shell 取代子系统功能验证。核内周期／时延、数据搬运和端到端时间分别报告，不能只测核内时延却称完整系统加速。

慢速接口回放可以提供相应功能证据，不支持高速在线相机采集或实时吞吐声明。无 DDR 的局部窗口方案也只有在算法和环境确实不需要外部存储时成立，不泛化为所有视觉或 CNN 系统。板级测量、bitstream 和持续运行需按 §12.5 的独立协议执行。

## 12. 可选扩展的独立协议

### 12.1 需求审计 A_req

核心保留公开事实来源、`ready / needs_clarification / capability_gap` 和非 ready 的停止边界。核心 VPP 任务均在方法分派前独立裁定 ready，自动 intake 不参与选择或删除正式实例。

完整 A_req 默认关闭。启用时单独冻结自然需求簇、变体、gold disposition、允许默认、澄清答案、标注流程、假设阈值、样本量及统计规则。原 100 簇／400 变体和严格误放行阈值可作为历史设计参考，但不能减少样本后沿用原置信保证。[S0, §§6.4, 7.3]

A_req 不给项目通过分数、不改变 M0–M5 分母、不调主方法；其失败不抹去核心研究结果，其通过也不证明任意需求理解。应用任务将关键事实显式化属于核心需求治理，不自动恢复完整 A_req。若以后启用 A_req，再将数值、背压、配置生效和时间条件等应用歧义纳入其独立人口与标注协议。

### 12.2 EA：DSC → DP → PC → 实现

EA 默认关闭，并使用独立协议与 `E0/E1` 标签。启用的前提是核心方法和评测边界已稳定，不以 EA 尚未完成阻塞主论文。

DSC 定义需求允许的设计空间，DP 是其下的候选设计点，确定性 decoder 生成 PC 的实现决策；冻结需求义务不可变。要求固定三周期时延时不得变四周期；允许时延区间时才可搜索区间内的流水线。数值精度、溢出和吞吐也按同样规则处理。

E0 是预声明采样测度下的非自适应随机搜索；E1 是自适应 EA。二者共享起始条件、DSC、decoder、实现后端、公开适应度、候选／模型／工具预算和终止选择。必须定义“均匀”作用于语法字段、合法 DP 还是唯一解码结构，并冻结拒绝采样、重复点与缓存计费。

**确定性 DP→PC 不等于确定性 DP→RTL。** 若行为仍由 LLM 生成，需固定每个 DP 的实现采样政策，并记录模型调用、重复实现、随机性与缓存；不能将多次幸运的实现抽样误称为架构搜索收益。

### 12.3 EA 的公开物理反馈例外

EA 可使用真实 public L3／L4 结果作为适应度，流程明确为：公开功能／契约检查→公开物理 fitness→搜索终止→封存→一次独立隐藏验证。它不是对核心“hidden 后 L4”的偷偷绕过；两者是不同方法协议、预算和信息权限。

建议首版终点是：在固定目标时钟与资源预算下找到物理可行、且终止隐藏功能符合的候选。除非有另外充分的测量，不称为一般 PPA 改进。

选“所有原始需求”还是“已获得有效 PC 的需求”为搜索起点必须预先冻结。后者只能支持条件性搜索结果；提供端到端结果时，PC 生成失败与前置成本必须回到分母。

### 12.4 目标配置适配

默认关闭。启用时冻结 profile pair、功能不变量、必须／允许／禁止的修改及两个目标各自的 L3/L4 终点。配对双方均符合才有适配通过，不能由 baseline-only 或存活者结果推断跨器件、跨工具或跨厂商可移植性。

### 12.5 平台／板级与应用质量扩展

完整相机／DDR／PCIe／host 集成、`.bit`、L5 和业务效果评测继续在核心之外。启用时另行冻结固定平台、生成边界、接口／时钟范围、数据来源、测试时长、适用指标、基线、成本和允许声明。板级功能回放不自动支持高速在线输入；有限负载也不自动证明现场可靠性。

仅采用冻结权重的推理案例不放开生成模型训练；算法质量比较若启用，应将量化或阈值选择与隐藏评测分开，不通过调隐藏标签改善结果。`paper2_bridge` 等目录名不决定这些扩展必然属于某篇论文；后续研究问题需另行设计。

所有扩展不得在主结果不理想后改成“真正的主研究问题”；需要新的预结果协议。扩展关闭时无需生成空 manifest 或建设无用执行路径。

## 13. 七个工作包与验收顺序

用七个可验收工作包替代不断增长的互相依赖 gate。每个包只保留直接支撑当前研究的问题、产物和失败处理，不增加与已关闭扩展有关的前置条件。

| 工作包 | 要解决的问题 | 最小交付与验收 |
|---|---|---|
| WP0 范围与迁移盘点 | 哪个研究协议有效，哪些任务和旧能力可复用？ | 采纳范围、旧新条款映射、家族实际算法／接口／oracle、开发暴露与最新阶段证据；不把目录意图当能力 |
| WP1 PC 语义与构建 | PC 到底约束了什么，约束来自哪里？ | 公开需求与环境、来源／义务／验证阶段映射、受限 lowerer、构建来源及结构／补丁测试；优先整理视觉任务卡 |
| WP2 真实开发闭环 | 真实模型能否跑通且修复链可观察？ | 开发任务上的 M0–M5 与真实工具、失败／恢复记录；需要应用开发版本时先视觉后 Q-table，独立身份并审计对核心留出的污染 |
| WP3 候选实验协议与 oracle | 测量是否能区分机制且信息公平？ | 任务资格、暴露审计、提示／预算／主要阈值、分析与隔离测试；案例纳入决策、位精确参考、预处理和负载方案 |
| WP4 排除式 pilot 与最终冻结 | 成本与方差允许做怎样的正式研究？ | 全矩阵 pilot、无删改结果、功效／精度、最终样本与核验；案例工作量／物理资格及独立分母最终冻结，不依据正式结果换任务 |
| WP5 正式核心与物理确认 | 在冻结设置下得到什么结果？ | 核心、纳入案例和 probe 的终止候选先封存；固定 suite、L3／预选 L4；独立分组保留全部失败、未验证义务和成本 |
| WP6 分析、声明与发布 | 哪些结论被证据支持？ | 主次结果、错误机制、案例完整回放表、义务覆盖、来源／许可、可重建图表；逐维度区分正确性、负载、物理和应用质量 |

### 13.1 开发可快，正式研究不可偷偷变化

WP2 可在明确授权的开发沙箱中使用真实模型，不需要完成完整需求审计、EA 或所有正式发布文档。必须提前具有：公开任务隔离、受信文件保护、预算硬上限、基础事件记录和不触碰正式 hidden 的措施。

fake model 适合验证控制流、重试和 reducer；不能单独证明自然语言规划、真实行为生成或自然修复可行。WP2 至少展示真实调用及一条有效修复链；若只有人工构造失败能修复，必须这样标注，不能宣称自然修复有效。

### 13.2 WP3 在 pilot 前冻结什么

冻结方法、信息权限、B4 与其他预算轴、停止规则、主要效应阈值与备择、缺失／完整性规则、分析方法、pilot 规模和自然失败 selector。正式测试需求／oracle 由评测域封存，生成侧只能见承诺和资格状态。

分析代码先在合成结果表上跑通，包括零成功和完全无方法差异的情况。不得以“等结果出来再挑统计方法”代替计划。

案例的公开需求、所有影响评分的规则与环境假设在生成前给各方法等价提供；参考模型、正式负载具体选择和期望输出留在评测域。WP3 准备案例是否纳入及其方案，WP4 在任何相关正式结果前锁定最终任务、重复和预算；未纳入案例不产生空评测路径。

### 13.3 WP4 的通过与失败

通过要求是参考路径可执行、每个模型 episode 都能闭合状态和成本、至少有真实模型候选达到可测的下游阶段、隔离和预算完整性成立。修复研究要有真实诊断／补丁／重跑可观察，不能只看到命名为 repair 的文件夹。

不规定“pilot 方法必须优于 Direct 才能继续”。低效应或负结果影响功效、主张和研究取舍，但不是删数据理由。若预算无法支持预定确认性结论，可在正式结果前转为估计性／机制描述研究；不得一面降样本一面维持原有强结论。

### 13.4 最终 campaign 一次冻结

冻结的是本次确切研究版本及其哈希，而不是沿用旧 `v1.7 freeze hash`。由负责人批准，独立核验程序验证输入、代码、工具、预算、oracle 和分析承诺一致。方法实现作者的自报 `authorized=true` 不能替代该核验。

正式结果打开后不改变方法、样本、模型、提示、约束和计分规则；机械纠错须保留版本和影响审计。实质变化建立新研究版本，并说明旧数据还能支持什么。

### 13.5 实际任务的推进顺序

不增加新的通用 gate。将实际任务工作纳入上述工作包，顺序为：**盘点现有家族 → 整理一份完整视觉任务卡 → 独立参考与协议资格 → 受控开发验证 → 冻结案例与负载 → 正式案例／预选物理确认 → 再决定 Q-table 和推理储备。**

视觉开发若会暴露核心候选机制，必须按 §7.4／§7.11 更新真实留出身份；不为方便而继续保留失实 family-held-out。核心方法冻结后，正式案例只测量，不反向调提示、lowerer 或预算。开发图像、轨迹和任务不得直接转成正式隐藏样本。

首个具体交付是附录 C 所列的视觉任务卡及其公开／私有边界，不是更多家族名或 UI 演示。后续才扩大负载、资源范围或接口深度；每次实质变化有新规格和证据身份，不复制先前通过状态。

## 15. 论文结果组织与退出标准

### 15.1 结果章节建议

论文先回答两个主问题，再解释原因，最后界定硬件证据：系统成功率与成本→共享 PC 构建机制→硬件错误分布→有限修复分析→代表性物理实现→纳入的应用案例与真实负载→跨模型与有效性威胁。案例不抢占或挽救主要比较的结论。

建议主表为 M0–M5 的 VPP-L3、全分母状态及成本；主图为两个主要比较的家族／宏平均效应区间。机制表展示结构、协议、数值、存储和时序失败，不仅展示 JSON 通过率。物理表包含预选全分母与条件结果。案例表逐个展示任务／方法／重复、终止候选、各类回放、义务阶段、成本及全部失败；算法质量指标只有实际预声明并执行时才出现。

每张表绑定样本身份、方法、模型、预算、工具阶段、缺失和产物 ID。没有某项结果就留空并说明未执行，不填预计提升数。

### 15.2 结果与允许声明

| 观察结果 | 允许表述 | 禁止跳跃 |
|---|---|---|
| M5−M1 达标、M4−M3 达标 | 在冻结模型、预算、任务和工具范围内，系统与构建机制均有支持 | 普适优越、训练内化、所有 FPGA 家族泛化 |
| 仅 M5−M1 达标 | 完整流程有效，但构建机制增量未获相同强度支持 | 把全部收益归因于 PC 或 lowerer |
| 仅 M4−M3 达标 | 同一 PC 下构建／编辑边界有效，但端到端优势尚不成立 | 宣称完整系统已经优于 Direct-Repair |
| 主要效应混合或区间宽 | 报告估计、机制和限制；可能形成评测／负结果研究 | 把不显著写成已经证明没有效应 |
| L4 仅部分成功 | 只报告明确工具／器件／子集的物理证据 | bitstream、板级系统、商用工具或通用 PPA 成功 |
| 自然 repair probe 样本不足 | 提供描述性个案与真实分母 | 从人工故障或少数成功推断总体修复率 |
| 真实图像派生负载在 RTL 仿真中通过 | 在冻结预处理、输入和检查范围内与独立参考一致 | 工业缺陷检测有效、真实相机实时处理、已上板 |
| 模拟 Q-table 轨迹通过 | 指定数值与状态语义在所测轨迹中一致 | 真实机器人负载、RL 收敛或控制效果提升 |
| 固定平台集成得到证据 | 生成子系统在所述接口与平台范围通过对应检查 | DMA／驱动／完整 SoC 全由模型生成 |
| 冻结权重推理位精确通过 | RTL 实现符合冻结量化参考 | 量化无精度损失、所有模型可部署 |
| L3 通过但目标物理义务未验证 | 所声明 L3 范围成功，其他义务未验证 | 满足全部公开应用配置或已具备实时部署能力 |

期刊目标是研究定位，不是接收保证。是否足以形成方法论文，需要真实方法差异、严谨实验与可复现硬件证据共同支撑。

### 15.3 最小退出检查

结束主研究时应能明确回答：不可变需求是什么；PC 检查了什么且没检查什么；lowerer 替模型完成了哪些工作；Direct 是否获得同等资源机会；每个正式实例发生了什么；隐藏结果是否独立；物理证据来自什么工具与约束；两个主要假设分别支持到什么范围。

A_req、EA、目标适配、训练或上板的缺席不能成为主研究永久无法完成的理由。它们只有在独立协议启用后，才承担自己的数据与声明义务。应用案例优先准备但不以成功为退出条件；未纳入则不提出对应结论，已经纳入则如实报告所有计划位置与缺失，不能因结果差删除。适用主任务的公开义务及验证边界仍必须清楚，不因案例可选而豁免。

## 17. 主要风险与预先应对

| 风险 | 识别信号 | 事前处理／允许的结果解释 |
|---|---|---|
| 强模型使简单任务全部通过 | 开发／pilot 缺少结构与语义错误 | 用真实组合义务设计开发任务；正式后不为制造差异加难题 |
| 弱模型只产生格式失败 | 下游没有可测候选 | 开发阶段调整接口、模型与支持域；仍失败则诚实报告可行性限制 |
| lowerer 实质藏入答案 | 行为来源映射显示大量家族特定实现 | 隔离模板，或改成明确的模板辅助扩展并提供公平对照 |
| PC 错误使结构正确但功能错 | H/L0 通过、hidden L2 失败 | 检查义务保持与 oracle；不靠降低语义标准掩盖 |
| 基础设施治理过重 | 主要工作变成创建授权文件而非方法闭环 | 每个前置条件必须映射到当前主研究风险；关闭扩展不产生依赖 |
| 修复 probe 没有足够自然失败 | selector 返回很少样本 | 保持描述性，报告样本不足，不补造失败 |
| 物理映射与仿真义务不一致 | BRAM／DSP 映射不符合预期、时序失败 | 保留数值与存储语义，报告真实硬件限制，不以属性替代结果 |
| 基础模型／提供方漂移 | 版本或 fingerprint 改变 | 停止受影响正式段，按冻结规则处理，不混成同一模型结果 |
| 留出污染 | 提示／库或提前开发的视觉案例包含测试家族解法 | 正式前重审家族／组合留出；案例方法冻结后运行；正式后披露而非改名掩盖 |
| 应用名称替代实际行为 | 有“工业／RL／雷达”名称却缺少明确算法或接口 | 用实际运算命名，核验任务卡与证据，不从字段或目录推断应用有效性 |
| 工程设定冒充真实要求 | 帧率、位宽、缓存等没有外部来源却被称客户需求 | 明确研究者配置身份和推导，冻结前补来源或收缩叙事 |
| 环境要求不自洽 | 无限背压、有限缓存、连续输入又要求无条件零丢失 | 先裁定到达／服务条件与适用域，不把不可能规格记作模型错误 |
| 回放混淆与样本膨胀 | 派生图像称原始相机流，多张图乘成多个工程 n | 记录预处理与真实来源，测试覆盖和独立工程分开 |
| 案例拖大范围 | 同时启动视觉、Q-table、CNN、PCIe 与机器人 | 先视觉、后 Q-table；推理作储备，完整部署独立且不阻塞主实验 |
| L3 被解释为满足完整应用配置 | 时钟／板级义务无证据但摘要称全部满足 | 按 §3.6 和 §9.1 逐阶段报告未验证义务 |
