# SR2FPGA Project Contract 2.0
## 面向契约约束工程构建与受限修复的全新设计

**设计状态：** `pc-2.0-design-candidate`，2026-09-14。  
**机器格式：** `sr2fpga-pc-2.0`。  
**兼容政策：** 不兼容 System-HIS v1.2；不包含旧别名、兼容转换器或宽松兼容入口。  
**研究关系：** 面向 Paper-1 v2.1 的方法目标，PC 格式版本不等于研究计划版本。  
**本次交付：** 新设计说明、完整 PC schema、模型输出投影 schema、参考静态检查器、两个说明性工程契约及本地测试。没有修改仓库、生成 RTL、执行仿真／综合／布局布线或正式实验。

> 本文是用户要求下的新设计，不是对已有代码能力的陈述。来源 [S0] 是被重设计的 schema；[S1] 是当前研究范围依据。下述组织、字段、限制和执行方案均属于本次提案。所谓“最优”，在这里指针对 SR2FPGA 的可检查性、生成负担、实验可解释性与实现复杂度作出的设计取舍，并非未经比较就证明对所有硬件任务最优。

## 1. 核心决定

**PC 是“绑定既定需求的、具有明确类型和层次的架构决策”，不是需求数据库、完整硬件程序、构建日志和评测结果的混合容器。**

采用以下关系：

```text
冻结公开需求 + 固定 target profile + capability profile
                       ↓（各方法信息等价）
               模型生成 design
                       ↓
控制器注入不可变 bindings → 完整 PC
                       ↓
严格解析 → schema → 引用/类型/参数/能力检查
                       ↓
派生的实例展开与构建计划（不再成为第二份设计权威）
                       ↓
受信结构构建 + 模型实现行为模块
                       ↓
FPP → 公开工具与有预算修复 → 封存 → 独立隐藏验证 → 适用 L3/L4
```

PC 负责描述“选择了怎样实现、这些选择对应哪些公开义务”；工具和独立评测负责说明“实际满足了什么”。跨模块一致性可以机械检查的部分，前置检查；无法静态判定的行为，不靠填写字段冒充证明。

### 1.1 不变的研究目标

M5−M1 仍是等总预算下的完整系统比较；M4−M3 仍使用同一生成 PC，比较确定性构建与编辑边界的联合干预。本设计不增加模型训练、不恢复 EA 必选、不扩大主实验家族或主假设。PC 变化属于方法版本变化，旧实验和旧 checker 通过记录不能自动沿用。[S1]

## 2. 四类逻辑对象，一份设计权威

| 对象 | 权威所有者 | 内容 | 不该混入的内容 |
|---|---|---|---|
| Requirement Envelope / 公开任务与配置 | 任务裁定方和受信控制器 | 对外接口、行为、环境假设、目标与允许资源；已有格式优先复用 | 模型未经允许添加的新假设、候选结果 |
| Project Contract | 控制器绑定；模型提出内部 design | 模块、参数、接口、连接、架构状态、数值／时间承诺、义务映射 | 隐藏 oracle、预算、分数、模型自报 pass |
| FPP 与派生构建记录 | 构建器和产物检查器 | 实际源文件、顶层名称、依赖、哈希、ABI 展开、编辑范围、来源映射 | 由预测值代替实际文件或实现结果 |
| Evaluation Evidence | 对应公开／隐藏／物理评测器 | 检查范围、结果、工具和配置、缺失与失败原因 | 回写并修改原始 PC 的事实义务 |

这是逻辑分工，不要求新建四套数据库。**不把实验治理数据塞入 PC，也不让每类对象各维护一份可冲突的完整需求。**

删除旧 PC 中作为核心成员的 `verification.pass_condition`、`artifacts.predicted_qor`、重复文件列表、实测资源、直接脚本路径和兼容别名。候选验证建议或 QoR 建议可以作为非权威附属产物，不能成为 PC 必填项。

## 3. 顶层格式：三个字段

```text
schema_version
bindings
    requirements         {id, sha256}
    target_profile       {id, sha256}
    capability_profile   {id, sha256}
design
    entry
    modules
    requirement_map
    notes?               非规范性说明
```

### 3.1 模型只写 design

`contracts/pc-2.0/design-proposal-2.0.schema.json` 验证模型输出；`contracts/pc-2.0/project-contract-2.0.schema.json` 验证控制器组装后的完整 PC。二者共享同一设计定义，不是两个竞争的 PC 格式，也不是宽松格式和严格格式。

`bindings` 由控制器以受信输入构造。模型不能选择另一份需求、另一个器件目标或更宽松能力配置。仅在 schema 写 `readOnly` 并不能实施权限保护；JSON Schema 的此类词是注解，真正的所有权来自输出投影、进程权限和运行时比对。[E1]

本参考适配器对输入文件的**实际 UTF-8 字节**计算 SHA-256，不宣称语义等价 JSON 具有相同哈希，也不宣称哈希等于签名或授权。被调用者必须从受信路径供应公开文档，不能把模型提供的“expected bindings”当权威。

### 3.2 对外签名引用，不让模型重写一份

入口模块的签名只能是：

```json
{"source": "requirement_boundary"}
```

它从被绑定的公开任务获得参数定义、对外端口和时钟域。内部模块使用 `source: declared` 声明自己的签名。入口的逻辑模块 ID 可由模型选择；实际对外 RTL 名称和 ABI 仍受公开任务控制。

这并不意味着 Direct 获得更少信息：同一公开边界、配置和约束也给 Direct／Structured 方法。M3/M4 的共同 PC 检查不依赖已经成功生成的 M4 skeleton，不用构建结果筛选共同起点。

### 3.3 严格记录与有类型的名字表

固定结构对象均关闭未知字段。模块、端口、实例、状态等使用按 ID 索引的 object，值按明确 schema 验证；名字表不是任意 metadata 字典。JSON 重复键在解析阶段拒绝，不能让解析器保留最后一项后再宣称名字唯一。

对象键不表达顺序；需要顺序的 record 字段与运算步骤必须使用有序表示。名字 ID 只允许有限 ASCII 字符集，并与物理 HDL 名称分离，避免任意代码或路径进入标识符。

JSON Schema 对对象附加属性和 schema 组合有具体作用域规则。[E2] 本次采用分别闭合的 tagged-union 分支，避免依赖一个顶层 `additionalProperties: false` 假装关闭全部嵌套对象。

## 4. 统一层次化模块，取消平铺对象之间的重复权威

每个模块由 `signature` 与 `implementation` 两部分组成。

| 实现类型 | 内容 | 构建／编辑责任 |
|---|---|---|
| `structural` | 子实例、明确参数与域绑定、唯一连接表、显式未使用值信号 | 构建器生成实例和接线；无自由行为代码 |
| `behavioral` | 组合／时钟执行类型、行为意图、可选架构状态与承诺 | 模型实现行为；外部签名受保护 |

顶层和子系统使用同一种模块表示；实例只属于某个 structural 模块。相同模块定义可以多次实例化，结构可以递归组合，但禁止**定义递归实例化**，例如 A 实例化 A 或 A→B→A。硬件数据反馈与定义递归不是同一概念，不能混淆。

本核心不允许一个模块同时拥有自由顶层行为和独立结构接线。确需控制逻辑时，将其组织成行为叶模块；顶层本身也可以是单个行为模块。是否需要多模块由任务决定，不把无意义拆文件视为复杂度。

`modules` 中每个定义必须从入口可达；不接受未使用的答案片段或为凑规模而加入的死模块。

### 4.1 纯组合模块不需要伪造时钟／复位

`behavioral.execution` 为 `combinational` 时不消费时钟，也不能声明架构状态；`clocked` 则需要至少一个消费上升沿时钟的域槽。时钟域标记不自动意味着实际存在一个时钟管脚，详见 §7。

### 4.2 组件来源与公共 IP

当前可执行 schema 只包含 structural／behavioral 两类，不提供任意外部脚本或任意第三方 RTL 路径。公共 IP、厂商块和完整协议桥接是后续显式扩展：需受信内容身份、接口摘要、许可和支持配置，并对方法等价可用，不能利用 `semantic_kind` 私下查找家族实现。

这不是排斥模块复用，而是避免把“复用既有行为库”和“结构性构建”两个因素混在当前主实验里。关闭的扩展不预建空运行路径。

## 5. 参数与类型：用有限 AST，不接受任意表达式字符串

### 5.1 静态形状参数

参数是非负整数的结构参数，例如位宽、深度、展开数量；每个参数声明 `minimum/maximum`，每次实例化必须显式赋值。运行时阈值、Q 值或 host 配置属于数据／状态，不冒充静态参数。

表达式只允许非负整数字面值、`{"param":"W"}`、二元 `add/sub/mul/ceil_div/min/max` 与一元 `clog2`。

```json
{
  "op": "max",
  "args": [1, {"op": "clog2", "arg": {"param": "DEPTH"}}]
}
```

明确 `clog2(1)=0`，因此直接作为端口位宽会失败；需要至少一位时必须显式写 `max(1, ...)`。除零、负中间结果、未绑定参数、超界值和过深表达式均拒绝。禁止 Python `eval`、任意 SV 表达式、字符串宏和模型提交的 `resolved` 值。

参考编码只使用 JSON 整数字面值，禁止浮点字面值、NaN/Infinity；定点值用缩放前的整数表示。安全数值范围为 ±(2^53−1)，结构表达式使用其中非负部分。真实多字常量可通过受信公开资产交付，不靠放宽任意表达式弥补。

**重要限制：** 参考检查器只展开本任务实际绑定的配置，并不证明参数域内所有组合都合法。需要“对全部参数都成立”时，必须给出有限配置覆盖或符号证明；否则明确报告配置级结论。

### 5.2 数据类型

| 类型 | 明确定义 |
|---|---|
| `bits` | 无算术解释的位向量 |
| `uint` | 无符号整数 |
| `sint` | 二进制补码有符号整数 |
| `fixed` | 总位宽、signed 与 fraction_bits；数值等于 raw integer × 2^(-fraction_bits) |
| `record` | 有序命名字段，递归包含上述类型 |

record 第一个字段位于最低有效位，偏移由前面字段宽度累加生成。连接比较包括类型种类、字段名与顺序、位宽、符号与小数位；同样总位数不意味着同一语义类型。

本设计允许 `0 <= fraction_bits <= width`，明确定义其缩放含义，而不借用有歧义的“Q16”简称。连接不自动进行符号扩展、截断、重打包或舍入；需要变换时显式建行为适配模块。

舍入和溢出属于**运算边界**，不是整个工程的统一默认。`numeric_rules` 描述指定公共义务下的一处结果类型、舍入和溢出承诺；它不是完整运算程序，运算次序与所有关键截断点依然由冻结任务规定和独立参考验证。

## 6. 接口与连接：逻辑事务连接是唯一权威

端口只有两个核心类型：

| kind | 含义 |
|---|---|
| `value` | 输入或输出的一个有类型值，可以显式为无域或归属某域 |
| `stream` | 指定域内、有类型 payload 的有向事务流，初版协议为 `ready_valid_v1` |

### 6.1 ready_valid_v1 的确切含义

在所属域的有效上升沿且 reset 不取消事务时，`valid && ready` 接受一个 token。未接受的有效 token 必须保持 valid 和全部 payload；附带帧／行／坐标字段若放入 payload，也与 token 一起保持。ready 表达接收能力，不能用连接器静默丢弃或复制 token。复位后何时恢复及在途事务处置遵守公开任务和模块义务。

这是本提案的有限协议，不自动等于 AXI4-Stream 或 AXI4-Stream Video。CIRCT ESI 同样区分消息类型和物理信号表达；这里借鉴分层思路，不宣称与 ESI ABI 兼容或首次提出类型化通道。[E3]

若任务必须使用真实 AXI Video ABI，需要明确桥接或协议扩展。例如 AMD UG934 将 TLAST 用作行终点，而非帧终点；不能让一个模糊字符串 `protocol: video` 代替完整公开规则。[E4]

### 6.2 一个连接，不重复列出 ready 反向线

```json
{
  "source": {
    "kind": "endpoint",
    "endpoint": {"instance": "first", "port": "out_stream"}
  },
  "sinks": [{"instance": "second", "port": "in_stream"}]
}
```

受信结构构建器根据协议产生 payload、valid 的正向线与 ready 的反向线；不另外存一份可冲突的 raw ready 连接。**本次只实现此规则的静态合法性检查，未交付 RTL emitter。**

只允许一层局部端点：`self` 代表当前模块边界，其他 ID 代表直接子实例。跨越多个层级的字符串路径被移除；层次访问必须通过模块公开端口。

结构中的 self input 是驱动源、self output 是接收端；子实例 output 是源、input 是接收端。检查器按层次方向判断，而非只看字符串 `input/output`。

value 可以一源多接收；stream 必须点对点。同一 stream 不能有两条链接或两个 sinks，广播、复制、汇合、仲裁、缓存必须由显式行为模块承担。不能通过自动插入 FIFO 或 fork 为 PC 方法注入额外行为答案。

每个接收端恰好一个驱动。未使用 value 源可列在 `unused_values` 中；未使用 stream 不允许隐式丢弃，要用明确 sink 模块。常量源只提供显式 scalar type 与 raw integer，不允许 X/Z、隐含位宽或任意脚本表达式。

### 6.3 不是所有循环都能在 PC 阶段定性

实例层次递归可以静态拒绝；数据反馈可能有寄存器，ready 路径也可能在时钟模块内部保持组合依赖。**不能因为一个模块标为 clocked，就断言没有组合环。** 真实组合环、握手死锁与活性需要生成后的结构／形式／仿真证据，参考静态报告明确列为未检查。

## 7. 时钟与复位：传递域身份，不从名称猜测

模块签名中的 `domains` 是局部域槽。子实例将局部槽映射到父模块槽；实际来源最终绑定至公开边界。这里不存重复 `primary_clock` 和 `target_fmax_mhz`，目标周期只由外部 target profile 定义。

每个槽说明是否消费 `rising` 时钟或 `none`，以及消费何种 reset。`clock: none` 可用于组合模块的域标记，不生成时钟脚，并且只能不消费 reset。这样组合模块可以参与一个时钟系统的数据类型／域检查，而不被迫生成虚假时钟接口。

需要 reset 的子模块必须与父域的 reset 方式和极性兼容；不消费 reset 的模块不要求不存在的 reset 连接。禁止构建器悄悄添加反相器、同步器或生成时钟。

语法定义 sync、none 和显式 async release 约定；附带的示例能力配置只启用 none/sync，async 请求返回能力错误。async 的 deassertion 描述本身不证明同步释放已实现，启用该能力前需独立验证所选平台或同步结构。

示例 core 限定单用户时钟域，跨域设计不在已交付能力中。未来 CDC adapter 必须是有独立证据的显式实体，不允许通过更换 domain 标签消除跨域问题。

## 8. 架构状态与行为承诺

状态定义只在 behavioral 模块内部。实例展开后的 owner 为明确的层次实例，不再同时维护一个全局 owner 字符串和另一个局部定义。相同模块的两个实例有不同状态身份。

本核心保留三个本质状态类别：

| 类别 | 必备信息 |
|---|---|
| register | 域、类型、复位值或无复位 |
| memory | 元素类型、深度、端口组织、同步读延迟、同址读写规则、初始化、运行时复位政策 |
| fifo | 元素类型、容量、读模式、满／空同时事件政策、复位无效化 |

counter 是带特定更新义务的寄存器；FSM 是状态存储加行为义务，不必在 schema 里再制造五类几乎相同的空壳。

memory 的 `initialization` 与运行中的 reset 明确分开：初始全零不表示每次 reset 都必须瞬间清零整个 RAM。当前 memory 的运行时内容政策为 `preserve`；需要逐项清空的应用可建显式控制行为并规定完成时间，不得借 reset 字段无成本地产生不可实现的批量清零要求。

FIFO 的 `full_exchange` 说明满时若同周期成功 pop，是否允许 push；`empty_exchange` 说明空时 push/pop 能否旁路成交，或必须先存入且本周期不成交 pop。接口实际提供 ready/valid 的时序由独立验证检查，不能由状态描述自证。

只记录与跨模块一致性、状态归属或数值行为有关的架构状态；不强制枚举每个实现临时寄存器。构建器不根据状态描述直接生成完整 FIFO、RAM 控制器或计算核。实际 RTL 中的状态表示、写者唯一性、reset 行为和内部额外状态需后续检查，PC 内 owner 唯一不等于 RTL 写者已证明唯一。

`intent` 是模型对实现行为的解释，辅助代码生成，不是新的任务规范。与公开义务冲突时应修设计，不能反向修改需求。

## 9. 需求映射、数值与时间承诺：关联不等于证明

`requirement_map` 把公开 fact ID 关联到 module、port、state 或 net。哪些 fact 必须出现，由受信需求投影给出。模型不能通过不列某条需求来从分母和义务中删除它。

静态检查器验证：fact 存在、目标存在、没有重复、必须关联的 fact 未缺失。**这仅是 reference coverage，不是 REQ→PC 语义 fidelity 的最终通过判据。** 把所有 fact 指向顶层可以满足最粗关联，但不自动获得机制或正确性信用。机制分析需要更细目标及真实诊断证据，不能拿关联条数当创新指标。

`numeric_rules` 的 fact 必须是公开 guarantee；条件时间承诺的 `under_assumptions` 只能引用已存在的公开 assumption。模型不能发明“下游永不停顿”来使一个不满足实际要求的设计通过。

时间承诺目前提供 stream 的 acceptance→offer/acceptance 延迟范围与最大启动间隔。单位是域时钟周期，初始采样边沿定义为周期零；offer 表示 valid token 已可观察，不以 ready 为必要条件。参考 checker 只检查端口、域、条件来源及数值范围，**不证明承诺可达，也不证明其能组合推出顶层期限**。

外部任务的数值步骤、交易顺序和时间限制保持权威。若只是自然语言，不假装 schema 自动理解；可由对应公开检查器、独立位精确参考或受控形式属性验证。内部承诺需要对应实现证据，不能成为免费增加外部环境假设的渠道。

分阶段状态属于 Evidence：L3 通过不会自动关闭 L4 目标时钟义务；没有真实负载回放或板级运行，也不能把对应义务标为已满足。[S1]

## 10. 构建、行为填充与修复边界

### 10.1 构建器应当生成的内容

根据已检查 PC 和受信 ABI，派生顶层与子模块签名、参数特化、实例、连接、协议信号展开、确定性源文件布局、声明式构建 manifest、行为编辑单元及来源映射。record 布局和 stream 的 ready 反向连线属于结构规则。

**不生成未经声明的家族行为，不静默选择算法、补 FIFO、添加舍入／截断、消除背压或降低时钟。** 这些选择属于模型明确的设计或公开等价可用组件，不靠隐藏模板完成。

符号 ID 不是文件路径。源文件路径由受信命名规则生成；实际 top 名称与外部信号 ABI来自任务。实例展开报告是派生缓存，不能被模型单独修改。删除 PC 中的可写路径仍不替代 FPP loader 的目录隔离、依赖检查和脚本限制。

### 10.2 行为实现边界

推荐以“行为叶模块＋受保护签名”为代码生成与修复单位，不靠注释哨兵保护任意文本区。叶模块内部可生成必要实现状态和算法，但不能改接口、域绑定、顶层约束或评测器。生成后使用真正的解析／elaboration 重新确认签名与层次，不能只用字符串搜索。

该部分是构建器实施要求。本交付没有解析 SV AST、没有强制文件编辑边界，也没有运行 OS sandbox；静态 checker 的 pass 不能替代这些能力。

### 10.3 PC 修正与 RTL 修复分开

PC 修正改变模型拥有的 design：检查新旧差异、重新验证整体引用与类型、重新展开受影响实例、使旧签名／连接／行为缓存失效。受影响闭包包括参数依赖、类型接口、上层接线和义务关联，不仅是改动的 JSON 字段。

RTL 修复只改允许的行为单元：保持受保护结构，重新执行对应公开检查。全局预算不因“重建”“重新规划”而重置。原 PC、旧候选和事件保持不可变。

真实实现可优先全量重建小工程，再在有测试依据时做增量缓存；不为声称最优而先建立复杂的增量编译服务。研究配置中 M3/M4 共享初始 PC，M5 后继 PC 不回流其他分支。

## 11. 对视觉和 Q-table 的作用

| 共同 PC 能力 | 视觉 | Q-table |
|---|---|---|
| record + stream | pixel、sof/eol、坐标作为同一事务的字段 | 更新请求、地址、奖励、参数与结果 |
| 层次化模块 | 窗口、算子、统计与配置模块的组合 | 读取、运算、写回、控制与结果模块的组合 |
| 数值承诺 | 有符号梯度、中间精度、绝对值和阈值边界 | 缩放、小数位、运算序列和逐步截断 |
| 架构状态 | 行存储、坐标、帧级配置快照 | Q 表、在途事务、同址依赖与转发责任 |
| 时间／条件引用 | 无停顿 II、背压保持、帧结果时间 | 接受／提交顺序、依赖下的吞吐条件 |
| target/profile binding | 片上存储与时钟要求 | RAM 规模、资源限制和目标时钟 |

不添加 `vision_mode`、`rl_mode` 等通用大开关；算法、图像尺寸、系数、真实图像选择、Q 表更新公式由任务卡决定。类似 `argmax` 平局规则只有在索引影响可观测行为时才是义务。[S1]

公开权重和初始化数据从被绑定需求的 `public_assets` 引用。参考 checker 只验证资产身份已声明，不读取或验证资产内容。真正构建阶段还必须核实字节、布局、许可与加载语义；不能把 asset ID 存在等同于真实数据已正确使用。

本交付的 stream relay 和组合加法是独立开发示例，不是视觉或 RL 工程已完成的证据，也不得计入正式留出任务结果。

## 12. 验证分层和已交付能力

| 层 | 责任 | 本交付状态 |
|---|---|---|
| 严格 JSON 解析 | 重复键、浮点／非有限字面值、大小和深度 | 已实现参考版本 |
| JSON Schema | 关闭对象、判别联合、字段类型、有限表达式语法 | 两份 schema 已通过 meta-validation |
| 引用与实例展开 | 模块／端口／参数／域／fact 引用，递归和可达性 | 已实现参考版本 |
| 静态结构语义 | 类型匹配、方向、驱动、stream 点对点、无隐式跨域、状态／参数范围 | 已实现列明规则 |
| 行为与需求符合性 | 算法、协议、存储事件、假设充分性、数值和时间承诺 | 未实现；需独立验证 |
| 构建与编辑边界 | RTL emitter、实际源清单、AST 检查、修复范围 | 未实现 |
| EDA 与物理 | lint、仿真、综合、时序、映射、板级 | 未执行 |
| 运行安全与授权 | 沙箱、可信注册、签名或授权、事件和隐藏隔离 | 未接入项目 |

不重用或重新定义现有 H0–H3 含义。实施时将本表规则映射到真实检查层，并记录当前协议版本。返回的局部报告使用 `scope: schema_and_listed_static_checks_only`，带有 `deferred_checks`，而非 `project_pass`。

参考检查器对一个输入通常返回首个语义错误，以利定位；schema 错误最多列出 12 条。位置为 JSON Pointer 或实例路径，错误代码可绑定诊断修复。它还只是参考原型，不是完整的生产级编译器或攻击面审计结论。

### 12.1 为什么仍然需要独立 oracle

schema 正确、图结构合法、接口类型一致的工程仍可能实现错误算法。`intent`、`numeric_rules`、`timing` 和 `requirement_map` 都不能自证。结构性优势必须由 M4−M3 与错误类型变化测量；整体正确性由共同 oracle，不能给 PC 方法一个更宽松标准。

没有把 source/output path 放入 PC 也不证明候选 RTL 无恶意依赖；实际 FPP 继续当作不可信输入处理。

## 13. 从设计到项目实现的顺序

**步骤 A：接入真实公共对象。** 将仓库现有 Requirement Envelope、target profile 和 capability profile 适配成 checker 所需受信视图。附带例子不是这些现有格式的替代权威。保留字节身份与实验信息等价；不要创造一个可被模型改写的并行“公共需求”。

**步骤 B：实现纯结构构建器。** 先完成端口、域、参数、连接和 deterministic ABI／路径，再生成独立行为单元。用最小模块、参数化复用、stream 连接和组合模块做正反例。

**步骤 C：实施行为与编辑检查。** 生成真实 SV 后检查保护签名、跨文件依赖和实际状态；公开验证失败形成稳定、可定位的诊断。不要只因出现“repair”文件夹就宣称有修复链。

**步骤 D：开发域验证并对接 M0–M5。** 先跑完不接触正式隐藏任务的真实生成／修复闭环，再按 v2.1 的预算与冻结程序做 pilot 和正式研究。

**步骤 E：有限应用案例。** 根据已冻结视觉／Q-table 任务卡使用共同语义，避免为了一个家族给 schema 添加隐藏模板。部署、公共 IP、多时钟和其他协议只有在明确扩展协议与测试后启用。

不需要旧数据迁移层；历史 v1.2 文档和结果可归档用于解释，不能因为没有兼容要求就覆盖其原始证据身份。

## 14. 接口设计取舍与明确不做的内容

| 取舍 | 为什么这样选 | 代价与边界 |
|---|---|---|
| 根边界引用而非再次生成 | 避免外部要求出现两个权威 | 构建必须能读取受信公共边界 |
| 一种统一模块结构 | 支持层次复用，减少全局 owner／path 混乱 | 复杂控制需叶模块化 |
| stream 原子链接 | 统一信号方向，阻止隐式广播／丢弃 | 完整 AXI、跨域桥需要显式扩展 |
| 参数 AST、精确类型 | 可安全求值和机械比较 | 相比字符串较长，需要生成模板和诊断 |
| 只记录架构状态 | 保持模型算法实现自由度 | 仍需真实 RTL 检查实际状态与写者 |
| 承诺与证据分离 | 防止自评、减少循环验证 | 静态通过不能变成完整正确性结论 |
| 有限已实现 core | 将“能表达”与“能正确处理”分开 | 不声称即刻支持所有 FPGA 应用 |

这是一套契约与构建前架构层，不是新的通用 RTL 编程语言。暂不定义完整算术／状态转移指令集、任意表达式脚本、自动 CPU/SoC 集成或通用形式证明框架。未来需要与 CIRCT/FIRRTL 等后端衔接时，使用编译边界映射，而不是把这些后端语法全部塞进 PC。[E3]
